# Agent Note: 微信事故：检查卸载后的本地入口必须先于卸载

## Problem

2026-10-12 的恢复在撤销历史 owners 状态时，先卸载可用外卷，再发现本地容器父目录不可访问。重挂又被部分复制事务自身的预留阻挡，微信原入口露出 000 空保护目录；缺少权限只是触发条件，不能成为切断现有数据入口的理由。

## Proposal

所有正常还原、恢复与重连在卸载前先核对事务、目标目录和写入者。实际打开并读取本地父目录，不能以外盘根目录可读或 statfs/lstat 成功代替。持有目录描述符的挂载点租约验证同一空保护目录，目标被替换或已有文件时保留当前挂载。

历史权限纠正重挂失败时重新检查卷的真实位置。仅当同一卷仍未挂载且目标安全时按原模式接回；不能为补救卸载后来挂到其他位置的卷，也不能假报权限纠正成功。部分还原走自己的恢复事务接回活动数据，再处理暂存，绝不以旧暂存覆盖新写入。

错误标题与实际入口状态一致，不用“数据已就位”掩盖未接回；卸载日志记录事实，不把本进程的命令归为外部卸载。TCC 授权针对当前二进制代码要求，bundle ID 和版本相同不能证明 Debug 已继承安装版授权。

## Incident evidence

来源通过保存的 FDA 代码要求验证：安装版匹配，事发 Debug 不匹配；没有取得 tccd 拒绝事件，也没有修改 TCC 数据库。持现有操作锁核对卷 UUID、容器、标记和原目录后，将活动卷按 noowners 接回；生产迁移记录内容未改，用户确认最近聊天及文件正常。该恢复不等于早晨的内盘还原已经完成。

来源同时记录目标访问拒绝、租约失败和自身 overlap 的回归复现。真实隔离 APFS 用目录权限模拟访问拒绝，没有制造真实 TCC 失效；10 月 13 日已完成真实微信原位还原。相关追加实现尚未随本次文档提交入库。

## Alternatives considered

- **先卸载再检查本地目录**：可以直接看到卸载后的路径，却在检查失败时主动破坏仍可用的入口。
- **用可读外卷证明容器访问权限**：检查便宜，但挂载遮住的本地父目录受另一组 POSIX/TCC 条件约束。
- **用早晨暂存覆盖活动数据**：表面上可迅速恢复目录，却无法证明暂存包含后续写入；保留最新活动卷才符合恢复目标。

## Acceptance criteria

权限或租约失败在任何卸载前发生，原挂载保持可用。复制后丢失权限、事务并发变化、部分复制重连和历史权限回退均有回归；恢复权限后可从普通入口重试并保留最新字节。将对应代码、测试与本篇同批提交，之后转 implemented。

## Risks

模拟 POSIX 拒绝不覆盖全部 TCC、签名更新、物理断线与登录竞态。来源没有发生率证据，不将一次恢复成功推广为所有环境保证。缺少完整基线的旧暂存不能因应用能启动就删除。
