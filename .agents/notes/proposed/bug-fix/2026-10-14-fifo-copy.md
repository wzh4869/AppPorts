# Agent Note: 复制持久 FIFO 节点，不读取瞬时管道消息

Status: proposed

> 迁移自 docs/apfs-cross-app-validation-2026-10-14.md

> 入库状态：本机已有实现与来源报告所述验证，相关源码尚未提交；按已确认的迁移约定暂记 proposed，随对应代码提交再转换。

## Problem

Realm 等数据库会在数据目录中保存 `.note` 命名管道。严格复制器一律拒绝特殊节点会阻断整个目录；把 FIFO 当普通文件读，又可能无限等待写入者或把瞬时消息误当持久数据。

## Proposal

识别 FIFO 并复制节点类型、所需元数据与树内硬链接关系，不读取管道中的消息。独占创建目标，保持描述符与节点身份检查；不因此支持 socket 或任意其他特殊节点。macOS 12 的兼容创建路径仍须约束已打开的目标目录，不能改用不受约束的绝对路径。

## Existing evidence

2026-10-14 来源记录独立 Realm FIFO 在修复前复现 unsupportedNode，修复后经 AppPorts 界面完成迁移、原路径使用、还原和清理，实际消息仍可读写。诊断包中的真实魔镜修图文件类型未证实，不能将其确定归因于 FIFO。当前工作区支持 `namedPipe` 与 `mkfifoat`/兼容创建，源码尚未提交。

## Related decisions

- 新增支持的节点类型不扩大其他复制权限，见[目录显示、执行权限与严格数据复制分开约束](../../implemented/architecture/2026-10-01-data-path-copy-safety.md)。

## Alternatives considered

- **拒绝全部特殊节点**：实现简单且保守，但会拒绝含持久通知 FIFO 的正常数据库目录。
- **按普通文件读取 FIFO**：复用字节复制路径，却可能阻塞，且消息并非需要落盘保存的节点内容。

## Acceptance criteria

独立 FIFO 目录往返后保留类型、权限、所需元数据和硬链接；原路径上消息可用且复制不读取消息。socket 仍拒绝，节点替换不能绕过身份检查。兼容分支在当前系统的强制测试与 macOS 12 实机结果分别报告；代码提交后转 implemented。

## Risks

FIFO 消息不迁移，应用必须按正常退出/写入者规则停止；不能把在线进程的 IPC 状态当作持久目录。来源未验证真实魔镜修图或 macOS 12 真机，不扩大成功范围。
