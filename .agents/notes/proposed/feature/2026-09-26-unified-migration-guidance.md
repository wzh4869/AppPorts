# Agent Note: 统一应用级迁移与修复引导

Status: proposed

> 迁移自 docs/design/2026-09-26-migration-onboarding-review.md

> 入库状态：统一向导尚未实施；已有局部改进不等于本提案完成。

## Problem

首次使用者需要在应用、数据和存储页面之间拼接步骤，无法从一个入口知道哪些内容会迁移、共享数据是否影响其他应用，以及修复完成后该继续做什么。

## Proposal

提供“选择应用、选择内容、选择存储、查看检查结果、迁移、验证使用”的连续主线。应用行的迁移数据动作直接定位该应用；摘要展示应用本体、可迁移数据和外盘依赖，共享容器不自动全选。现有目录行直接操作继续保留。

复用已有磁盘预检，把运行状态和权限检查纳入同一任务上下文；授权或换盘后可继续，修复完成后返回当前应用的下一步。详细路径和 APFS 机制放在详情中，经典模式保留为高级选择。此连续向导尚未实施，不将已完成的局部预检改进算作整项完成。

## Related decisions

- 此提案复用已经落地的局部预检，不能把它当作完整向导，见[按当前任务进行 APFS 迁移预检](../../implemented/feature/2026-09-24-apfs-migration-preflight.md)。
- 向导的共享与个人目录显示须遵守[容器归属、个人目录链接与大小显示](../../implemented/feature/2026-10-01-container-ownership-presentation.md)。

## Alternatives considered

- **继续使用分散入口**：改动少且熟练用户可直接操作，但首次使用者仍须自行理解页面间顺序。
- **每次都强制完整向导**：可以统一步骤，却给简单目录操作增加负担，因此保留直接入口。
- **让用户先选符号链接、APFS 或重签名**：暴露全部控制，但把实现机制变成使用门槛；默认流程应按数据类型选择适用方式。

## Acceptance criteria

- 从应用行进入数据任务时保留应用与目标盘选择，未确认不变更数据。
- 换盘、返回权限设置和修复完成后能继续同一任务；取消有明确出口。
- 共享、未知归属及当前模式可见；不能把扫描候选描述成已确认所有权。
- 中英文真实界面走通主线与直接入口，相关回归和 Release 构建通过；无法覆盖的平台单列。

## Risks

连续流程需要处理跨页面状态失效、目标变化和授权返回；界面上下文不能替代执行前重新检查。来源没有记录更完整的交互布局对比，不补造设计评审结论。
