# Agent Note: 临时目录的结构资格与迁移推荐分开

## Problem

随机临时子目录挂载能通过普通容器结构检查，却改变应用删除根目录、原子替换和跨卷移动的语义。只把扫描到的占用标为可迁移，会把“看见了”误当成“适合长期挂载”，且未来的新随机目录仍占本地空间。

## Proposal

将结构资格与迁移推荐分开。对随机 `.com.tencent.XXXXXX` 这类临时根，不默认推荐长期迁移；候选应有稳定根路径，且相关原子 rename、替换、硬链接工作流不跨文件系统。显示隐藏占用不自动增加推荐可释放大小。

是否对所有普通容器 tmp 后代增加产品级禁止，原调查没有作出决定，本篇也不作这个决定。当前普通策略允许精确结构节点的更深业务目录继续接受其他检查；微信额外白名单已锁定其 tmp 后代。此提案尚未修改生产策略，区别于本树中“本机已有实现、源码待提交”的其他 proposed 笔记。

## Evidence

25 个企业微信隐藏 tmp 目录的独立副本在合成容器中通过系统原函数检查，原目录未改动，也未运行真实企业微信。使用 ditto 的清单对照覆盖路径、类型、权限、长度、内容散列与链接目标，没有覆盖全部 ACL、xattr 和时间；不能当作生产迁移器完整验收。

后续 44 项合成矩阵显示：挂载目录内文件读写、删除与内部 rename 可成功；清空后删除挂载根返回 `EBUSY`，与本地 tmp 间 rename 覆盖或 hardlink 返回 `EXDEV`。根目录同父改名到不存在名称可成功，不能笼统说挂载点一律不能改名。用另一目录替换根、交换根或跨父移动的测试失败。新随机兄弟目录仍在本地。

SQLite WAL 的正对照与合成沙盒路径策略各有独立范围；外部软链接在该合成策略下被拒绝，不是 44 次真实企业微信功能测试。静态名称或层级不足以证明任意应用不会删除根或跨卷替换。

## Alternatives considered

- **结构检查通过就推荐全部临时后代**：可展示更多候选，但实测挂载根清理和跨卷原子操作不等价，新临时根也不会被自动重定向。
- **迁移共同父目录以保持同卷操作**：相关文件放在同一卷可避免部分 EXDEV，但共同父目录若是 tmp 或 Documents，便违反固定结构约束。
- **软链接或依赖高级 API 自动 copy-delete 回退**：实现可能更简单，但沙盒授权仍限制外部链接，且回退不是原子 rename，不能作为未知应用的通用兼容保证。

## Acceptance criteria

先明确推荐与硬禁止各自范围，界面区分总占用、结构候选和经过工作流验证的推荐。针对选定应用验证删除/替换根、跨卷临时文件提交及新目录创建，不以合成结构检查替代真实流程。产品决定、代码和验证同批落地后再转 implemented；本次只保存提案依据。

## Risks

过度收紧会封住本来可用的稳定业务目录，直接放开则可能破坏应用临时文件协议。AppPorts 无法仅凭路径静态证明所有调用方式，推荐范围需要可追溯的应用验证；本篇不是执行新磁盘实验或扩大迁移权限的授权。
