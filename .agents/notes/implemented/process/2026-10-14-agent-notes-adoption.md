# Agent Note: 将决策笔记集中到随仓库维护的 Agent Notes

Status: implemented

> 来源：2026-10-14 用户确认的 Agent Notes 迁移任务及 CLAUDE.md 项目约定。

## Problem

旧 docs 被 Git 忽略，没有版本控制兜底，且不同 worktree 保存重复或互相取代的设计、执行计划和验证报告。继续在多处写决定会让后续维护者把过时方案或本机实验当成已提交行为。

## Decision

本项目的决策笔记集中在 `.agents/notes/`，`write-notes-like-deepseek` 完整入库到 `.claude/skills/`，上游提交记录在 `.vendored-from.txt`。笔记规范只引用该 skill，不在 CLAUDE.md 复制另一套状态、格式或归档规则。CLAUDE.md 的项目约定使用英文。

根目录 `AGENTS.md` 为 Codex 提供项目指令入口，要求先读 CLAUDE.md，并在非平凡改动、技术取舍或笔记工作前加载 skill。`.agents/skills/write-notes-like-deepseek` 以相对软链接指向 `../../.claude/skills/write-notes-like-deepseek`，让 Codex 的技能发现与 Claude 的目录共用同一份入库内容。声明“需要安装”不能代替本地可用文件；项目不依赖每个人另装全局副本。

主仓库旧 docs 通过移动保存到 `~/Documents/AppPorts-docs-archive/`，不删除无 Git 兜底的原文。首次迁移不移动四个 worktree 的 docs；其独有决定提炼到主仓库，纯计划和原始证据不变成笔记，工作树自身后续清理由所属任务负责。User_docs 继续承载文档站，不承担决策笔记存储。

此次经确认的迁移区分已提交实现、尚未实施的向导和当时已实现但未提交的后续改动。第三类当时暂放 proposed 并注明入库状态，1.9.1 把它们随对应源码同批转为 implemented；现在 proposed 只保留尚未实施的向导与临时目录提案。这是本次历史迁移的明确处理，不把本机实测否认成没有实现。原文缺少备选或日期时说明来源缺口，不编造。

## Migration audit

身份解析、列表刷新、所有权和容器显示按已提交代码修正过时的“未实施”文字。三处自动恢复同内容文件仅采用主仓库一份；三份长报告也采用包含 10 月 14 日补记的主版本。

自动恢复、微信事故、权限兼容、验证复用和测试边界部分重叠，分别守住职责并互链；报告只补充对应决定，不另立同主题报告笔记。被完全吸收的手工副本管理、独立文件夹取回和个人入口展示路线，把独有理由与限制保留在后继笔记的备选和后果中，不制造过期归档。

两组真实翻转分别保留：已提交的 newfs/owners 与系统建卷/noowners；已提交的不新增长期原包与保留可恢复原包。其他主题按各自机制归属，没有用一个笼统“迁移改进”笔记吞掉不同决定。历史原文的日期、构建与实测数字均只按其记录范围引用。

补充迁移核对 10 月 9 日合订本的 79 个来源、74 份唯一正文及 60 条边界，并对照 10 月 12–14 日真实故障与修订。新增六个独立主题；复制、所有权、恢复、显示与验证的重叠内容原地补充并互链。临时目录推荐仍未实施，与已经入库的建卷和恢复决定分开记录。

普通 APFS 的 diskutil/noowners 与自动恢复方向已经确认。保留历史理由不授予旧路线优先级，不能按 implemented/proposed 文件夹推翻后来已选定的默认或恢复过时限制；历史严格事务仍需按原证据解释。旧调查支持的安全目标与后来兼容修复分别留痕，不把调查报告本身断言为故障原因。

个人用户名、工作树绝对路径和个人卷名从入库笔记及 CLAUDE.md 示例脱敏；来源用归档名称、源 ID 或 worktree 名称定位，原始归档保持原文。已有来源哈希用于核对材料未变，不将原始私有日志复制进仓库。

## Alternatives considered

- **继续在 docs 与 worktree 分散写笔记**：可沿用原布局，但忽略目录没有 Git 兜底，也难以识别重复和当前决定。
- **原样搬文件或把计划日志全部入库**：能保存文字，却把施工步骤、过时状态和原始证据混成现行决策；因此提炼语义并外部保留原文。
- **删除 docs 消除双源头**：目录消失最直接，却不可依赖 Git 恢复；采用移出并核对完整性。
- **在 CLAUDE.md 复写笔记规范**：读取方便，但会形成与 vendored skill 漂移的第二份规范，项目入口只保留指向与特有路径。
- **只在 Markdown 中要求自行安装 skill**：仓库内容更少，但缺失安装或版本差异会影响笔记与门禁，无法保证新工作区有相同脚本；保留仓库内版本。
- **给 Codex 复制第二份 skill**：能放进默认发现目录，但两份正文、模板和脚本可能漂移；采用官方支持的目录软链接。

## Consequences

决定与理由可随仓库审查，完整原文仍有外部副本。代价是外部归档不随 clone 分发，历史原始证据需从归档另行取得；笔记必须明确哪些验证只是原报告记录。本机已实现的提案必须在对应代码入库时同步，不能永久以双重当前状态放置。

Codex 的发现入口与项目使用要求分别明确，减少仅写在 CLAUDE.md 中而被遗漏的情况。代价是必须保留 Git 软链接及其目标；改动路径时同步更新入口。技能能被发现不保证每次自动选中，因此 AGENTS.md 仍明确要求适用任务加载它。已运行的会话不视为自动重新读取了新增项目指令。

## Verification

首次迁移来源指纹覆盖 87 个文件，形成 26 篇笔记；补充后共 32 篇，20 implemented、12 proposed。1.9.1 入库时其中 10 篇源码待提交记录转为 implemented，并新增进度反馈与源码审计范围 2 篇，现为 34 篇、32 implemented、2 proposed（尚未实施的向导与临时目录提案）。合订本 79 份冻结来源逐份核对哈希，重复正文不重复建笔记。逐文件溯源使用纯文本，跨笔记引用使用相对链接。tree 与 format 校验、原资料完整性与提交范围检查构成文档验证；Swift 功能测试和真实磁盘实验没有在此次迁移中重新执行。

发现入口依据官方 [Skills](https://developers.openai.com/codex/skills/) 与 [AGENTS.md](https://developers.openai.com/codex/guides/agents-md/) 文档：项目技能扫描 `.agents/skills/` 并支持目录软链接，项目指令在新运行开始时读取。入口验证核对软链接解析、目标内容一致性和 Git 的 symlink 类型；后续新会话应确认项目指令与技能实际可见。

公开贡献入口中的验证责任与同步要求见[贡献流程入口](2026-10-25-contributor-workflow-entrypoints.md)；本篇原有决定保持适用。

AI 指令入口的内容范围见[精简 AI 指南](2026-10-25-concise-ai-guide.md)，架构与历史事实按需查源码和既有笔记。
