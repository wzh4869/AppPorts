# Agent Note: 首页应用体积使用原生目录遍历

Status: implemented

## Problem

首页缓存未命中和手动刷新都需要重新计算应用包大小。外盘 Xcode 的单包扫描约 1.6 秒，其中逐项构造 URL 并读取文件属性的开销值得消除。

## Decision

首页继续由原有入口解析逻辑决定扫描路径。本地已链接条目计本机入口，外盘条目计真实应用包。每个可见普通文件使用 Darwin fts 已取得的逻辑长度。入口模式还计包内符号链接自身的长度。遍历跳过点文件、带 Finder 隐藏标志的文件和目录、嵌套挂载卷，并保留取消及 50 万可见条目的上限。

## Existing-note audit

[原生目录遍历和四路并发](2026-10-29-页面目录大小扫描优化.md)曾为保住隐藏项和启动入口语义而保留首页的 Foundation 枚举。此次只调整该项决定。数据目录仍计入隐藏项。外部应用库总量继续使用[现有的逐行汇总](../feature/2026-11-19-外部应用库总大小展示.md)。

## Alternatives considered

保留 Foundation 枚举可以直接沿用系统的隐藏项过滤。对同一批真实应用交替计时，复用 fts 已有属性可以减少大包扫描时间。直接调用数据目录的累计函数会混入隐藏文件，也会漏掉本地入口中的链接长度，因此首页单独处理这两条规则。

## Consequences

首页按包独立统计。单包收益随文件数和磁盘而变。扫描达到上限或被取消时，既有接口仍返回已测得的字节数。

## Verification

使用相同的真实应用包交替测量旧、新文件遍历，预热后四轮取中位数。外盘 Xcode 从 1560 ms 降至 977 ms，PyCharm 样本从 104 ms 降至 51 ms，Chrome 样本从 9.4 ms 降至 5.2 ms。各轮分别核对了字节数。专项回归覆盖整个应用软链、深层 Contents 链接、断链、隐藏目录及外部真实包。另用临时挂载的 APFS 卷核对了父目录与挂载点各自的计数。
