# Agent Note: 双文件日志配额隔离、10 MB 默认迁移与诊断导出加固

Status: implemented

## Problem

原有 `AppLogger` 将全部日志写入单一 `AppPorts_Log.txt`，默认上限仅 `2 MB` 且轮转采用同步队列上的全文件读入拆行截半重写。这套设计在实际排障中暴露出四类问题：

1. `AppScanner` 每次扫描按应用逐条写入上百行 `TRACE`，与高频目录监控事件一起挤占 `2 MB` 单文件配额，在轮转截半后迅速冲掉前几天的真实迁移与异常记录；而这些逐应用条目在默认诊断导出时又会被过滤删除。
2. 主应用、后台更新守护（`UpdateRecoveryAgent`）与容器卷自动挂载代理（`ContainerMountAgentInstaller`）共享同一日志文件，仅靠进程内 `DispatchQueue` 无法防止多进程写交错和轮转期写入已替换 inode；同步写盘与全文件轮转还会阻塞主线程。
3. `DateFormatter` 在队列外被并发访问且未固定 `en_US_POSIX`；`recentOperationSummaries` 仅存内存，重启或后台代理失败后导出摘要缺失；`redactedDiagnosticText` 在同行引号/逗号后可能过度匹配且未覆盖 `smb://` / `afp://` 共享地址；`/usr/bin/ditto` 缺少超时上限，macOS 版本映射把 `>= 15` 全部标记为 Sequoia。
4. 设置页缺少日志大小展示及日志位置修改/恢复默认入口，导出弹窗每次都要求先手动选择保存路径后才启用“导出”。

## Decision

### 1. 默认 `10 MB` 配额与一次性向上迁移

- `AppLogger.defaultMaxLogSizeBytes` 统一提升为 `10 MB`，可选档位收口为 `[1, 2, 5, 10, 20, 50, 100]` MB 并追加“不限”（`unlimitedMaxLogSizeBytes = -1`），菜单栏与设置页共享同一常量。
- `AppLogger` 初始化时依据一次性版本键 `MaxLogSizeDefaultVersion = 1` 执行迁移：未设置用户直接使用 `10 MB`；原配置 `< 10 MB`（`1 / 2 / 5 MB`）一次性平滑提升至 `10 MB`，迁移后允许用户再次手动调小并永久保留；原配置 `> 10 MB`（如 `50 / 100 MB`）及“不限”（`-1`）原样保留，绝不降级。
- “不限”模式下完全跳过轮转与 `rename`，永不删除或覆盖任何本地日志文件；诊断包导出副本采用尾部上限读取（主日志最新 16 MB、追踪日志最新 8 MB）与容错 UTF-8 解码，避免超大或含旧版坏字节的历史日志阻塞导出，且绝不删改本地原文件。

### 2. 双文件 `6:4` 磁盘隔离、O(1) 轮转与多进程安全

- 用户设置的单个“最大日志大小”作为磁盘总上限，内部按 `6:4` 拆给两路独立滚动文件（每路各含当前卷与 `.1` 上一卷，四卷总和严格不超过设定上限）：
  - 主日志 `AppPorts_Log.txt` + `AppPorts_Log.1.txt`（共占 60%，单卷 30%）：承接 `INFO / WARN / ERROR / DIAG / DISK / PERF`。
  - 追踪日志 `AppPorts_Trace.txt` + `AppPorts_Trace.1.txt`（共占 40%，单卷 20%，与主日志同目录）：承接 `TRACE`。
- 写入在 `.AppPorts_Log.lock` 的 `flock` 保护下通过 POSIX `O_WRONLY | O_CREAT | O_APPEND | O_CLOEXEC` 追加；单卷超限时以原子 `rename(2)` 将当前卷切为 `.1` 并在新卷首行记录轮转信息，取代全文件读入截半。
- 常规日志派发至 `writeQueue.async` 避免阻塞主线程，同时提供 `flush()` 在 `AppDelegate.applicationWillTerminate`、后台挂载代理、更新守护、启动映像接回进程退出前以及导出/清空/单测时同步排空。
- `DateFormatter` 通过独立锁与 `en_US_POSIX` 保证线程安全；日志同步镜像至 `os.Logger(subsystem: "com.shimoko.AppPorts", ...)`（Release 对自由正文默认 `.private` 保护隐私，Debug 全量可读），替代无条件 `print()` 并打通 `script/build_and_run.sh --telemetry`。

### 3. 日志分级与高频去噪

- 低频高价值排障现场（`DiskUtility` 变更类与失败/超时命令输出、`TreeCopySession` `sourceChanged` 详情、`AppMigrationService` 的 `logPathState` 与入口创建校验、`FileCopier`、外盘弹出退让、ShipIt 跳过、启动接回就绪和自动挂载切换）升格为 `DIAG`，稳定留在主日志；常规成功的 `diskutil -plist` 只读查询不再把 2 KB 原始 XML 灌入主日志，仅在 `TRACE` 记录命令、退出码与输出字节数。
- 删除 `AppScanner` 逐应用 `扫描应用: ...` 写盘刷屏，改为扫描完成后更新内存中的轻量应用清单快照；仅在用户主动勾选“允许包含本机应用列表”时将其脱敏导出为 `app-inventory.json`，同时保留 `removingAppInventoryEntries` 兼容过滤升级前的历史日志。
- `FolderMonitor`（10 秒日志聚合窗，不改变回调防抖时机）与 `ContainerRemountLoop`（兜底复查汇总）对高频重复 `TRACE` 做短窗聚合。

### 4. 诊断导出、脱敏与界面完善

- `recentOperationSummaries` 持久化到同目录 `.AppPorts_Log.operations.json`（保留最近 100 条），并在导出与快照读取时与内存缓存合并去重，跨重启与后台代理可见。
- 诊断包按时序合并 `.1` 与当前卷，继续输出 `AppPorts_Log.share-safe.txt`，新增 `AppPorts_Trace.share-safe.txt`；`/usr/bin/ditto` 复用 `runDiagnosticCommand`（30 秒超时）；`redactedDiagnosticText` 收紧路径终止分隔符（含 `<` 以兼容 XML 标签、避免吞掉同行引号/逗号后文本），补齐多行 plist `<key>VolumeName</key><string>...</string>` 与 `smb://` / `afp://` / `cifs://` / `nfs://` 地址脱敏；磁盘诊断键名统一为稳定英文键（保留历史多语卷名脱敏标签）；修正 macOS 26 Tahoe 及后续版本、M4 机型识别。
- 设置页补齐当前日志总大小显示、日志位置显示、“更换位置”与“恢复默认”按钮，将“在 Finder 中查看 / 导出诊断包 / 清空日志”合并为单排自适应操作栏，修复 `启用日志记录` 绕过 `AppLogger.shared.isLoggingEnabled` setter 的问题；设置页与菜单栏点击“清空日志”统一弹出二次确认框（回车默认取消、确认按钮标红），确认后通过 `FileManager.trashItem` 将日志文件移入废纸篓（不支持废纸篓的路径回退直接删除），防止误操作导致历史日志永久丢失；菜单栏同步增加“恢复默认日志位置”与“不限”档位；`AppPageVisibility` 下沉隐藏页层级（`zIndex = -1`）并向下传递 `isPageActive` 环境值，阻止隐藏的应用页 `TappableBadge` 气泡与目录分割线指针穿透悬浮在设置页上方；`DiagnosticExportDialog` 预填桌面默认保存路径并适配 RTL 布局；新增 5 个 UI 本地化键补齐全部 22 种语言并移除 18 个已不再使用的旧磁盘日志键。

## Alternatives considered

- **仅将高频 `TRACE` 放入 300–500 条内存环形缓冲，出错或导出时落盘**：零平时磁盘写盘，但存在五个不可接受的信息缺失盲区——崩溃/强退/重启后再导出直接清零、无法读取独立短命后台代理进程内存、不抛 `ERROR` 的静默状态异常不会触发落盘、数百条窗口在扫描/监控抖动下几秒即被顶穿、补刷会打乱时间线。因此改为独立磁盘滚动文件隔离。
- **沿用单文件并单纯把上限调大到 10 MB**：改动最小，但全文件读入拆行截半在 10–100 MB 下会明显卡顿主线程，且高频 `TRACE` 仍会稀释真实错误与迁移记录的留存时长。
- **强行将所有老用户（含 50 MB / 100 MB）统一重置为 10 MB**：实现更简单，但会破坏已主动调大日志配额用于长周期排障的用户配置，故采用仅向上迁移 `< 10 MB`、原样保留 `> 10 MB` 的一次性版本迁移。

## Consequences

- **收益**：主日志默认 `6 MB` 独立留存不受 `TRACE` 稀释，追踪日志 `4 MB` 跨崩溃、重启与后台代理完整保留；O(1) `rename` 轮转与异步 `flock` + `O_APPEND` 消除主线程卡顿与多进程交错；诊断包体积在 ZIP 压缩后仍维持 ~1 MB 级别，且跨重启保留操作摘要、一键预填导出路径、补齐网络共享脱敏。
- **代价**：日志目录下新增 `AppPorts_Trace.txt`、`*.1.txt`、`.AppPorts_Log.lock` 与 `.AppPorts_Log.operations.json` 辅助文件；调用方在直接读取底层日志文件（例如单元测试）或进程主动 `exit()` 前需调用 `AppLogger.flush()` 排空异步写入队列；诊断包格式新增 `AppPorts_Trace.share-safe.txt` 与可选 `app-inventory.json`，需在后续排障文档与分析工具中一并查看。
