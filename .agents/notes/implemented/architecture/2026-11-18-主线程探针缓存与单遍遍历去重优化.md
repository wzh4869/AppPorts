# Agent Note: 主线程探针缓存与单遍遍历去重优化

Status: implemented

## Problem

高频路径此前存在多处重复 I/O 与空闲唤醒开销：
- 已完成的 `MigrationTaskRow` 历史行和 `MigrationTaskDetail` 结束态仍无条件运行 `0.5s` / `0.25s` `TimelineView`，`DiskEjectionControls` 在无暂停盘且无待刷新状态时仍以 `Timer.publish` 每 `5s` 唤醒主线程，多处视图保留未读取的 `AppOperationState.shared` 订阅。
- `StorageCapabilityProbe.probe` 每次在 `@MainActor` 同步创建并删除 4 个探测文件，批量迁回会连续触发重复探测并在确认弹窗中二次探测。
- `AppSearchRecordStore.mutate` 无条件重写 JSON 文件。
- `DataDirScanner.inspectItem` 对同一 `volumeUUID` 依次单独起两次 `diskutil info -plist` 且无每轮扫描缓存，`scanLibraryDirsWithDiagnostics` 又对已在 `resultsByPath` 的挂载记录重复 `inspectItem`。
- `WeChatAccountMigrationService.measure` 对整个账号、`msg + business` 与 `msg/file + msg/video` 串行遍历 3 遍，随后迁移在已通过 `AppDataMigrationPreparation` 完整测量的同一套源目录上再重测 1 遍。
- `SignatureSnapshot.remove` 为临时副本构造持久化删除清单导致 3 遍全量 SHA-256 哈希；`SignatureRemovalManifest.remove` 在 `verify` 全树哈希后，`unlinkat` 前又对每个普通文件重算第 2 遍全量 SHA-256；`CodeSigner` 刚 `capture` 完清单又紧接着多跑一次 `verify`。
- `MigrationTaskCenter`、`DiskEjectionService` 与 `DiskEjectionPauseStore` 存在双重历史写盘/通知、已挂载成员找到后未及时 `break`，以及 `save` 前重读自身 `snapshot()` 的冗余开销。

## Decision

在不削弱任何安全不变量、离线保护或内容校验标准的前提下，对热路径执行去重、短时缓存与单遍合算：

1. **界面空闲刷新收紧**：`MigrationTaskRow` 与 `MigrationTaskDetail` 仅在任务未完成（且处于实时进度页）时启用 `TimelineView`；`DiskEjectionControls` 改为 `.task(id: controller.needsRefresh || !controller.pauses.isEmpty)` 按需轮询；移除 `SidebarTargetSection` 与 `AppUpdateActions` 中未读取的 `AppOperationState.shared` 订阅（保留依赖 `AppUpdateController.installationBlocked` 与模态窗口语言刷新的观察者）。
2. **`StorageCapabilityProbe` 目录身份缓存**：先以 `O_RDONLY | O_DIRECTORY | O_NOFOLLOW` 打开目录并检查 `fstat` 无 `UF_IMMUTABLE | SF_IMMUTABLE` 且 `faccessat(..., W_OK | X_OK, AT_EACCESS) == 0`，仅在可写时查询/写入 `5s` TTL 缓存（按 `(st_dev, st_ino, st_mode, st_flags, st_uid, st_gid)` 为键，永不缓存 `nil`）；`ContentView` 迁回弹窗直接复用已探测结果。
3. **`AppSearchRecordStore` 脏写跳过**：`mutate(_:)` 在保留双次 `WriterAdmission.recheck` 边界的同时比较 `records != original`，未变化时直接返回。
4. **`DataDirScanner` 卷状态单进程合并与每轮缓存**：`DiskUtility.volumePresenceAndLockState` 通过单次 `diskutil info -plist` 同时提取在线与锁定状态；`DataDirScanner` 在 `scanKnownDotFolders`、`scanSignatureDependencies` 与 `scanLibraryDirsWithDiagnostics` 开始时清空 `volumeStateCache`，避免同轮扫描对同一 `volumeUUID` 重复起进程，并在回填 `mountRecordsByPath` 时跳过已入列的路径。
5. **`DirectorySizeTraversal` 多子树单遍合算**：新增 `measure(at:skippingDirectories:subtrees:)` 重载，利用目录深度栈在单遍 `fts_read` 遍历中同时汇总账号根与同文件系统内的多级子树（如 `msg` 与嵌套 `msg/file`、`msg/video`）及各自读取异常；跨文件系统挂载的子成员单独回退 `measureDirectorySize`。`WeChatAccountMigrationService.migrate` 新增 `preverifiedSources`，仅当 `DataDirsView` 在同一任务内先执行 `preparation.refresh` 并校验完完整性后才跳过重复预测。
6. **签名删除与验证降重不降标**：
   - 新增 `SignatureSnapshot.itemsWithInfo(in:)`（每项单次 `lstat`）与 `SignatureSnapshot.singleNodeFingerprint(at:info:)`，产生与 `fingerprint(of:)` 逐字节一致的单文件摘要。
   - 临时工作副本清理 `SignatureSnapshot.remove(_:)` 保留删前全树 `itemsWithInfo` 挂载边界检查、允许节点类型检查与无跟随锚定打开、`st_nlink == 1 || S_IFDIR` 解锁及逐节点 `(st_dev, st_ino, kind, birthtime, mtime, ctime, size)` 校验，省去无持久化用途的 3 遍 SHA-256。
   - 持久化回收清单 `SignatureRemovalManifest.remove` 通过 `verifyAndSnapshotStats` 在 1 遍全树哈希时锁住哈希后 `stat`，`removeNode` 打开文件后核对 `(st_dev, st_ino, mode, size, mtime, ctime)`（在 `fchflags` 之前），替代删前第 2 遍全文件重写读哈希；`CodeSigner` 在当次刚 `capture` 完清单时不重复调 `verify`。
7. **任务调度与弹出状态去重**：`MigrationTaskCenter` 抽取 `scheduleRunnableJobs()` 使 `submit`/`cancel`/`finish`/`resume` 只触发一次 `objectWillChange.send()` 与 `persistHistory()`；`DiskEjectionService` 命中已挂载路径即 `break`；`DiskEjectionPauseStore` 的 `pause` 与 `reconcile` 直接透传已加载的 `images`。

## Existing-note audit

- 与[微信账号拆分迁移](../feature/2026-10-20-微信账号拆分迁移.md)同步：保留其分组白名单与不跳过完整性门禁的约束，将三遍同步测量收口为同文件系统单遍 `fts_read` 并允许 `preparation.refresh` 传递 `preverifiedSources`。
- 与[后台迁移任务与异常处理](2026-10-21-后台迁移任务与异常处理.md)同步：`MigrationTaskCenter` 保持原有排队与持久化契约，合并双次通知与双次写盘。

## Alternatives considered

- **彻底删除 `SignatureRemovalManifest.remove` 的 `stat` 二次校验**：更简单，但会在签名备份清理阶段失去从 `verify` 到 `unlinkat` 间的防篡改保护，违反安全删除边界；改用“单次哈希并锁定不可伪造 `ctime`/`mtime`/大小元数据”兼顾速度与安全性。
- **直接按路径字符串缓存 `StorageCapabilityProbe`**：跨挂载变更或目录切换只读后会误命中；改用 `(st_dev, st_ino, st_mode, st_flags, st_uid, st_gid)` 与实时 `faccessat` 前置校验。

## Consequences

- 空闲任务列表、侧栏空间与更新弹窗不再每秒唤醒主线程重绘或后台无效轮询；批量还原、微信账号大小统计、扫描器卷查询与签名临时副本删除的磁盘 I/O 与子进程启动显著减少。
- 代价是 `SignatureRemovalManifest` 要求单文件 `verify` 后紧邻清理前保持 `ctime`/`mtime` 与大小不变，跨卷挂载的微信子成员仍按分支单独统计以确保跨越 `FTS_XDEV` 边界。
