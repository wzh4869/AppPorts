# Agent Note: 停用微信仅大文件与视频新迁移

Status: implemented

## Problem

微信的 `msg/file` 和 `msg/attach` 可以各含一个指向同一份文件的硬链接。旧版「仅大文件与视频」为 `msg/file` 和 `msg/video` 分别建卷，源目录检查发现链接跨出迁移范围时拒绝复制。已有迁移可能只完成了一个成员，或正处于迁回和旧副本清理阶段，升级后仍需要从相同的记录找到卷和本地入口。

## Decision

账号迁移面板和执行模式只提供全部迁移与 `msg + business`。新迁移路径策略在微信账号的拆分成员中只准入 `msg` 和 `business`。账号测算沿用单遍目录遍历，移除旧模式的预览测算和扫描器中专为它补齐的本地候选目录。

保留精确的 `msg/file`、`msg/video` 识别，用于分组展示、挂载、切换冲突检查和还原。新迁移的路径策略默认拒绝这两个路径，只有已有记录的挂载及恢复检查启用原有的精确成员校验。旧账号行按已记录的成员展示挂载状态，提供还原和适用的挂载、解锁操作。仅迁出一个成员的账号也按实际持久化记录迁回，旧版写入的账本可以直接读取。

## Alternatives considered

- 保留旧模式并提前提示硬链接冲突。没有跨目录硬链接的账号仍可选用，但用户决定停止接受新的此类拆分。
- 对跨目录共享的文件写出两份独立副本。可以把图片目录留在内盘，同时迁出文件目录，但需要验证微信后续的读写和新链接行为，并定义还原时对已经分化的内容如何处理。

## Consequences

需要迁出聊天媒体的用户可以使用 `msg + business`，其中整个 `msg` 在同一个卷内，能保留内部硬链接。已选旧模式的用户仍可连接原外置盘还原已迁出的成员，再选择新模式。新用户如需把聊天图片留在内盘，需要保留整个聊天媒体目录在本地。

## Verification

策略测试覆盖新迁移拒绝、目录与同名普通文件的区分、旧成员账号分组、切换模式前的还原要求和设置关闭时的迁回。挂载事务回归通过合成卷验证旧成员可卸载、接回并还原最新数据，且只有记录中的成员进入恢复流程。

用 `script/validate_private_apfs.py --run --wechat-restore` 在一次性 APFS 映像中验证旧成员重新挂载和迁回。迁回后原路径可读到在外置卷上更新的文件，本地视频内容完整，已迁出成员的记录和专用卷均已清理。
