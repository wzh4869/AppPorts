# Agent Note: 历史死代码与过期资产清理

Status: implemented

## Problem

多轮迭代后，仓库残留一批已无生产调用点的原型接口、失效脚本与 PR 截图资源：

- `AppMigrationService` 保留被硬编码开关关闭的 `.transparentHybrid` 创建分支，以及无人监听的 `.signatureMaterialsDidChange` 通知与废弃的 `CodeSigner.ownershipRepairAppleScript`。
- `AppDataScanIdentity`、`DataTransferMaterialService`、`FileCopier.removeCopy`、`OperationLock.isHeldByAnotherProcess`、`AppMoverError.appStoreAppError` 以及被实现忽略的 `removeMigrationBackup:` / `failSourceBackupCleanup:` 参数已无生产路径使用。
- `DataMigrationWorkflow.run` 与 `ContainerMountStore.unfinishedTransfers` 仅由单测驱动，留在生产类型上容易误导后续调用者。
- 根目录 `manage_translations.py`（针对旧 `Localizable.strings`）、`script/prepare_apfs_baseline.py`、`script/benchmark_apfs_lifecycle.py`（引用已移除符号）、`.github/pr-assets/` 与 `assets/screenshots/*/appports-search-exclusion.png` 孤立截图、`AppPorts/StubLauncherBinary`（构建期已改为直接编译至 `$(DERIVED_FILE_DIR)`）、`xcuserdata` 个人配置、`User_docs` 未使用的 `"cn"` 依赖、零引用组件 `HelpButton.swift` / `MigrationTaskToolbarButton`，以及界面与测试中一批只写不读的状态、不可达弹窗/分支和 420 条零引用 `Localizable.xcstrings` 词条均已失去运行时或当前工程用途。

## Decision

移除无生产调用且不影响历史落盘兼容的代码与过期资产，同时严格保留已发布版本的磁盘格式、入口恢复读取能力，以及经代码核实仍在生效的界面契约（如 `@Environment(\.locale)` 刷新订阅、`DataDirRowView.classicModeActive` 与 `Contributor.avatarURL` 解码字段）：

- 删除 `AppDataScanIdentity.swift`、`DataTransferMaterialService.swift`、`CodeSigner.ownershipRepairAppleScript`、`.signatureMaterialsDidChange`、`FileCopier.removeCopy`、`OperationLock.isHeldByAnotherProcess`、`AppMoverError.appStoreAppError`，以及 `DataDirMover` / `ContainerVolumeMigrator` 上已被忽略的 `removeMigrationBackup:` 和 `failSourceBackupCleanup:` 形参。
- 移除 `.transparentHybrid` 的新建入口实现与开关，保留 `hybridPortalExternalURL` 与 `localPortalKind` 识别及迁回恢复分支，确保历史创建过混合入口的用户仍能正常读取与还原。
- 将仅服务于测试驱动的 `DataMigrationWorkflow.run` 与 `ContainerMountStore.unfinishedTransfers` 迁入 `AppPortsTests/LegacyTestShims.swift`，并移除 `AppMigrationServiceTests`、`MigrationSafetyRenderTests`、`LegacySignatureBackupFixture` 中零调用的私有测试辅助与冗余导入，保持生产接口干净且不削减既有恢复测试覆盖。
- 删除 `AppPorts/StubLauncherBinary`（及 `project.pbxproj` 对应排外项）、个人 `xcschememanagement.plist`、孤立 `appports-search-exclusion.png` 截图、`.github/pr-assets/`、`manage_translations.py`、`script/prepare_apfs_baseline.py`、`script/benchmark_apfs_lifecycle.py`、`APFSLifecycleBenchmarkTests.swift`、`User_docs` 未使用的 `"cn"` 依赖、零引用 `HelpButton.swift` / `MigrationTaskToolbarButton` / `MigrationTaskToolbarIcon`，以及 `ContentView` / `DataDirsView` / `CustomDirsView` / `AppMotion` / `AppRowView` / `StatusBadge` / `ReadinessCheckView` 中的死状态、不可达弹窗、重复分支与零调用包装方法；同时清理 `.gitignore` 历史忽略项与 `AppPorts/Localizable.xcstrings` 中全仓零引用的 420 条废弃词条（保留 `PortalLocalizedStrings`、语言自称及仍在 SwiftUI 中由 `.locale` 触发刷新的全部活跃键）。

## Existing-note audit

- [卷盘点与清理退避](../architecture/2026-10-22-volume-state-adaptation.md)：原地同步薄包装 `DataTransferMaterialService` 的移除事实，`ContainerMountStore.preservedMaterials` 继续作为唯一保留材料读取入口。
- [APFS 验证证据](../testing/2026-10-12-apfs-validation-evidence.md)与历史界面改进记录：原地移除指向 `.github/pr-assets/` 和旧基准脚本的失效引用，保留各自原有决策与验证结论。
- [持久化迁移生命周期](../architecture/2026-10-10-verified-transfer-lifecycle.md)与[签名备份外置卷](../architecture/2026-10-15-signature-backup-volume.md)：所有历史账本 schema 解码与磁盘恢复路径保持不变，不归档或改写既有契约。
- proposed 与 rejected 中无同职责提案。

## Alternatives considered

- **连同 `linkApp`、`cancelTransfer`、`signatureMaterials` 等恢复辅助入口一并删除并重写百余条安全测试**：能进一步缩减内部方法数，但改动面波及核心安全回归断言，存在误伤恢复覆盖的风险；仅下沉纯测试包装，保留经过验证的内部恢复原语。
- **一并删除 `.transparentHybrid` 的读取和迁回识别**：代码更少，但会导致极早期创建过该类本地入口的用户无法被扫描识别和还原；只删新建路径，保留只读识别与还原。

## Consequences

生产模块不再暴露失效原型开关、无监听通知或已被忽略的参数，测试专用便捷入口不再混入正式服务表面，仓库体积与 `.gitignore` 规则更清晰。

历史落盘账本、旧版签名记录与旧版混合入口的识别及恢复兼容继续保留，因此对应的识别代码仍需随迁移服务维护。移除旧手工基准脚本后，如需重新做 APFS 生命周期吞吐对比，应基于当前 `ContainerVolumeMigrator` 公开入口新建独立测量夹具。
