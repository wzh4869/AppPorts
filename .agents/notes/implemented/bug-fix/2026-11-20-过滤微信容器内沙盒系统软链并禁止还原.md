# Agent Note: 过滤微信容器内沙盒系统软链并禁止还原

Status: implemented

## Problem

macOS 沙盒容器的 `Data/Library/` 下默认存在一整套指向同一用户 `~/Library/` 的相对符号链接（如 `Mail`、`Keychains`、`Dictionaries`、`Sounds`、`Application Support/iCloud`、`Application Support/SyncServices`、`Application Scripts/<bundleID>`、`Images/People`、`Preferences/com.apple.security.plist` 等）。

`DataDirScanner.scanContainerStructure` 原本通过 `shouldSurfaceNestedContainerLink` 过滤目标落在用户主目录 `~/` 内的常规容器软链，但该分支错误地附加了 `decision.canMigrate` 前置条件。其他沙盒应用在 `DataPathPolicy` 中对这些子路径返回 `canMigrate == true`，因此正常被过滤；唯独微信（`com.tencent.xinWeChat`）走专属白名单，将非白名单子路径一律标记为 `weChatCompatibilityDirectory`（`canMigrate == false`），导致微信容器内 28 条 `Data/Library/*` 系统软链全部绕过过滤并被暴露为「现有软链」与可点击的「还原」按钮。

更严重的是，执行层 `DataDirMover.restoreRetainingOriginal` 对无 AppPorts 标记的容器软链直接放行，且未拒绝目标位于用户主目录的系统入口。一旦用户点击未被系统进程占用的项（如 `Keychains`、`Dictionaries`、`Sounds`），`restoreAndComplete` 会将本机真实的 `~/Library/<X>` 复制进微信容器并清理原目录，造成系统用户数据丢失风险；而对不存在目标的悬空系统软链（如 `SyncServices`）则会误报「外部存储目录不存在」。

## Decision

建立跨越模型、扫描、界面与执行四层的统一沙盒系统软链识别与拦截边界：

1. **统一规则（`AppPorts/Models/DataDirItem.swift`）**：
   - 新增 `DataDirItem.isSandboxHomeEntryLink(source:target:)`，识别 `<home>/Library/Containers/<containerID>/Data/...` 下指向同一用户主目录对应位置的 macOS 沙盒便捷软链：
     - `Data/<PersonalFolder>` → `<home>/<PersonalFolder>`（`Desktop`、`Downloads`、`Movies`、`Music`、`Pictures`），同时由 `isSandboxPersonalFolderLink(source:target:)` 单独区分；
     - `Data/Library/<subpath>` → `<home>/Library/<subpath>`，且排除 `Data/Library`、`Data/Library/Application Support`、`Data/Library/Preferences` 等受保护结构目录本身。
   - 比较目标路径时同时兼容词法路径与 `resolvingSymlinksInPath()` 规范路径（处理 `/var` 与 `/private/var` 及悬空相对软链）。
   - `DataDirItem.isUserDirectoryLink` 复用该判断（保留 `!hasManagedLinkRecord && recoveryOperationID == nil` 约束），使所有受检的沙盒系统软链均不计入大小、不触发 `needsRecoveryOrAttention`、不在界面展示操作按钮。

2. **扫描层过滤（`AppPorts/Utils/DataDirScanner.swift`）**：
   - 在 `scanContainerStructure` 中，对未登记为受管的 `existingSymlink`，除需保留为隐藏只读行的顶层个人目录入口（`isPersonalFolderShortcut`）外，只要命中 `item.isUserDirectoryLink` 或满足原有 `decision.canMigrate && !shouldSurfaceNestedContainerLink(...)`，一律在扫描阶段剔除。
   - 受保护结构目录本身（如 `Data/Library`、`Data/Documents`、`Data/Library/Application Support`）以及指向外置盘（`/Volumes/...`）的真实历史迁移软链不受影响，仍保持可见与可还原。

3. **界面与执行层硬守卫（`AppPorts/Views/DataDirsView.swift`、`AppPorts/Utils/DataDirMover.swift`）**：
   - `DataDirsView.askManageExistingLink` 对 `item.isUserDirectoryLink` 直接返回。
   - `DataDirMover` 在 `restoreRetainingOriginal`（在 `fileExists` 检查之前同时校验单跳词法目标与解析后目标）、`createLink` 和 `resetExistingLink` 中对无受管记录的沙盒系统软链统一抛出 `DataDirError.sandboxSystemLink`，既防止误删 `~/Library/*` 真实目录或破坏系统软链，也避免悬空 `SyncServices` 误报「外部存储目录不存在」。
   - 新增错误提示文案先补齐 `zh-Hans` 与 `en`（按维护者指示其余语种留待后续统一补全）。

## Alternatives considered

### 1. 仅放宽 `scanContainerStructure` 对 `weChatCompatibilityDirectory` 的 `shouldSurfaceNestedContainerLink` 过滤

直接把第 1903 行的 `decision.canMigrate` 改成 `decision.canMigrate || decision.role == .weChatCompatibilityDirectory` 改动最小，也能立刻隐藏微信的 28 条 `Data/Library/*` 软链。但该方案有两处缺口：一是当用户切到其他外置盘或未选外置盘时，若微信兼容锁定路径下存在指向另一块外置卷的旧迁移软链，会被 `shouldSurfaceNestedContainerLink` 一并隐藏；二是执行层 `DataDirMover` 仍无硬守卫，一旦旧缓存或直接调用触发 `restoreAndComplete` / `resetExistingLink`，依然存在删除 `~/Library/*` 的数据丢失风险。因此采用精确匹配 `Data/Library/<X> -> ~/Library/<X>` 并联动执行层拦截。

### 2. 在 `DataDirMover` 中一律禁止还原所有指向 `~/` 内的软链

禁止还原目标位于 `~/` 内的全部无标记软链规则更短，可以覆盖所有系统软链。但部分测试或用户手工将目录迁到 `~/` 下的自定义位置时，宽泛拦截会误伤非沙盒系统入口的合法链接；按容器相对路径与 `~/` 目标精确镜像校验，既 100% 覆盖 macOS 沙盒生成的 33 类入口，又不影响普通目录和外置盘还原。

## Consequences

- **收益**：
  - 微信应用数据页不再把 macOS 自带的 28 条 `Data/Library/*` 软链暴露为「现有软链」和「还原」按钮，扫描日志与汇总统计不再产生虚假现有软链噪音；
  - 执行层在 `restoreAndComplete`、`createLink`、`resetExistingLink` 彻底阻断对 `~/Library/Mail`、`~/Library/Keychains`、`~/Library/Dictionaries` 等系统目录的误搬迁/误删除，以及悬空 `SyncServices` 的误导报错；
  - 微信容器内真正指向外置存储的历史迁移软链及受保护结构目录自身的异常软链仍可正常发现和还原。
- **代价与已知边界**：
  - `DataDirItem.isSandboxHomeEntryLink` 依赖 `<home>/Library/Containers/<id>/Data/Library/<subpath>` 与 `<home>/Library/<subpath>` 精确同构；如果未来 macOS 新增指向 `~/` 下不同相对路径的沙盒系统链接，需要补充识别规则。
  - 新增错误文案 `该符号链接是 macOS 沙盒系统目录入口，不是应用迁移数据，不能还原或解绑：%@` 当前仅在 `Localizable.xcstrings` 补齐 `zh-Hans` 和 `en`，其余语种将回退到源文案并会在全语种本地化审计中提示，待后续批次统一补齐。
