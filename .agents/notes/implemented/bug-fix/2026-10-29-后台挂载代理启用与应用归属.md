# Agent Note: 后台挂载代理注册同时核对启用状态与应用归属

Status: implemented

## Problem

现场自动挂载代理 plist 存在，但 launchctl print-disabled 显示该服务被禁用，print 查不到已注册服务。两个加密媒体卷已解锁且原位挂载，主程序运行时可用，却不能据此证明后台接管正常。旧安装流程只相信 bootstrap 或兼容 load 的退出码，没有恢复持久化禁用状态，也没有在命令后核对注册结果，可能记录假成功。

系统设置还以签名开发者姓名显示后台项。现有 legacy LaunchAgent 没有关联应用标识，用户难以识别这是 AppPorts 的自动挂载功能。

## Decision

有受管挂载或恢复记录时，安装与启动校准先对本用户域的精确服务执行 enable；失败立即终止，保留现有定义，不先 bootout。定义相同且 print 确认已注册时保留现有进程；其余情况按原有操作锁约束 bootout、原子写定义、bootstrap，保留兼容 load 回退。两种加载命令之后都必须以 print 确认服务已注册，才能记录安装成功。正常退出的按需代理仍算已注册，不要求进程持续运行。

`configureAgent` 注入命令执行和配置写入边界，测试不运行真实 launchctl。LaunchAgent 增加 `AssociatedBundleIdentifiers = [com.shimoko.AppPorts]`，遵循本机 launchd.plist 手册对 legacy plist 的系统设置归属要求。该字段使新定义与旧定义不同，下一次安装校准沿用既有重新注册流程。签名、开发团队、完全磁盘访问身份、卷记录和密码保管规则保持原有机制。

## Alternatives considered

仅让用户打开主界面：可暂时接管挂载，但后台代理仍可能处于持久禁用状态，不能恢复登录与插盘时的自动挂载。

只增加 enable：能修复当前禁用状态，但加载失败或 legacy load 假成功仍无法被发现；因此同时核对最终注册结果。

只修改 Label 或签名姓名：Label 是服务身份，签名关系影响钥匙串与完全磁盘访问；它们不能替代系统文档要求的应用关联字段。

本次迁移到 SMAppService：可改变后台服务的安装方式，但涉及打包、注册、系统授权与旧服务迁移，不是修复现有 legacy 安装缺口的必要条件。

## Consequences

安装成功表示对应服务已经启用并注册，系统可按事件启动它；主界面不再成为恢复代理禁用状态的唯一偶然执行者。代价是已有受管记录触发安装或启动校准时，会恢复该服务的启用状态，包括用户曾手动禁用的同名服务。该行为只针对 AppPorts 自己的挂载代理，不修改其他后台项；手动卸载和弹出暂停记录仍决定卷是否允许挂载。

应用归属字段不删除系统的旧后台项缓存，不能保证旧开发者分组立刻消失；最终名称与图标需安装新版并重新注册后在系统设置确认。此变更不保证钥匙串可读、加密卷可解锁或挂载权限可用。

## Verification

现场恢复现有安装版服务的 enable 与 bootstrap 后，代理独立启动，确认四个挂载点就位，正常退出；系统显示 enabled，已注册且 last exit code 为 0。用户确认可用。该证据来自原有二进制及已经解锁的卷，不构成新版验证或从锁定状态自动解锁的证明。

`ContainerMountAgentTests` 增加禁用服务重注册、无变化不重启、启用失败保留原配置、load 返回成功但未注册仍报错，以及应用关联字段用例。本批仅做 Swift parser 静态检查及笔记门禁，未编译、构建、执行测试或安装新版；后台项显示效果尚未实机验证。
