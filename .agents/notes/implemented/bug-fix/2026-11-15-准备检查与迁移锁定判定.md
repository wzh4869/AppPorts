# Agent Note: 准备检查、文档入口与迁移锁定判定

Status: implemented

## Problem

维护者实机发现帮助页 storage-capabilities.html 返回 404，DeepSeek 从底部迁移时未显示锁定选择。准备情况把普通文件可写称为 App 管理已授权，已就绪时又隐藏设置入口。当前新旧安装证书相同且都匹配系统授权要求，不能把完全磁盘访问拒绝归因于证书替换。

同盘 APFS 隔离目录的生产能力探针实测：未锁定时四项全部支持，UF_IMMUTABLE 锁定后四项全部被判不支持。还原提示把在应用包内创建探针失败当作卷能力缺失，是可复现误报。锁定选择的界面使用扫描标记、执行使用实际更新器，存在跳过确认却按默认值上锁的代码路径；这次实机为何缺少扫描标记尚无直接证据。

## Decision

App 管理独立显示待核对，始终提供系统设置入口，并复用完全磁盘访问的文件图标拖拽与浮窗。普通文件写入不能证明修改其他应用的授权，因此移除该探针；完全磁盘访问继续使用现有实际打开受保护文件检查。拖拽接受不改变授权状态，不读写 TCC 数据库，不引入私有状态查询。

App 管理的系统跳转标识使用 Privacy_AppBundles，与系统 SecurityPrivacyExtension 的 TCCServiceList.plist 中 kTCCServiceSystemPolicyAppBundles.revealElementKeyName 一致。错误的 Privacy_AppManagement 仍会被 URL 处理器接受，但只打开隐私与安全性总页；处理器返回成功不能证明子页已经打开。这个入口直接定位子页，不增加辅助功能权限或自动点击。

设置齿轮与设置页的准备情况检查按钮共用 PermissionReadiness 的当前权限结果。完全磁盘访问检查被拒绝时显示静态红点，无法确认时显示橙点，通过后清除；App 管理的待核对与存储格式不参与提示点判定。提示有现有文案组成的悬停与可访问状态，颜色不是唯一说明。启动、回到前台、打开设置和检查页时刷新，检查页结果同步到两个入口，不增加定时器或授权历史持久化。

迁移、整包符号链接迁移和接回入口使用 AppMigrationService 的实际更新器检测创建同一个锁定选择。确认内容捕获本次应用和目的位置，取消不提交操作；只有锁定按钮提交 true，没有更新器时提交 false。界面提交层不再默认上锁，后台位置切换、既有锁接管和更新恢复保持原边界。接回后加锁也检查实际应用内容。

存储探针使用应用包外的现存父目录，在独立临时文件上测试原四项能力。创建失败、访问拒绝及其他不明错误返回未知，只有明确不支持的操作结果才报告缺失；临时文件由局部 defer 清除。不给应用包解锁，不在其签名树里创建文件，不以 APFS 名称代替能力测试。

应用文档链接生成三语现行的 /docs、/en/docs、/zh-Hant/docs 路径，保留显式章节。准备 APFS 的入口改用 storage-guide#prepare-apfs，赞助菜单复用同一链接生成器；站点不增加旧地址兼容层。版本保持 2.2.1 / build 53，初次验证不安装；仅在维护者后续明确授权时替换安装版。不提交、推送或发布。

## Alternatives considered

- 保留普通文件写入探针，额外加设置按钮：改动最少，但仍会错误称为 App 管理已授权，故改为独立待核对。
- 读取私有授权状态或系统数据库：有机会显示开关值，但会增加权限依赖及系统适配；当前批准范围选择保留核对入口。
- 使用持续小动效或把所有 warning 都显示成红点：更显眼，但会把无法自动确认的 App 管理当成持续缺权限；使用共用的静态提示点，红色只对应明确拒绝。
- 继续依赖扫描标记：省去点击时读更新器，但它与执行检测不同，漏识别时又有默认 true；复用执行检测并要求明确选择。
- 按文件系统名称判断：避免创建文件，但不能反映挂载选项与实际操作能力；继续使用应用包外的真实探针。

## Consequences

App 管理没有自动已授权状态，用户需在系统设置核对。不可写位置的未知能力不会触发降级提示，实际迁移仍由复制与校验实现判定能否完成。已在旧盘发生的真实信息丢失无法由这项修正补回。

回归使用隔离应用和磁盘，不修改用户的 AppPorts、DeepSeek、聊天、设置或系统授权。权限拖拽进入系统设置、开关授权和重启后识别仍需实机验收；截图渲染不能替代授权测试。
