# Agent Note: 解除应用更新保护时统一清除应用缓存锁

Status: implemented

## Problem

网易云音乐第一次非锁定迁移后的自更新成功。第二轮先锁定迁移并尝试更新，Sparkle 将包内带 UF_IMMUTABLE 的 Autoupdate.app 复制进本机缓存，安装外盘旧应用时失败。用户迁回再非锁定迁出后，11:22:47 的更新日志报无法删除旧辅助缓存。现场原应用及包内辅助程序已无锁，缓存辅助程序的全部 72 个节点仍带不可变位，实际版本仍为 3.1.12。数据迁移的三个目标在线；本次错误指向本机更新辅助缓存，不指向歌曲或业务数据。

## Decision

增加 AppUpdateCache，统一处理当前应用 Bundle ID 对应的用户 Caches/<Bundle ID> 与 Caches/<Bundle ID>.ShipIt 两棵树。用户明确要求解除保护后的应用及缓存恢复成未锁定状态，不局限于一份 Sparkle 辅助程序。应用包沿用现有保护解除与旧锁接管；缓存按应用归属统一清除不可变位，不要求辅助程序或缓存内容与当前应用相同，因为这里只解锁，未安装或删除任何内容。

只清 UF_IMMUTABLE，保留其他属性与所有文件，由应用自己的更新器进行后续更新。复用 SignatureSnapshot 的普通树枚举和 DataPathIdentity 校验，共享操作准入在每个写入前复查。迁回及非锁定迁移在正常转移准备阶段调用，已有中断记录重试复用同一路径；显式解除保护调用同一实现。缓存根不得通过软链接跳转，子软链接只清自身标记而不跟随目标；只操作当前用户的节点，普通文件存在硬链接时保留该项并记录原因。其他应用的缓存不参与。锁定迁移不改变缓存锁。没有新增轮询、后台任务、下载或安装更新逻辑、落盘格式和界面文案；交付 build 按维护者要求升至 54。

## Alternatives considered

- 锁定迁移时排除包内更新辅助程序：可以避免新副本继承锁，但改变现有整包更新保护规则，且无法处理已经出现的带锁缓存，本次保留整包锁定行为。
- 只处理 Sparkle 固定辅助文件：范围最小，能处理本次直接错误，但遗漏同一应用其他更新缓存的残留锁；采用 Bundle ID 归属范围统一解锁。
- 删除整个应用缓存：可直接移除锁与残留内容，但会丢失仍有用的缓存及更新材料；保留文件，只清不可变位。
- 要求整包内容与当前辅助程序相同：可以证明副本内容，却会把正常的旧版本辅助缓存留锁。本操作只清不可变位、保留原内容，无需做安装级内容验证。

## Consequences

应用对应缓存里原有的手动不可变位也会解除，这是统一恢复非锁定状态的明确取舍；其他标记不变。缓存需要一次目录枚举，只读取节点元数据而不计算整包摘要。标准 Bundle ID 缓存目录以外的自定义更新路径不猜测归属。取消转移不重新给独立缓存上锁。解锁成功不等于整次应用更新成功，仍需网易云实际更新复测；不删除或归档缓存。
