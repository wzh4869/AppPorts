# Agent Note: 恢复微信文件与视频迁移

Status: implemented

## Problem

微信可以在 `msg/file` 和 `msg/attach` 放置指向同一份文件的硬链接。单独迁出文件和视频时，复制器只看到部分入口，原模式因此停止新迁移。将整个 `msg` 迁走能保留链接，却会把聊天附件一起移动。

## Decision

账号面板提供 `msg/file + msg/video` 模式。只有开启微信拆分迁移的对应容器和有关账本的重试，才允许为这两个精确目录分离跨界普通文件硬链接。扫描记录每组源文件在迁移范围外的入口数，保留目录内的硬链接关系，并要求外盘副本通过原有内容、元数据和目录内链接校验。其他目录、特殊节点及目标卷继续拒绝跨界硬链接。

开始清理前验证源端链接计数和身份。恢复中断清理按已记录的 inode 确认剩余入口，避免已清理的组首路径变化影响续跑。清理只移除迁移范围内的旧入口。还原使用外盘版本建立本地副本，原来留在本地的其他入口和文件保持原样。

## Alternatives considered

- 整体迁移 `msg` 可以保持所有共享关系，同时会迁出聊天附件。
- 为跨界链接创建指向外盘文件的软链接能节省对应的内盘空间，但改变微信沙盒路径和离线访问行为，并需要替换计划外的入口。
- 跳过跨界文件会留下目标目录缺项，原路径切换后微信无法按原路径读取这些文件。

## Consequences

共享文件继续占用原有本地空间，外盘增存一份独立副本。迁移后两份文件的写入互不影响，且 macOS 不能在两个卷间新建硬链接。若发现源文件或链接计数改变，现有校验拒绝清理并保留原件。旧快照缺少新增的可选计数字段时继续采用原规则。
