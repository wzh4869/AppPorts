# Agent Note: 已退出进程登记的有界回收

Status: implemented

## Problem

主程序和挂载代理退出后遗留 `.writer-presence/<PID>.plist`。逐年启动累积小文件，但登记内容损坏不能等同于进程退出，旧版发布者也不会遵守新维护锁。

## Decision

启动登记成功后在 utility 后台队列发起一次分批遍历。回收仅以 `kill(pid, 0)` 返回 ESRCH 确认 PID 不存在；活着、权限不足或无法判断的 PID 均保留。PID 被无关程序复用也保留，待它退出后再处理，避免把进程相关性识别引入垃圾回收。

单轮最多枚举 256 项、尝试处理 64 个候选，并使用单调时钟的 20ms 软预算。登记发布和所有操作边界的准入检查保持原协议；重复获取 OperationLock 不触发回收。维护锁只串行化回收器，以非阻塞方式获取。

回收器通过目录描述符和 RENAME_EXCL 将候选移到随机 `.claim-<PID>-<UUID>` 名字，再核对设备、inode、大小和修改时间并复查 PID。只有同一份、对应 PID 仍已退出的暂存文件可以删除。发布者可继续在公共名字原子发布；它不能替换随机暂存名字。观察之后发布的新文件如果被移入暂存，则尝试以 RENAME_EXCL 恢复；目标已存在时保留两份，绝不覆盖较新的公共登记。

暂存文件也承担中断恢复：下次启动遇到合法 claim 名字先尝试恢复公共名字。恢复失败保留文件。普通登记只处理当前用户、单硬链接的普通文件，不跟随符号链接。回收只在当前用户私有的登记目录内执行。

## Alternatives considered

- 删除前比较 inode 然后 unlink 公共路径：代码简单，但比较和删除之间的新发布仍可能被删。
- 发布与删除共用新锁：合作的新版本容易串行化，但旧版不遵守锁，无法覆盖兼容场景。
- 按文件年龄删除：不需要进程查询，但长时间运行的有效登记也会变旧。

## Consequences

已退出进程留下的损坏登记也可回收；PID 查询失败不扩大删除范围，回收失败不向启动调用者抛错。暂存处理保护并发更新的内容，新增的维护文件和 claim 都在原登记目录内，不触碰迁移、挂载及恢复副本。

代价：公共名字在暂存与恢复之间可能短暂缺失，其他版本在此窗口内可能保守拒绝一次操作，安全准入不会因此放行。进程在暂存后崩溃会让登记持续缺失，直到下次回收恢复；不能宣称对所有旧版本完全无感。恢复冲突的 claim 保留，存在额外小文件。后台遍历保留同一目录枚举流，每批达到预算后暂停 10ms 再继续，避免稳定前缀饿死尾部。进程退出会结束未完成的遍历，下次启动重新扫描；持续产生文件时不保证目录始终清空。这些限制需要在扩大清理范围或引入持续后台维护前重访。

## Testing

`WriterAdmissionTests` 覆盖退出后损坏登记、有效登记、原子替换、进程重新出现、符号链接、删除数量预算、零扫描预算、中断恢复冲突和跨批保留枚举位置；`OperationLockTests` 验证原有互斥和准入行为。测试使用独立目录和注入的退出判断，不清理用户的实际登记。2026-10-28 专项执行共 33 项通过（WriterAdmission 25 项、OperationLock 8 项），无失败；独立代码审查指出的扫描饥饿已修正并复查。笔记树、格式和归档封印检查通过。Release `xcodebuild clean build` 通过（arm64 与 x86_64，无代码签名）。全量测试未执行。
