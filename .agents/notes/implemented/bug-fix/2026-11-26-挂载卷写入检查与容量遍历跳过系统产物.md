# Agent Note: 挂载卷写入检查与容量遍历跳过系统产物

Status: implemented

## Problem

[Issue #115](https://github.com/wzh4869/AppPorts/issues/115) 报告在 macOS 27.2.1 下对 Telegram 挂载迁移后的 `~/Library/Group Containers/6N38VWS5BX.ru.keepcoder.Telegram/appstore` 执行还原时，准备阶段约 0.4 秒即以 `DataOperationSafety.Failure.accessDenied` 失败，提示“AppPorts 暂时无法访问这个位置，请在系统设置中检查访问权限”。同类用户反馈中，已挂载微信账号目录也出现相同还原失败与“统计不完整”，部分未挂载本地目录同样仅报告最外层目录需要系统权限。

原因在于：

1. 挂载迁移将业务目录变成独立 APFS 卷根目录。一旦系统或应用在该卷内调用标准接口（例如 `FileManager.url(for: .itemReplacementDirectory, ...)` 或 `trashItem(at:)`），macOS 会在卷根按需生成 `.TemporaryItems`、`.Trashes`（POSIX 权限 `0311`，仅可写与进入、不可列目录）。即便用户已授予完全磁盘访问权限，`lsof +D` 与 `fts_read` 对其 `opendir` 仍必然返回 `Permission denied`（`EACCES`）。
2. `ContainerVolumeMigrator` 在复制与 `syncTree` 阶段已通过 `volumeSystemArtifacts` 排除这些卷级系统产物，但 `DataOperationSafety.requireNoKnownWriters` 与 `DirectorySizeTraversal` 对已挂载卷根未排除它们，导致 `lsof` 警告被误判为缺少系统磁盘访问权限，容量遍历将其记为 `readIssues`。
3. `DataOperationSafety.requireNoKnownWriters` 与 `AppDataMigrationPreparation.refreshedItem` 均吞掉了具体报错子路径、错误码与 `lsof` stderr，使日志与提示无法区分全局 TCC 权限缺失、局部子路径不可读与非权限 I/O 错误。

## Decision

1. **写入者检查仅对已挂载卷根的已知系统产物豁免**：
   - `DataOperationSafety.requireNoKnownWriters(at:bundleIdentifier:preferWholeVolumeInspection:excludingRootEntries:)` 在保留 `preferWholeVolumeInspection`（`lsof +f --` 按卷查句柄）的同时新增默认空集合参数 `excludingRootEntries`；只有当 `excludingRootEntries` 非空，且 `lsof` stderr 行严格匹配 `lsof: WARNING: can't (opendir|lstat|stat|readlink)(<path>): (Permission denied|Operation not permitted)`，且 `<path>` 位于被检查根路径（同时核对 `standardizedFileURL`、`resolvingSymlinksInPath()` 与 POSIX `realpath`，以兼容 macOS 上 `/var` 与 `/private/var`、`/tmp` 与 `/private/tmp` 的前缀差异）的直属 `excludingRootEntries` 名称下且不含 `.` 或 `..` 路径穿越段时，才忽略该行警告。
   - 其它任何 stderr 行（含非排除子目录权限报错、根目录自身不可读、未知警告或异常退出码）仍 fail-closed；同卷其他业务目录上的真实写入进程仍正常拦截为 `.writers`。
   - `ContainerVolumeMigrator` 提供统一内部封装 `requireNoKnownWriters(at:bundleIdentifier:)`，仅在 `isMountPoint(url)` 为真时传入 `Self.volumeSystemArtifacts`；`ContainerVolumeMigrator.swift` 与 `ContainerVolumeMigrator+Recovery.swift` 全部调用统一经过该封装，普通本地目录与未挂载暂存目录保持空排除集。

2. **容量统计对已挂载卷根跳过系统产物**：
   - `measureDirectorySize`（`AppPorts/Utils/DataDirScanner.swift`）与 `WeChatAccountMigrationService.measure`（`AppPorts/Services/WeChatAccountMigrationService.swift`）在目标本身为挂载点（`isMountPoint == true`）时，将 `ContainerVolumeMigrator.volumeSystemArtifacts` 对应的直属路径加入 `skippingDirectories` 传给 `DirectorySizeTraversal.measure`。`DirectorySizeTraversal` 在 `FTS_D` 与 `FTS_DNR` 分支均跳过 `skippedPaths`，从而消除 `.TemporaryItems` / `.Trashes` 导致的“统计不完整”误报，也不再将 `.Spotlight-V100` 计入应用数据大小。

3. **保留具体失败子路径与结构化日志，不新增用户界面文案**：
   - `DataOperationSafety.requireNoKnownWriters` 失败时通过 `AppLogger.shared.logContext` 记录原路径、解析出的失败子路径、退出码与截断的 stderr（≤512 字符，导出时走既有脱敏规则）；遇到非排除子路径的权限报错时，`.accessDenied` 携带该具体子路径。
   - `AppDataMigrationPreparation.refreshedItem` 在 `!measured.isComplete` 时记录前 5 条 `readIssues` 摘要；存在 `isPermissionDenied` 条目时抛出 `.accessDenied(denied.url.path)`，全为非权限读取错误时改抛 `.inspection(firstIssue.url.path)`。沿用既有本地化错误文案，不修改 `Localizable.xcstrings`。

## Alternatives considered

1. **按文件路径逐个运行 `lsof -- <file>` 或放弃 `lsof +D`**：可以绕过系统隐藏目录，但对百万级文件目录逐一传入路径不可行，且会改变既有写入者发现范围与超时契约。在 `lsof +D` 结果解析阶段仅对挂载卷根白名单产物做严格路径前缀过滤，改动最小且保留完整业务树检查。
2. **新增“部分子目录无权限”专属错误类型与 22 语种本地化文案**：能进一步把“FDA 缺失”和“局部 POSIX 权限缺失”分成两条用户提示，但需要新增 22 语种翻译并调整错误弹窗判断分支；先让现有 `.accessDenied` / `.inspection` 精确指向真实子路径并落盘日志，能在零翻译风险下直接暴露根因，后续如仍需细分提示可独立演进。
3. **在 `DirectorySizeTraversal` 内硬编码跳过所有名为 `.TemporaryItems`/`.Trashes` 的目录**：会无意隐藏普通本地子树内同名目录的真实体积或读取异常；仅在 `isMountPoint == true` 时由上层通过 `skippingDirectories` 传入，只影响卷根直属条目。

## Consequences

- **收益**：
  - 修复已挂载 APFS 卷生成 `.TemporaryItems` / `.Trashes` 后还原永久卡在 `0.4s` `accessDenied` 的问题，同时消除挂载卷因此被误标“统计不完整”或计入 `.Spotlight-V100` 的问题；
  - 所有安全检查与准备扫描的读取失败都会把真实子路径与底层诊断写入日志，便于快速定位普通本地目录（如钉钉等）中的异常子项。
- **代价与边界**：
  - 放行仅以 `isMountPoint(url)` 为前提；若出现尚未修复或未被识别为挂载点的异常卷根路径，仍会保守按 `.accessDenied` 拦下；
  - 普通本地目录中若应用自行创建了 `0311`/`000` 子目录，依旧会安全阻断迁移（现可精确定位到该子路径），不盲目绕过未知权限限制。
