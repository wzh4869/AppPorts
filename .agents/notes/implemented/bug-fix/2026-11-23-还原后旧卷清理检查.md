# Agent Note: 还原后按挂载卷检查旧副本的写入进程

Status: implemented

## Problem

还原已提交后，旧 APFS 卷在移除前仍要检查写入进程。目录模式的 `lsof +D` 要先遍历全部目录，微信大目录的检查可以长时间没有文件进度。微信账号行也把已还原的本地成员和仍有迁移记录的成员归为「待完成」，用户可以再次触发迁移或还原，却没有直接查看该账号旧副本的入口。

## Decision

还原清理时先确认旧卷的 UUID 和挂载位置。在系统挂载表确认待检查路径为文件系统根时，使用 `lsof +f` 按卷匹配打开的句柄，涵盖正常清理挂载点和重新接盘后的自动挂载点。普通目录继续按其目录树匹配，避免将其他目录的写入计入本次操作。用于授权删除的旧卷文件清单、卷身份和持久化记录仍参与检查。

首次清理与按记录重试进入同一清理阶段，进度提示依次报告当前数据检查、旧副本检查和卸载。清理异常按原操作 ID 写入诊断日志。

旧卷清理失败时同时保存失败原因和下次重试时间，包括写入删除检查点之前发生的离线和身份检查错误。记录也保留原阶段和删除证据，详情页可从原记录显示原因。

目录扫描把当前入口与已提交还原的记录核对，确认后将该结果传给微信账号分组。只剩旧副本待处理时，账号显示「已还原到本地」和「查看旧副本」，按成员路径展示该账号的记录。符合新迁移条件的拆分账号（`msg + business` 或 `msg/file + msg/video`）可以明确选择「迁移」。仍有成员挂载在外盘或存在未提交操作时，账号保留原有的继续或还原流程。

账号的「查看旧副本」入口在后台重新读取账本，再按标准化的账号及成员路径打开有待处理记录的弹窗。列表扫描与面板的记录刷新可能在不同时间完成。若已无匹配旧副本，重新扫描目录行。弹窗打开期间最后一条旧副本记录完成时，关闭弹窗并更新目录行。

拆分账号的还原资格来自成员中仍可还原的挂载或尚未完成的恢复记录。仅剩已还原成员的旧副本时，显示旧副本处理。

## Alternatives considered

- 继续调大递归查询超时。它可容纳更多文件，但每次重试仍先遍历整个旧卷。
- 枚举所有打开文件后按路径前缀过滤。开销取决于打开的文件数，但改名后的句柄与路径别名需要额外判断。旧副本有专用卷，可以直接按文件系统匹配。
- 直接使用目录扫描结果打开详情可以省去读账本，但扫描期间旧副本可能已由后台清理，扫描结果也没有弹窗需要的完整记录。
- 仅在写入删除检查点后保存失败原因可沿用清理阶段的记录更新，但离线与卷身份检查通常先于该检查点。把原因写进同一次重试元数据更新，详情在这两种阶段都可显示。

## Consequences

专用旧卷的占用检查不再随旧目录的文件数增长。当前本地目录仍需检查写入进程并同步，旧卷仍需完整校验。卷检查的超时或错误会阻止自动清理，保留已还原数据和旧副本。
