# Agent Note: 启动入口只转发系统请求，等待真实启动结果再退出

Status: implemented

## Problem

迁移后的本地启动入口需要把打开应用、文件和 URL 请求交给外盘应用。启动子进程后立即退出无法确认转发结果，而完整 AppKit 启动会引入本地入口不需要的文档和窗口恢复过程。

## Decision

目标缺失时的映像接回行为由[启动迁移应用时静默接回映像](../feature/2026-11-03-启动迁移应用时静默接回映像.md)部分扩展，先准备映像和关联数据，再沿用本篇的启动转发与退出规则。

`StubLauncherSource.swift` 注册打开、重开、文件及 URL 的 Apple Event 处理器，用 Carbon 事件循环分发请求，不运行 `NSApplication.run()`。直接执行入口时在下一次主循环执行启动兜底；初始和重开事件与兜底共用已收到请求标记，避免重复启动。

转发调用 `NSWorkspace` 的打开应用或带 URL 打开接口，保留所有待完成请求计数；结果回调返回且计数归零后才结束事件循环。外盘目标缺失和系统启动失败显示错误；无效事件参数返回 Apple Event 错误。启动耗时日志记录在独立 launcher 子系统，不把请求发出等同于应用成功打开。

## Related decisions and history audit

- 数据迁移期间的转发前检查与共享锁生命周期见[启动入口保护](../feature/2026-10-24-portal-data-migration-launch-protection.md)，沿用本篇等待真实启动结果的事件循环。
- 与[持久化迁移生命周期](../architecture/2026-10-10-verified-transfer-lifecycle.md)部分重叠：入口仍指向迁移的有效位置，本篇只约束启动请求转发，不证明复制或清理完成。
- 与[应用数据身份解析](2026-09-29-app-data-identity.md)部分重叠：本地入口与外盘真实应用仍是不同角色，转发成功不能代替真实包身份核验。

## Alternatives considered

- **用 open 子进程转发后立即退出**：实现少且使用系统工具，但未等待实际打开结果，失败无法可靠反馈。
- **用完整 NSApplication 生命周期接收事件**：直接使用 AppKit 委托，但入口会承担无关的文档和窗口恢复；使用最小事件循环并由真实应用持有界面。

## Consequences

入口可等待转发完成并反馈系统错误，真实应用负责自身窗口与文档恢复。代价是维护 Apple Event 分发、兜底和退出条件；不同系统及文件关联行为仍需真实启动验证。交付需保持 `AppPorts/StubLauncherBinary` 与源码同步，不能仅更新源码。

## Verification

分支同时更新启动器源码、构建脚本和内嵌二进制，`PortalPresentationTests.swift` 与 `LaunchReadinessCheckerTests.swift` 包含相关入口断言。此次仅核对代码与变更范围，未重编译启动器或执行真实文件、URL 打开流程。
