# Agent Note: 按所选映像使用应用库卷

Status: implemented

## Problem

打开或重新挂载所选映像时，服务要求映像只有一个可写 APFS 卷，并拒绝尚无保存 UUID 的已有未挂载附件。多卷映像和系统已附加的映像因此无法使用。设备枚举还只识别 Apple_APFS 内容标记，遗漏系统使用的 APFS 分区 GUID；APFS 清单缺少 MountPoint 时，也会遗漏实际已挂载的卷。

## Decision

卷搜索限定在用户所选映像关联的设备中。已有记录按保存的卷 UUID 定位；首次使用时优先采用应用库挂载路径对应的可写卷，否则按设备自然顺序使用首个可写 APFS 卷，并保存 UUID，后续恢复沿用该卷。其他可写卷的存在不阻止使用。已有未挂载附件直接挂载，不重复附加，不卸载其他进程已有的附件。

APFS 物理存储同时识别 Apple_APFS 和分区 GUID，通过 PhysicalStores 找映像内的卷。当前挂载位置从 diskutil info 读取，清单未提供 MountPoint 不代表没有挂载。最终检查只核对本轮所用卷的 UUID、挂载位置和可写属性，其他卷不参与目标判定。

未挂载卷使用 WritableMedia 判断是否可以尝试挂载；系统在未挂载状态下返回 WritableVolume=false，不能据此拒绝挂载。挂载完成后仍要求目标卷 WritableVolume=true。其他卷可以挂载在沙盒数据目录，验证时先按目标 UUID 筛选，再检查应用库路径，不能让非目标卷的位置阻断应用库。

挂载使用 diskutil mount 让系统创建正常挂载目录，不传要求目录预先存在的 -mountPoint。首次使用记录实际挂载路径；已有应用库要求挂载后的路径与保存路径一致，避免已迁移应用入口失效。核对失败日志记录判断位置，便于区分失败分支。

## Alternatives considered

- 要求唯一可写卷可以简化定位，但映像包含其他卷不代表所选目标不可用，保存选中卷的 UUID 足以支持后续定位。
- 多卷时增加一次选择弹窗可提供细粒度控制，但当前操作对象是映像，采用固定优先级并保存结果可以直接完成打开操作；需要切换同一映像内部卷时再提供明确的卷选择入口。
- 预先创建自定义 /Volumes 挂载目录可以继续传 -mountPoint，但需要管理系统目录写权限及失败后的目录清理；使用系统正常挂载流程可避免这两项额外职责，挂载后仍验证已保存路径。
- 沿用 main 在附加时指定挂载点，把卷名与保存路径不一致的旧记录重新附加到原路径，可以保住旧入口；但只适用于单卷映像，还要先卸下已核对身份的附加再重新附加，属于挂载策略变更。已发布的 2.1.0 不含应用库映像，没有需要兼容的用户记录，因此不采用。
- 挂载前按卷名推算系统挂载路径并提前拒绝，可以避免把卷留在错误路径，也不会记录带序号的路径；但只改善失败方式，仍不能挂回原路径，本次不实现。

## Consequences

首次打开多卷映像会使用上述优先级对应的卷，暂不提供内部卷切换界面。已有记录 UUID 不匹配时仍失败，不悄悄换成另一个卷。清单缺少挂载路径时增加只读设备查询。失败不删除映像；存储离线、挂载位置占用和真实只读卷仍可能导致操作失败。

系统按卷名选择挂载目录，应用库路径因此依赖卷名。按映像文件名固定挂载的旧记录只存在于使用 main 构建的测试环境；AppPorts 创建的映像卷名与文件名相同，不受影响。以下情况挂载后的路径核对会失败：在 Finder 中改了卷名；或首次打开卷名与文件名不同的映像时，`/Volumes/<卷名>` 已被占用，记录下了带序号的路径。失败时记录不变、映像保留，把卷名改回与保存路径一致即可恢复。映像原本已由其他进程附加时，卷可能留在系统选择的位置，需要在 Finder 中检查。

## Verification

更新隔离回归用例，覆盖已有未挂载附件无保存 UUID 时挂载、APFS 两种内容标记、清单缺少 MountPoint，以及多可写卷时沿用保存 UUID 和 UUID 被替换时拒绝。夹具按真实系统数据返回未挂载时 WritableMedia=true / WritableVolume=false，并将同映像非目标卷挂在 /Volumes 之外；挂载参数断言采用系统默认挂载。

真实 SMB 映像附加后，只读查询确认目标卷 UUID 与保存记录一致，未挂载状态的 WritableVolume=false。系统执行自定义挂载返回 Mountpoint /Volumes/AppPorts does not exist，随后改用 diskutil mount 成功；目标卷保留挂载，不卸载同映像已由后台代理挂载的数据卷。此证据验证系统操作及设备字段，不代表修改后的完整应用流程已通过。修改文件执行 Swift 静态语法检查及笔记门禁，不构建或安装应用，不执行测试套件。
