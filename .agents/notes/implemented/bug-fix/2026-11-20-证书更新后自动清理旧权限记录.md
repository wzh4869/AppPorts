# Agent Note: 证书更新后自动清理旧权限记录

Status: implemented

## Problem

GitHub 上发布的 2.2.0 与 2.3.0 均使用 `Apple Development` 证书签名；2.2.0 使用的旧证书（序列号 `128644ABEF9F79816183F98C03EEFF8F`）于 2026-11-17 过期，2.3.0 使用 2026-11-18 新签发的证书（序列号 `7BDD2FD3969A84FFE47B6B7FA8D4FF35`）。同时 2.3.0 新增了基于当前运行进程签名的 `TCCAccessPreflight` 检查（`kTCCServiceSystemPolicyAppBundles`）。

老用户从 2.2.0 升级到 2.3.0 后，macOS 系统设置「App 管理」（以及部分环境下的「完全磁盘访问权限」）仍按 Bundle ID 展示旧证书留下的已开启条目，但 `tccd` 校验 `csreq` 不匹配当前新版进程，导致 AppPorts 持续提示缺少权限；用户即便进入系统设置反复开关旧条目也无法刷新底层 `csreq`，必须手动点 `-` 删除旧条目再拖入新版重新开启，困惑成本很高。

## Decision

新增 `LegacyPermissionResetter`（`AppPorts/Services/LegacyPermissionResetter.swift`），与 `ContentView`、`ReadinessCheckView` 配合，以「精准清理失效旧记录 + 弹窗引导重新授权 + 手动兜底清理」解决证书变更后的 TCC 残留问题：

1. **启动自动清理边界（仅针对已生效过旧版且当前失效的正式副本）**：
   - 仅在同时满足以下条件时执行：已完成欢迎引导（`WelcomeView.completionDefaultsKey == true`）、Bundle ID 为 `com.shimoko.AppPorts`、位于允许的应用程序目录（`AppInstallationLocation.isAllowed()`）、读取到当前应用签名指纹（优先叶子证书 SHA-256 `cert:<hex>`，无证书时回退 `cdhash:<hex>`），且该指纹尚未处理过（记入 `UserDefaults` 的 `LegacyPermissionResetter.handledSigningIdentity`）。
   - 仅纳入实际失效的权限：`AppManagementPermission.state() != .granted` 时纳入 `SystemPolicyAppBundles`；`LaunchReadinessChecker.fullDiskAccessState() == .denied` 时纳入 `SystemPolicyAllFiles`（`fullDiskAccessState == .unknown` 不纳入，避免因 I/O 异常误清）。
   - 若两项权限均已 `.granted`，只静默记录当前签名指纹，绝不调用 `tccutil` 也不弹窗；若仅单项失效，只重置失效项，绝不触碰已授权的另一项。
   - 启动自动清理一律免管理员密码，通过 `/bin/sh` 包装调用 `/usr/bin/tccutil reset <service> com.shimoko.AppPorts`。

2. **防 `SIGKILL` 闪退与防死循环保护**：
   - 调用 `tccutil reset` 前先持久化已处理签名指纹与待展示弹窗状态（`LegacyPermissionResetter.pendingPrompt`）。
   - 外置非提权脚本开启 `trap '' HUP PIPE`；若 `tccd` 在删除活动记录时终止了原 `AppPorts` 进程，脚本检测到原 PID 退出后自动以普通用户身份 `open -n` 重拉起同一应用包，新启动的进程读取 `pendingPrompt` 复核仍缺失的权限并立即补出提示，且不会重复执行 `tccutil`。若原进程存活则直接清除 `pendingPrompt` 并弹窗。

3. **弹窗引导与手动兜底清理**：
   - `ContentView` 使用统一的 `WarningSheetRequest` 展示「需要重新授予系统权限」弹窗：仅缺单项时主按钮直达对应系统设置子页并复用 `FullDiskAccessGuide` 悬浮拖拽引导；两项同时缺失时主按钮打开 `ReadinessCheckSheet`，集中展示两项实时状态与设置入口。
   - `ReadinessCheckView` 在存在未授权权限（App 管理非 `.ok` 或 FDA 为 `.failed`）时展示「清理旧版授权记录」入口：点击后对 `SystemPolicyAppBundles` 免提权清理，对位于系统域 TCC 的 `SystemPolicyAllFiles` 通过 `DiskUtility.runWithAdministratorPrivileges` 请求一次管理员授权执行 `/usr/bin/tccutil reset SystemPolicyAllFiles com.shimoko.AppPorts`（绝不以 `root` 身份 `open` 应用），取消管理员弹窗按 `CancellationError` 静默恢复。
   - 新增 15 条界面文案同步补齐 `Localizable.xcstrings` 的全部 22 种支持语言（`extractionState: manual`）。

## Alternatives considered

### 1. 使用 2.2.0 旧证书重签 2.3.x 避免 TCC 失效

使用满足 2.2.0 既有 `csreq` 的证书重签可以实现零用户操作兼容。但核查 GitHub 发布包确认 2.2.0 所用 `Apple Development` 证书已于 2026-11-17 过期，无法继续签发新构建；且未来更换为 `Developer ID Application` 或续签证书时同样可能面临一次切换，因此必须在客户端侧建立可复用的旧记录清理与重新授权引导。

### 2. 启动自动清理时直接对 FDA 弹管理员授权框

在启动阶段直接用 `DiskUtility.runWithAdministratorPrivileges` 重置 `SystemPolicyAllFiles` 可以一步清理系统域旧条目。但未等用户知情就在刚打开应用时弹出系统密码框过于突兀，且无法事先区分“系统域存在旧证书残留”与“用户本来就未授予 FDA”。因此启动阶段坚持免提权清理 + 清晰弹窗，把系统域 FDA 的提权清理放到准备情况页的用户主动操作中。

### 3. 仅改文案提示用户手工在系统设置点 `-` 删除旧条目

只修改文案改动最小且零子进程调用，但用户仍需手动定位旧条目、点 `-` 删除并重新拖入，且容易在看到“开关已开”时忽略删除步骤。先通过苹果官方 `tccutil reset` 自动清理失效旧记录再弹窗进设置，显著降低老用户升级阻力，同时在文案中保留手动 `-` 删除作为最终兜底。

## Consequences

- **收益**：
  - 老用户因证书续签/切换导致 App 管理或 FDA 失效时，升级打开新版后自动清理旧记录并弹出清晰指引，不再面对“设置里开关开着却持续报红”的假象；
  - 同一证书指纹最多自动处理一次，已正常授权的老用户与首次使用欢迎屏的新用户完全零打扰；
  - 未来 2027-11-18 证书再次续签或切换正式分发证书时，同一机制可自动按新证书指纹生效。
- **代价与已知边界**：
  - macOS 安全边界决定了应用无法静默授予自身权限，清理后仍需用户在系统设置中完成一次拖入/开启操作；
  - `SystemPolicyAllFiles`（完全磁盘访问权限）位于系统域 `/Library/Application Support/com.apple.TCC/TCC.db`，部分 macOS 版本上启动阶段的免提权 `tccutil reset` 可能无法删除系统域旧条目，届时需要用户点击准备情况页的「清理旧版授权记录」并确认一次管理员授权，或在系统设置中手动点 `-` 删除；
  - 若 `tccd` 在执行管理员清理 FDA 时终止 AppPorts，为避免以 `root` 启动 GUI 进程，不会自动重拉起，待用户重新打开后通过 `pendingPrompt` 继续展示引导。
