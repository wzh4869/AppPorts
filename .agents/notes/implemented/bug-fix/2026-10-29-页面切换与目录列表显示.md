# Agent Note: 页面切换直接显示内容，同上下文刷新保留目录列表

Status: implemented

## Problem

用户反馈标签页切换迟缓，目录迁移页的原生整行蓝色选中效果也与应用页不同。代码中整页透明度和位移弹簧动画需要对大列表持续合成，AppPageVisibility 还通过额外 State 更新可见性；应用数据页在异步查询缓存前清空列表，即使命中缓存也会先显示空白。此为静态识别的额外渲染和列表刷新成本，尚无帧率或耗时测量，不能断言覆盖全部卡顿来源。

## Decision

`AppPageVisibility` 直接由 isActive 控制透明度、层级、点击与辅助功能可见性，取消中间可见性 State、整页淡入与位移动画，继续保留已访问页面。工具目录与应用数据的内部切换也停止整页 transition；顶部导航标签使用 plain 按钮样式，选中背景直接更新，不使用按压缩放或匹配几何滑动动画，仅保留悬停反馈。标准 Button 的点击、键盘及辅助功能行为保持不变。页面隐藏仍取消扫描并更新 token，不通过销毁页面清理迁移状态。

`DataDirsView` 保存已展示快照的 Context。刷新开始时，仅当应用、目标盘、拆分设置和记录版本一致才保留现有列表，异步权限探测及缓存查询继续执行。Context 改变立即清空旧列表；权限拒绝或未知时清空列表和缓存。扫描结果仍受 token 与记录版本保护，迁移确认仍绕过缓存并重新扫描。保留显示不授予旧数据执行权限，也不省略权限探测。

目录迁移页复用应用页的面板、列布局、行背景、悬停和菜单样式。原 AppRowView 私有的原生选中抑制器移至已有共享组件文件，两个列表共同使用；保留原生 List 的键盘、多选与 tag 身份。名称、路径、状态保持可见，大小单独对齐，菜单复用原有 Finder、断开链接与移除记录回调，不改迁移服务或记录格式。

## Alternatives considered

缩短整页弹簧时间：保留原有动效，但仍要在切换时合成大列表，不能消除额外可见性 State 更新；选择内容立即切换并保留局部按钮反馈。

每次返回页面销毁并重建内容：减少隐藏视图，但会丢失选择、滚动和操作提示，重新触发首屏构建；继续保留页面。

跳过权限探测直接显示缓存：返回更快，但权限被收回后会继续使用旧授权判断；保持异步权限检查，失败时立即清空展示。

## Consequences

页面可见性少一轮 State 更新及整页动画；缓存命中的同上下文列表不先清空，目录迁移视觉沿用应用页。代价是去除整页淡入后切换更直接，保留页面仍占内存，相同上下文在刷新过程中短暂展示旧结果。该结果仅作展示，执行前仍重新核对。

此修复不证明磁盘扫描、系统权限探测或超大列表首次布局已足够快；如实际新版仍卡顿，需要按真实操作测量主线程和扫描耗时，不能以移除动画替代性能验证。
