# Agent Note: 强制解绑释放旧软链记录

Status: implemented

## Problem

`.bun` 等工具目录已经是外部软链，但仍有旧迁移记录占用原路径。强制解绑复用普通迁移的无重叠检查，导致用户确认舍弃本地关联后仍被“已有迁移或保留副本重叠”挡住。

## Decision

本决定取代[现有软链强制解绑](../feature/2026-10-26-现有软链强制解绑.md)中“旧迁移记录必须先走原恢复流程”的限制，其余路径策略、软链身份检查及替换机制继续适用。

强制解绑只允许接续 `originalPath` 与当前路径完全一致的软链迁移记录和管理索引。普通重叠检查为这些明确的记录提供现有所有权豁免；祖先、子目录、挂载迁移和其他路径的记录仍阻止操作。保存时还拒绝记录快照变化、其他任务引用待结束任务，以及其他路径共用其操作标识的情况，避免释放仍被别处使用的记录。

`ContainerMountStore.detachSymlinkHistory` 在写入锁内重新核对记录快照与本地软链身份，将关联迁移记录转为现有 `preservedMaterials`，再移除其活动迁移记录和管理索引。只有索引的情况保存外部位置摘要。原记录、目标路径和旧副本位置保留，不标记为已删除。软链历史材料不参与挂载材料的自动清理，也不预留原路径，因此空目录可以重新使用或迁移。

先保存结束旧关联的决定，再执行本地条目替换，避免入口已改为空目录而活动记录仍授权旧恢复流程处理该路径。保存失败时不修改软链；后续替换失败时仍保留旧软链或原有回滚材料，但已经结束的活动记录和管理索引不会自动恢复。历史记录已结束的情况下可以再次尝试解绑。外部目标无需在线，过程中不读取或改写其数据。

## Alternatives considered

- 只跳过冲突检查：能完成一次解绑，但旧记录仍占用路径，后续迁移继续失败，旧恢复流程也可能重用已经失效的关联。
- 删除旧迁移记录：可以释放路径，但会丢失原目标与副本位置。复用保留副本机制同时释放路径并保存这些事实。
- 新增迁移状态与存储版本：可以表达已解绑状态，但现有保留副本已经支持不占用路径的历史材料，没有必要扩大持久化格式。

## Consequences

用户确认强制解绑也意味着结束该路径的旧软链迁移任务。旧副本仍保留在原位置，不会自动清空或自动回迁。来自其他目录或挂载迁移的冲突继续报错。

持久化与文件系统替换是两个独立步骤，不具有共同回滚。保存成功而替换失败时，用户需要根据错误中保留的位置重试或处理材料，不能仅凭活动记录消失认定解绑完成。保留摘要增加历史材料的维护成本；它保留位置和恢复事实，不证明外部副本仍在线或完整。

## Verification

`AppPortsTests/ExistingLinkResetTests.swift` 包含七项测试：四项基础路径保护测试，以及旧迁移记录释放并保留外部和备份数据、离线管理索引释放、祖先目录迁移冲突拦截三项测试。断言同时检查本地目录、记录释放及副本保留，避免仅凭界面任务成功判断结果。

实现时的验证记录为七项定向测试及笔记格式、目录和相对链接校验通过。测试使用临时目录，未对用户实际的 `.bun` 执行解绑。当前测试未注入持久化失败、保存后的替换失败或记录快照并发变化；这些失败路径的恢复行为仍缺少自动化验证。
