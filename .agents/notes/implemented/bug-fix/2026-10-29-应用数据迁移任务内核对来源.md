# Agent Note: 应用数据来源刷新属于迁移任务的准备阶段

Status: implemented

## Problem

应用数据列表复用展示快照，但执行必须以当前来源为准。旧入口在打开迁移确认前清空缓存并异步扫描，任务尚未建立时页面就进入等待；若用户随后取消确认，这轮扫描也没有执行用途。确认与任务排队期间来源仍可能变化，因此提前刷新不能代替执行时核对。

## Decision

`askMigrate` 和 `askMountMigrate` 直接使用展示项进入原有模式选择、目标检查与确认，不触发目录重扫。确认中的大小仍是估算。新迁移任务取得资源与操作锁、应用启动保护并核对应用已退出后，在原有 preparing 阶段调用 `AppDataMigrationPreparation`；没有新增面板、进度阶段或文案。

前置流程从提交时捕获的应用、外部根、微信拆分设置与容器身份重新发现目录，按原始标准化路径选中当前项，要求身份判断成功、可迁移且仍为本地状态。拆分成员集合必须与提交时一致，不能扩张已预留资源。只对所选目录或聚合媒体强制重新测量大小，读取不完整则停止；实际复制使用新项，不使用旧快照的大小和状态。普通数据、挂载及微信拆分的新迁移均接入，工具目录继续沿用其原有执行核对。

权限检查、扫描与测量在独立工作任务执行，捕获迁移控制以支持检查点；取消向工作任务传递，结果发布前再次检查取消。任务前置扫描不依赖页面激活或列表刷新 token，页面切换不会取消已提交的迁移。列表仍可使用自己的展示快照，任务完成后沿用原刷新入口更新列表。

APFS 已失败尝试的 retryToken 分支和还原不重新运行“新迁移来源必须本地”的前置流程，而继续使用现有持久化恢复与执行安全检查；它们可能已经切换入口或完成一个拆分成员，不应被误当作全新的本地来源。

## Alternatives considered

保留确认前刷新：能在确认时显示较新的大小，但造成任务之外的等待，仍不能消除确认到执行之间的状态变化。

只依赖缓存进入复制：响应直接，却会把旧可迁移资格和大小带入新执行；选择在任务开始后重新发现并强制测量。

重测所有关联目录：与旧页面扫描行为接近，但未选择的缓存和媒体也产生额外遍历；保留发现的完整来源判断，只重测实际所选目录。

把前置扫描绑定页面任务：可复用原 scanLibraryDirs 回调，却会被页面隐藏或切换应用时的取消机制中止；执行前置流程由迁移任务独立持有。

## Consequences

点击迁移不再触发页面重扫，等待进入已有任务面板的准备阶段；来源变更、权限不足或大小不完整均在复制前失败。代价是确认显示的估算大小可能陈旧，任务准备仍有扫描成本，发现结果不会单独回填浏览缓存。目标容量、来源身份与目录切换继续由底层迁移服务在执行时复核，不能把准备结果当作锁外永久授权。

## Verification

`AppDataMigrationPreparationTests` 覆盖返回新元数据与大小、仅测所选路径、来源消失/保护/迁移后拒绝、拆分成员变化拒绝，以及读取不完整拒绝。本批仅做相关 Swift parser 静态检查和笔记门禁，未构建、执行测试、安装或进行真实迁移；面板打开时机、准备阶段取消和切页后继续需在修改版确认。
