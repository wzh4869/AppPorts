# Agent Note: 过滤运行时伪软链并守卫规范化管理

Status: implemented

## Problem

Chromium 与 Electron 系应用在 `~/Library/Application Support/<App>/` 下通过符号链接原子性存储运行版本号与实例锁（例如 `RunningChromeVersion -> 157.0.4341.60:1`、`SingletonLock -> <host>-<pid>`），目标字符串在磁盘上不存在对应目录。应用数据扫描将其识别为名称匹配的「现有软链」并放进目录列表，不仅造成列表噪音与破坏性「强制解绑」误操作风险，用户点击「规范化管理」时也会被底层目录存在性检查拦截并报错「外部存储目录不存在」。

## Decision

- **在应用数据扫描中过滤运行时伪软链（`DataDirScanner.swift`）**：`DataDirScanner.isRuntimeMetadataSymlink(at:)` 仅作用于未被当前 `recoveryInspection?.managedLinks` 登记为受管链接的符号链接：凡文件名命中 `ignoredRuntimeMetadataSymlinkNames`（`RunningChromeVersion`、`SingletonLock`、`SingletonCookie`、`SingletonSocket`），或目标字符串为不含路径分隔符 `/` 的单段非路径名且解析后 `lstat` 不存在时，均判定为运行时元数据伪软链并从 `indexTwoLevels`（批量列表计划）、`findMatchingDirs`（单应用搜索）与 `scanContainerStructure`（容器子目录浏览）中跳过；指向 `/Volumes/...`、`../...` 等含路径分隔符 `/` 的断开外置软链以及本地已有兄弟目录链接保持可见。`scanSignatureDependencies` 的签名依赖检测保持独立且不引入该过滤。
- **「规范化管理」目标存在性前置校验与按钮禁用（`DataDirMover.swift`、`WarningSheet.swift`、`DataDirsView.swift`）**：
  - `DataDirMover.canNormalizeExistingLinkTarget(_:)` 使用 `lstat` 验证软链目标路径当前必须是真实存在的目录（`S_IFDIR`），排除缺失路径、普通文件或嵌套软链。
  - `WarningAction` 增加可选 `isDisabled`（默认为 `false`），在 `WarningSheet.button(for:)` 中同时结合 `requiresAcknowledgement` 控制按钮可用态。
  - `DataDirsView.askManageExistingLink(_:)` 对非真实目录目标的「现有软链」禁用「规范化管理」按钮，并在弹窗中通过复用既有全语言词条 `"外部存储目录不存在：%@".localized` 展示警示说明；「强制解绑」在勾选确认后仍可用，使外置盘暂未连接或人为损坏路径软链仍保留显式解绑退路。

## Existing-note audit

- 与[应用数据发现限制层级并响应取消](2026-10-26-应用数据发现限制层级并响应取消.md)互链：延续「两层列举、先 `lstat` 再过滤无关文件系统节点、保留路径错误诊断边界」的发现策略，在 `S_IFLNK` 分支追加运行时伪软链过滤，不改动受管记录匹配或外部路径断链的恢复边界。
- 与[现有软链强制解绑](../feature/2026-10-26-现有软链强制解绑.md)互链：维持“强制解绑不要求目标在线、原路径重建空目录并保留外部副本”的设计不变，同时阻止不满足目录前置条件的目标误触发「规范化管理」。
- 与[应用数据左侧列表展示大小与分组排序](../feature/2026-11-19-应用数据列表大小展示与排序.md)协调：`indexTwoLevels` 与 `findMatchingDirs` 共享同一套伪软链过滤，使左侧批量汇总与右侧详情扫描看到的候选集合一致。
- 与[过滤微信容器内沙盒系统软链并禁止还原](2026-11-20-过滤微信容器内沙盒系统软链并禁止还原.md)互链：本篇过滤无 `/` 的运行时状态标记伪软链，后者过滤并拦截容器内指向 `~/Library/*` 的 macOS 沙盒系统入口软链。

## Alternatives considered

### 为什么不过滤全部悬空软链，而仅过滤特定命名及无 `/` 的单段悬空目标

一律忽略所有 `lstat` 目标不存在的悬空软链实现更简单，且可以消掉所有无法「规范化管理」的链接。但用户手动迁移到离线外置盘后未挂载（如 `-> /Volumes/External/...`）或相对路径外置链接在断开期间同样呈现为悬空软链；若将其从扫描器隐藏，用户将失去在「链接详情」中使用[现有软链强制解绑](../feature/2026-10-26-现有软链强制解绑.md)重置本地入口的途径。因此保留带 `/` 路径分隔符的真实路径软链，仅过滤明确运行时锁名及单段非路径名标记。

### 为什么不只在点击弹窗时禁用「规范化管理」，而同时在扫描阶段过滤

只在 UI 弹窗禁用按钮改动最少、不触碰扫描器逻辑。但如果不从候选发现中剔除 `RunningChromeVersion` 等条目，Edge、Chrome 或 Electron 应用数据列表下仍会持续展示多个「现有软链」，且用户勾选确认后仍可能点中「强制解绑」，把 Chromium 用软链保存的版本号/进程锁替换成空目录，干扰浏览器自身实例锁或升级检测；因此从扫描层消除噪音并以弹窗禁用兜底其它非目录目标。

## Consequences

- **收益**：Chromium / Electron 应用数据目录扫描直接跳过 `RunningChromeVersion`、`SingletonLock`、`SingletonCookie`、`SingletonSocket` 等运行时状态标记，列表不产生伪「现有软链」误导；对于目标缺失、指向普通文件或嵌套软链的非受管链接，弹窗明确给出缺失路径说明并禁用「规范化管理」，减少无意义的失败任务。
- **代价与已知边界**：过滤规则假设真实的数据目录迁移软链总包含 `/`（绝对路径或带目录层的相对路径），若存在手工建立的单段同级目录名称悬空软链且未被 `ManagedDataLinkRecord` 索引，则会被当作运行时标记过滤。
