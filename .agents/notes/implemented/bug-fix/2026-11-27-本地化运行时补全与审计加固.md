# Agent Note: 本地化运行时补全、复数支持与审计守卫加固

Status: implemented

## Problem

在[本地化覆盖与英文占位守卫](../testing/2026-10-23-本地化覆盖与英文占位守卫.md)将字符串目录补齐到 22 语 100% 填充后，现有 19 项审计仍放过了一批影响真实非中文用户的运行时与译文缺陷：

- `INFOPLIST_KEY_NSAppleEventsUsageDescription` 硬编码简体中文且没有 `InfoPlist.xcstrings`，非中文系统弹出 Finder 自动化权限提示时仍显示中文。
- 主窗口与关于窗口只注入 `.environment(\.locale, ...)` 而未注入 `.environment(\.layoutDirection, ...)`，非阿拉伯语系统热切到 `ar` 时界面不会翻转为 RTL。
- 盲文沿用语言代码 `br`（ISO 639-1 对应布列塔尼语），导致 `LocalizedByteCountFormatter` 与数字/日期格式化输出布列塔尼语（`623 okted`、`1,5 Go`），且目录中 12 条新增文案被错译为布列塔尼语而非 Unicode 盲文。
- 既有审计只做区分大小写的精确 `value == english` 比对与 `.sorted()` 占位符比对，导致 15 语中 3 条不同迁移限制提示被复制成同一译文、`ar`/`hi`/`th` 出现拉丁罗马音转写、14–16 语残留 `No local apps found` / `Interface Speed` / `npm cache`、繁中残留 14 处简体字、5 处 `AppPorts` 误拼为 `AppPort`，且潜在的参数顺序错位崩溃无法被拦住。
- 全部 18 个计数型 UI 文案未配置复数规则（英文出现 `1 apps`），多处视图硬编码中文全角冒号 `：`、顿号 `、` 及 `hasPrefix("正在")` 前缀裁剪，且 `UpdateChecker` 在目标语言缺少更新日志时优先回退 `zh-Hans` 而非 `en`。

## Decision

**补齐系统层与运行时本地化边界。** 在 `AppPorts/` 新增 `InfoPlist.xcstrings`（由 Xcode Synchronized Root Group 自动编译进 22 个 `.lproj/InfoPlist.strings`），覆盖 `NSAppleEventsUsageDescription` 全部 22 语。`LanguageManager` 新增 `layoutDirection`（使用 macOS 12 兼容的 `Locale.characterDirection(forLanguage:)`）、`formattingLocale` 与 `pluralLocale`：主窗口（`Appports.swift`）和关于窗口（`AboutView.swift`）同步注入 `.environment(\.layoutDirection, languageManager.layoutDirection)`；`br` 的格式化与复数 locale 映射为 `en`、`zh-martian` 映射为 `zh-Hans`，`LocalizedByteCountFormatter` 与视图数字/百分比/时间格式化统一使用 `formattingLocale`。`AboutWindowController.windowTitle()` 同时剥离 `...`、`…` 和盲文 `⠲⠲⠲`，关于页链接标签改用 `PreferenceKey` 自适应最小宽度。

**为热切换语言提供 `.stringsdict` 复数支持。** `String` 新增 `localizedFormat(_:)`，按当前选中语言的 `.lproj` 读取模板并以 `LanguageManager.pluralLocale` 调用 `String(format:locale:arguments:)`，确保应用内切换语言时编译生成的 `.stringsdict` 复数规则生效（包括 `ru`/`pl`/`ar` 多复数形态与 `br` 英文单复数规则）。单占位计数 key 使用 `variations.plural`，多占位计数 key（`%@ (%lld 个应用)` 与两条 macOS 27 签名提醒）使用 `substitutions` + `variations.plural`。

**消除代码层中文标点、前缀与不一致回退。** 冒号拼接改为完整格式化 key（`开始：%@`、`处理时间：%@`、`当前应用：%@`、`当前目录：%@`）；顿号拼接改为 `Sequence.localizedListJoined`，通过语义 key `list.separator` 读取各语言分隔符（中文/日语 `、`、阿语 `، `、盲文 `⠂ `、其余 `, `），避免 Xcode 26 `GenerateStringSymbols` 因纯标点 key 无法生成 Swift 符号而编译失败。新提交的后台任务统一使用非进行态标题（如 `迁移应用`、`迁移「%@」`），`MigrationTaskCenter.displayTitle` 保留去 `"正在"` 逻辑仅用于兼容已落盘的历史中文记录。`UpdateChecker` 改为中文变体（`zh-Hant`/`zh-martian` 等）先回退 `zh-Hans`，其余非中文语言优先回退 `en` 再回退 `zh-Hans`，与 `DocumentationLink` 及 `PortalLocalizedStrings` 保持一致。

**全量修补译文、清理 75 条死/日志 key，并加固 10 项审计守卫。** 修复 15 语 3-key 错贴、12 条布列塔尼语混入 + 1 条部分 ASCII 盲文、6 条罗马音、3 组英文残留、5 处 `AppPort` 拼写与 `zh-Hant` 简体字及术语混用（`Finder`、`本機`、`外接`、`資料`、`檔案系統`）；清理 27 个无任何源码/测试引用的废弃 key 与 48 个仅出现在非 `.localized` 日志调用中的 key（总 key 数由 1,409 降至 1,352），并重新运行 `script/generate_portal_strings.py`。`LocalizationAuditTests` 升级占位符校验为按参数索引与类型精确核对并递归检查 `variations`/`substitutions`，补充 `InfoPlist.xcstrings` 覆盖、盲文脚本、非拉丁目标脚本、繁中 `Hans-Hant` 简体泄漏、多语共享 ASCII 残留、不同长文案重复译文、品牌名拼写，以及 RTL / `formattingLocale` / 复数格式化 / 列表分隔运行时回归。

## Alternatives considered

### 为什么不把盲文语言代码 `br` 改为私有标签（如 `en-x-braille`）？
改用私有语言标签能从根源避免与 ISO 639-1 布列塔尼语冲突，无需额外维护 `formattingLocale` 映射。但现有用户的 `UserDefaults`（`selectedLanguage`）、`project.pbxproj` 的 `knownRegions`、`PortalLocalizedStrings` 以及第三方/旧版偏好迁移都会受影响；保留 `br` 并通过 `formattingLocale`/`pluralLocale` 隔离 Foundation 格式化，再用审计测试锁定 `br` 必须为 Unicode 盲文，迁移成本最低且零兼容破坏。

### 为什么不把全库 `.localized` 全面迁移到 `String(localized:)`？
`String(localized:)` 是 Swift 现代标准接口，原生支持 String Catalog 复数。但 AppPorts 需要在应用内热切换语言（脱离系统语言），且全库已有近千处 `.localized` 与 `LocalizationAuditTests` 静态扫描约定；在 `LanguageManager` 增加轻量 `String.localizedFormat(_:)` 直接绑定目标 `.lproj` 与 `pluralLocale`，改动局部可控且能直接触发 `.stringsdict`。

### 为什么列表分隔符不直接用 `"、"` 作为 catalog key？
沿用中文源文案作 key 最直观，但 Xcode 26 开启 `GenerateStringSymbols` 后会拒绝纯标点 key（`Unable to derive a symbol name from this key`），导致整个 target 编译失败。改用语义 key `list.separator` 既通过符号生成，又保持单一译文源。

### 为什么不保留 `UpdateChecker` 对非中文语言先回退 `zh-Hans` 的旧行为？
旧行为已由单测固定，不改可零测试改动；但与文档站链接和独立启动器统一回退英文的策略不一致，会使德/法/日等用户在缺译时看到中文更新日志。改为中文变体先回退 `zh-Hans`、其余语种先回退 `en`，兼顾繁中/火星文与国际用户体验。

## Consequences

- **收益**：系统权限弹窗、阿拉伯语 RTL 排版、盲文数值格式、22 语单复数语法、列表分隔与非中文更新日志回退全部闭环；词库减少 75 条无效 key（减少 1,650 条死翻译维护面）；审计测试从 19 项增至 29 项，堵住了大小写英文残留、罗马音、布列塔尼语混入、跨 key 错贴、繁中简体字与占位符换序崩溃盲区。
- **代价与限制**：
  - `LocalizationAuditTests` 维护了同形词、近义词对和繁中正异体白名单，新增文案命中边界时需要按测试提示审慎维护。
  - 若后续有新视图直接使用不带 `.locale(LanguageManager.shared.formattingLocale)` 的 SwiftUI 格式化器，在 `br` 下仍会退回布列塔尼语数字格式；新代码需继续遵守 `formattingLocale` 约定。
  - 历史已持久化的中文任务记录仍依赖 `MigrationTaskCenter.displayTitle` 剥离前导 `"正在"`。
  - 18 种 AI 翻译语言与复数变体仍属工程级翻译，未经过各语种母语审校。
