# Agent Note: 按操作检查安装位置与普通入口独立启动

Status: implemented

## Problem

映像启动准备把 AppPorts 当前可执行路径写入所有原生入口，普通物理盘应用因此也依赖那份 AppPorts。数据挂载迁移只排除临时目录，没有明确限定应用程序目录，映像操作没有相同入口检查。

## Decision

用户在本次对话确认：应用数据新迁移、创建、打开及手动重新挂载 APFS 应用库映像之前，要求 AppPorts 位于 /Applications 或当前用户的 ~/Applications。使用共用检查与原生提示，提供打开应用程序文件夹和取消；查看、扫描不弹窗。已有数据的迁回、恢复不新增安装位置门槛。自动恢复从不合适的位置启动时静默跳过，不反复弹窗。

原生入口只在应用本体或同一应用的受管数据需要映像时保存辅助程序路径。复用启动计划的关联判断，不另建索引。入口刷新比较准备元数据，覆盖后续迁移数据及恢复后解除依赖；沿用原有 staging、签名和替换流程。当前映像切换后保留入口已保存且仍对应真实应用路径的映像线索。需要辅助程序的入口只能由应用程序目录中的 AppPorts 生成，扫描调试版不能写入临时路径。

本次新增文案仅补齐简体中文和英文，这是用户明确选择；其他语言沿用现有本地化回退，补译留待后续，不复制英文伪装完成，不放宽审计。

## Alternatives considered

- 应用启动时强制安装位置可以统一限制，但用户仅查看或迁移普通应用时没有必要，用户选择按功能检查。
- 只检查数据迁移不改变入口依赖实现最小，但普通应用的入口仍可保存未经检查的程序路径，因此必须同时收窄准备元数据。
- 每次启动器自行解析完整数据账本可立即跟随记录变化，但会在独立启动器复制关联和兼容逻辑；复用原有扫描刷新和同一启动计划判断更直接。

## Consequences

数据新迁移和手动映像操作在不合适位置、发生副作用前停止；普通浏览及迁回不弹安装提示。普通物理盘且无映像数据的入口无辅助程序依赖；同应用数据在映像内时保留准备能力，其他应用记录不影响它。

后续数据迁移的入口更新依赖现有 recordsRevision、扫描及入口刷新，增加或去掉准备依赖；映像离线时不能刷新真实应用入口。本次不修复 PR 中其余三个映像问题，也不将构建通过视为真实 NAS 或权限链路验收。

新增提示的 3 个 key 是 `请先将 AppPorts 放入“应用程序”文件夹`、`请移动 AppPorts，并从“应用程序”文件夹重新打开后，再继续此操作。` 及 `打开应用程序文件夹`。只提供 zh-Hans、en，其他 20 种语言未翻译，沿用 String.localized 的系统语言回退；不保证固定回退为英文。后续补译这 3 项，不扩大到现有目录清理。
