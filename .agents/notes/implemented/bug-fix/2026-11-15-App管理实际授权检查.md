# Agent Note: App 管理实际授权检查

Status: implemented

## Problem

维护者截图中系统设置的 AppPorts App 管理开关开启，准备情况仍显示待核对。LaunchReadinessChecker 的 appManagementItem 固定返回 warning，界面又固定输出待核对，未检查授权。人工核对入口无法消除已授权用户的疑虑。

## Decision

使用动态加载的 TCCAccessPreflight，只查询当前运行应用的 kTCCServiceSystemPolicyAppBundles，不传其他进程 token，不请求或改变权限，不读取授权数据库。Apple IOKitUser 的声明定义返回值 0 为 granted、1 为 denied、2 为 unknown；未知值、缺失符号或框架也返回 unknown。FDA 保留原文件读取检查，不从它推断 App 管理状态。

准备情况映射三态：已就绪、需要授权、无法确认。App 管理的系统设置入口常驻；未知状态说明无法读取授权状态。共用 PermissionReadiness 同时汇总两种权限：拒绝优先红点，其次未知橙点，全部通过后隐藏。悬停和可访问文字列出真正未通过的权限。沿用启动、回到前台、打开设置与检查页的刷新，不增加轮询或持久化确认。

补齐所有语言，版本保持 2.2.1 / build 53。维护者授权修复并替换安装版；使用原证书完成 Release clean build，验证新安装版的实际检查结果后清理暂存旧包。不提交、推送或发布。

## Alternatives considered

- 保留人工待核对：没有私有接口依赖，但用户开关开启后仍持续警告，已被实际反馈否定。
- 读取 TCC 数据库并匹配签名要求：可以读取记录，但依赖 FDA 和数据库结构，新增依赖更多；选择直接向系统预检当前应用。
- TCCAccessCheckAuditToken：能显式指定身份，但本机 App 管理服务的实测返回 false，tccd 日志明确报告查询者没有检查目标授权的 entitlement。即使查询自己的 token 也如此，不能将 false 当成权限拒绝；不使用该接口，也不添加私有 entitlement。
- 普通文件写入或以打开设置成功确认授权：前者早已实测不能证明权限，后者只表示页面可打开，都不构成授权证据。

## Consequences

已开启权限的用户能看到独立 App 管理已就绪结果，提醒点同时反映两种实际权限。接口属于 macOS 私有 SPI，未来版本可能改变或移除；系统返回 unknown、未知值、缺失符号或框架时显示无法确认，不把查询失败当已授权。未确定不等于明确拒绝，不新增持久化人工确认。
