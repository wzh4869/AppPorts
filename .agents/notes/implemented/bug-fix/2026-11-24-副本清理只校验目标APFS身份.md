# Agent Note: 副本清理只校验目标 APFS 身份

Status: implemented

## Problem

同一个 Apple Metal 工具链磁盘映像可以被系统服务和 Xcode 分别挂载。两次挂载报告相同的 APFS 容器 UUID 和卷 UUID。AppPorts 在确认旧卷归属时要求整份清单的 UUID 唯一，微信数据还原到本地后，另一块盘上的旧副本因此无法完成清理。

## Decision

清理读取完整的 APFS 清单，核对目标卷 UUID 的出现次数和关联容器 UUID 的唯一性。清理重试只有在原容器唯一在线、目标卷在整份清单中均无记录时，才能认定旧卷已移除。目标卷出现在别的容器、目标身份重复、容器离线或清单字段无法读取时，暂停清理。其他卷和容器的 UUID 可以重复。

[持久化迁移事务](../architecture/2026-10-10-verified-transfer-lifecycle.md)与[卷盘点和重试](../architecture/2026-10-22-volume-state-adaptation.md)定义的内容核对、切换记录与删除凭据继续适用。应用库映像接管和物理磁盘弹出使用各自的身份规则。

## Alternatives considered

- 全局按 UUID 合并条目可直接沿用旧查询结构，但会丢失目标身份重复的证据，可能把错误的容器视为唯一匹配。
- 仅查询旧卷所在容器可减少读取范围，但旧卷删除后的重试仍需验证原容器在线，并确认目标卷未出现在其他容器。

## Consequences

无关映像的重复挂载不再阻塞旧副本收尾。每次核验仍需要完整清单，目标身份不明确或清单无法读取时等待重试。

## Verification

`DiskUtilityCreationTests` 中的清理用例覆盖无关映像重复挂载、原容器在线且目标卷已消失，以及目标容器、跨容器目标卷和同容器目标卷重复。夹具注入模拟磁盘清单。
