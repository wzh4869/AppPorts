# Agent Note: 应用数据快照缓存与权限门槛

Status: implemented

## Problem

在应用数据页反复选择应用会重新发现目录并测量大小。若直接复用旧结果，访问权限、目标磁盘或迁移记录已经改变时仍可能展示过时状态；读取失败也不能被当作确认没有应用数据。

## Decision

`AppDataScanCache` 保存当前页面生命周期内的内存快照，以应用路径查找，再比较完整 `Context`：`AppItem`、外部根目录、微信拆分模式和 `recordsRevision`。快照包含目录、读取及身份诊断、沙盒状态和微信容器信息；身份失败或任何读取问题会移除该应用的缓存。不增加磁盘格式、离线身份数据库或有效期承诺。

`DataDirsView.scanLibraryDirs` 每次先探测当前进程的完全磁盘访问权限，包括缓存命中路径。只有 `.granted` 才继续；拒绝或未知时清空缓存，显示“权限不完整”和检查入口，不读取受保护的应用数据。权限面板关闭后，未就绪页面重新扫描。

普通应用选择和页面返回可以复用相同上下文的完整快照。迁移记录变化、目标盘变化、挂载或卸载通知以及人工刷新清空快照；人工刷新同时清除大小缓存并强制重测。新扫描先发布目录发现结果，再以最多四个任务统计大小；完成发布受扫描 token 和记录版本保护，已取消任务不保存完成快照。

普通迁移与挂载迁移在打开确认前均通过 `refreshAppDataBeforeMigration` 绕过快照并强制重测。仅当原路径仍存在、可迁移、大小读取完整且状态为本地时继续，否则提示重新选择。底层执行仍承担路径、锁和数据安全检查，界面快照不能授予操作权限。

## Alternatives considered

以下为 `b716357` 中原实现与当前实现的对照，未追认不存在的历史评审。

- 每次选择应用都完整扫描：结果更新直接，但重复浏览同一应用仍需重做发现与统计，因此复用内存快照并保留显式失效入口。
- 直接按路径复用已测快照：查询简单，但不足以区分目标盘、分组模式和记录变化，因此复用前同时核对上下文与当前权限。
- 直接用列表中的缓存项打开迁移确认：省去一次等待，但展示数据可能陈旧，因此迁移入口强制重新发现和测量。

## Consequences

普通浏览可复用完整结果，权限未就绪与空目录结果有明确区分。代价是权限探测仍在每次访问时执行，迁移确认前仍需等待重扫；快照按访问应用累积且没有容量淘汰或定时失效。同一路径内数据自行变化时，展示可一直陈旧到刷新或其他失效事件，不能将缓存描述为实时监控。若浏览应用数导致内存压力，应重访淘汰策略。

## Verification

`AppDataScanCacheTests` 四项测试覆盖应用间保留、权限拒绝与未知、目标盘/记录/分组变化及显式失效和读取失败。测试直接调用缓存结构，不覆盖真实系统授权、通知送达或迁移前重扫交互。本次只核对源码与测试内容，未重跑测试或测量性能；真实权限变更与迁移入口需实际应用验收。
