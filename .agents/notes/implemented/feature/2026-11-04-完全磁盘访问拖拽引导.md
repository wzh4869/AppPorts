# Agent Note: 完全磁盘访问拖拽引导

Status: implemented

## Problem

现有授权入口只打开系统设置，用户需要自行定位 AppPorts，再添加到完全磁盘访问列表。用户要求参考 dogsc，在系统设置旁提供可拖动的应用图标。

## Decision

用户在确认 MIT 可复用及具体交互后要求继续接入。仅接入完全磁盘访问入口，不扩展到应用管理或额外权限。入口先沿用[安装位置检查](../../implemented/bug-fix/2026-11-04-按操作检查安装位置与普通入口独立启动.md)，然后打开系统设置，显示不抢焦点的原生浮窗。浮窗跟随系统设置窗口，下面放不下时移到上面，上下都放不下时贴着窗口底边内侧显示，不遮挡标题栏和窗口控制按钮；左侧提供真实应用文件 URL 拖拽，右侧显示“找不到 AppPorts？”和“把图标拖入‘完全磁盘访问权限’列表，再打开开关。”。按用户给出的参考图保留紧凑横向布局，不提供 Finder 定位和关闭按钮。切换到无关应用、设置关闭或拖入被接受时隐藏，不遮挡后续系统认证。

借用 dogsc 提交 567fd6ed3bf113227dcf3e815f87ce60f0b69497 中 RecorderPermissionView.swift 的图标拖拽、NSPanel 生命周期和窗口定位代码；保留 MIT 版权声明与仓库来源，并将声明打包进应用资源。无需引入 dogsc 的录屏模块或依赖。视图复用 AppDialogTypography，明亮背景白色、暗色中性色，无渐变或装饰图标。

拖入成功只表示系统接收文件，不能设为已授权。继续沿用 LaunchReadinessChecker 的完全磁盘访问探针及返回应用后的刷新。新文案覆盖语言目录中的全部 22 种语言，遵循[本地化覆盖规则](../testing/2026-10-23-本地化覆盖与英文占位守卫.md)。

## Existing-note audit

- 安装位置记录部分重叠，新增授权按钮也要求稳定位置；原有迁移和映像策略不变。
- 活跃笔记中未发现相同权限浮窗决定，未取代其他权限检测规则，无需归档。

## Alternatives considered

- 只打开 Finder 并选中 AppPorts 实现最少，但还需要用户在两个窗口之间找图标，未满足贴着系统设置提供浮窗的需求。
- 在浮窗内保留 Finder 定位和关闭按钮可提供额外操作入口，但用户确认只需要图标和拖拽文案，故移除按钮；需要键盘操作时仍可使用系统设置自身的添加入口。
- 引入完整 dogsc 权限教程可直接复用更多界面，但其录屏、辅助功能、动画和工作区恢复与 AppPorts 无关，仅提取必要部分。
- 自动修改系统权限不能替代用户确认，也不是本任务的授权范围；继续由系统设置控制添加、开关和认证。
- 上下都放不下时改放窗口左右两侧可以不遮挡窗口内容，但常见屏幕宽度放不下 640 点浮窗，仍要第三种兜底位置；因此直接贴窗口底边内侧显示。

## Consequences

完全磁盘访问的现有三个界面入口共用同一服务，用户能在系统设置旁直接找到要添加的应用；应用管理仍维持现状。拖拽载荷是当前稳定安装应用的文件 URL；浮窗不把接受拖入当成授权成功。设置关闭、切换到无关应用或拖入被接受后停止跟随并隐藏。

新增一个原生浮窗及窗口跟随任务需要维护。系统设置窗口定位依赖公开窗口列表及当前窗口尺寸；系统版本变化可能使浮窗无法定位，此时原有系统设置仍能使用，应在适配该版本时重新核对。代码维持 macOS 12 最低系统版本，NSHostingController.sizingOptions 仅在 macOS 13 及以上设置；macOS 12 运行表现尚未验证。

系统设置窗口接近占满屏幕高度、上下空间均不足时，浮窗贴着窗口底边内侧显示，可能遮住窗口底部的部分内容，但不覆盖标题栏及三个窗口控制按钮。修正前，实机出现过浮窗被限制在屏幕顶部、覆盖标题栏的情况。

浮窗新增三个 key：`找不到 AppPorts？`、`把图标拖入“完全磁盘访问权限”列表，再打开开关。`、`将 AppPorts 图标拖入系统设置的应用列表`，现已补齐全部 22 种语言，不再依赖其余语言的临时回退。连同安装位置提示，本次相对 PR 基线共新增六个 key，旧条目内容不变。
