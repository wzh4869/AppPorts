# Agent Note: 后台更新守护与主窗口设置

Status: implemented

## Problem

现有 ShipIt 监控只由主程序启动，完全退出后无法接手更新。容器卷与应用库恢复已通过无窗口的 --mount-agent 运行，但用户没有开关，也无法从设置理解后台行为。设置目前为固定 560 宽的 sheet，与主窗口中的迁移页分离。

## Decision

磁盘维护代理和应用更新守护使用两个持久化偏好，缺失时均为 true。关闭磁盘维护代理会卸载其自动运行配置，保留现有挂载、数据和恢复记录；前台手动恢复不变，后台在取得操作锁后再次核对开关。关闭应用更新守护会安全停止自动接手，保留收据和副本。开关说明明确用途与当前 ShipIt 支持范围。配置写入复用共享 OperationLock、既有稳定安装路径、签名约束和 launchd 注册核对；两项配置分别执行、合并报告错误，一项失败不阻止另一项关闭。AppLibraryAgentSync 串行应用最新偏好，并显示配置中的等待、失败和重试状态。

新增文案按维护者指定先完成 en、zh-Hans、zh-Hant，其余语言明确回退英文，不复制英文充当已完成翻译，不放宽全语言审计。构建、安装和后续设置验收由对应验证记录持有。

## Alternatives considered

- 在挂载代理每次运行时检查一次更新：复用进程最直接，但更新发生时不一定插盘，无法及时接手。
- 复制一套独立 helper：可以彻底独立于应用包，但需要另一套签名、权限和更新安装路径；同一可执行文件的后台模式可以复用既有代理约束。
- 前后台分别启动监控器并共同写任务历史：直接复用现有界面逻辑，但两进程的整份历史快照会互相覆盖；只保留一份自动执行者，并独立发布每次更新的状态。
- 保留设置弹窗并增宽：改动小，但不满足用户要求的主窗口页面；保留入口并改变内容区。

## Verification

Debug build-for-testing 及独立测试宿主构建成功。核心专项执行 143 项 XCTest（141 通过、2 项可选签名夹具跳过），另 80 项 Swift Testing 通过。覆盖真实文件事件、独立后台子进程、ShipIt 恢复及回退、状态导入、配置隔离、自更新、挂载与映像、权限和 WriterAdmission。复制、操作锁、收据和事件使用生产实现；系统注册、应用启动及可选签名夹具的结果不扩大为安装版实机更新。首轮 core-first 中一项事件反向断言在监听根初始事件稳定前开始；修正夹具等待后专项通过，首轮失败记录保留。

布局修改前设置渲染及自更新 25 项通过。双列布局修改后补跑设置渲染、挂载注册与映像专项，20 项 XCTest 和 40 项 Swift Testing 通过。设置渲染覆盖 660/940 点、中英文及法语英文回退、明暗模式；共 12 张设置截图使用生产组件及隔离偏好。它们不能用于推断安装版的实际权限状态。

本地化审计 19 项中 18 通过，仅全语言翻译完整性失败：八个新 key 在延期的 19 种语言中缺少 152 个翻译槽位。该混合运行整体 exit 65，不视为全部通过；缺译按维护者指定范围保留。

初始同证书 Release clean build 成功，产物为 2.2.1（55）、arm64/x86_64，严格整包签名通过。与构建时安装的 2.2.1（54）相比，叶证书、指定签名要求、entitlements、hardened runtime、Team ID 和应用标识一致。313 个构建和测试输入的最后哈希核验无变化，核心专项后变更的四个文件均由上述补跑覆盖。安装后的启动缺陷及 build 57 的修复验收由更新守护登记记录持有，初始构建结果不代替后续安装结论。

独立 Debug 空记录代理在 15 秒内检查次数保持 1、窗口数为 0、CPU 时间保持 0:00.06，末次采样为 0.0% CPU、30.6875 MiB RSS，SIGTERM 正常退出。这仅证明隔离空记录进程没有周期扫描，不量化安装版或实际恢复中的性能。

核心命令、源码快照及结果在本地 build/Validation/background-agents-20261116/REPORT.md。专项测试与隔离子进程结果不扩大为安装版实际应用更新、开关切换、登录或系统权限切换的完整验收。全量 runner 验证单独记录。

## Consequences

两个后台代理使用持久化开关与共享操作锁串行同步；配置失败可重试，一项失败不会阻止另一项关闭。开关关闭不删除迁移数据或恢复材料。

后台仍依赖稳定安装的 AppPorts 可执行文件及现有系统权限。其余语言暂用英文，翻译完整性审计保留缺口；实际登录和应用更新需要安装后验收。
