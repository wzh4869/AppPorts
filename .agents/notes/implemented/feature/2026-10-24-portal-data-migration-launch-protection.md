# Agent Note: 数据迁移期间阻止原生启动入口转发

Status: implemented

## Problem

应用数据复制和切换要求应用停止运行。用户可能在迁移或迁回过程中再次点开本地启动入口；只有开始时检查运行状态，不能减少这种误操作。用户确认对经过 AppPorts 启动器的请求实施防误打开。

## Decision

启动前映像准备及共享租约的扩展时机见[启动迁移应用时静默接回映像](2026-11-03-启动迁移应用时静默接回映像.md)，不改变迁移持有独占锁的规则。

AppPorts 与原生 macOS portal 共同编译 `ApplicationLaunchGate`，使用用户 Application Support/AppPorts/launch-locks 下按真实 bundle identifier 的 SHA-256 命名的 flock 文件。迁移持有独占锁，启动转发持有共享锁，均非阻塞取得。锁文件不删除、不原子替换；关闭描述符释放锁，进程退出或崩溃由内核释放，不凭 PID 文件或时间推断结束。文件拒绝符号链接、非普通文件、多硬链接及非本人/开放权限的状态。

原生入口核对真实应用标识与 portal 记住的目标一致，再取得共享锁。启动、重开、文件和 URL 事件共同经过同一转发函数；冲突显示“正在迁移或迁回应用数据，请等待完成后再打开”，检查失败显示不可确认，不转发。共享锁持续到 NSWorkspace 回调在主线程处理完，避免请求已发出而应用尚未登记的间隙。迁移仍须在取得独占锁后检查应用运行状态和既有写入者。

应用数据任务在执行时持锁，排队未开始不阻止启动，复制暂停仍持锁；取消后直至原有恢复收尾返回才释放。APFS migrateAndComplete、restoreAndComplete 、resumeVerifiedTransfer 和独立恢复入口 recoverWithIndependentBudget 同时保护服务入口及后台接续；任务内嵌调用用 TaskLocal 保留同目录、同身份租约，不重复取得自身独占锁。独立恢复显式把该上下文传入 detached task，调用方在等待恢复完成期间仍持有租约；后台首次接续则在 detached 之前取得租约。测试记录库使用自己的 launch-locks，不能阻止真实用户应用。

传统符号链接数据迁移在 DataDirMover 的完整操作、低层迁移/迁回、接续和清理入口同样持锁，覆盖签名修复面板和后台维护的直接服务调用。应用身份优先取目录关联信息，再取受管链接和该原路径的事务记录；复制的写入检查与新事务保存同一身份，确保关联信息或链接索引缺失时，后续接续仍能找到保护锁。

启动保护引入 portal 格式 6；本地化补齐后为 7，映像启动准备使用格式 8。原生 macOS 旧入口通过既有完整 staging、签名和原子替换刷新。找不到内嵌 native binary 时拒绝创建/刷新替代入口，保留旧入口，不以无保护 bash 降级冒充此能力。迁移本身不改真实应用的代码、权限或签名。

新增提示现已覆盖 22 种语言，独立启动器的译文由主目录生成并按系统首选语言选择，主应用保留自身语言选择；生成约定与范围见[本地化覆盖](../testing/2026-10-23-本地化覆盖与英文占位守卫.md)。

## Scope and recovery

这是一层协作式防误打开，不是系统执行拦截。直接打开外盘真实应用、应用本体仍在本机、旧版 AppPorts 或尚未更新的 portal 都可绕过。iOS 包装应用的既有 bash 入口不在本轮原生 macOS 范围内。崩溃后内核释放锁仅表示该进程已结束，不证明中断的数据事务已经修复；原事务的恢复与数据完整性检查继续负责后续处理。保留[严格复制与写入检查](../architecture/2026-10-01-data-path-copy-safety.md)，不据启动器拦截删掉切换前检查。

## Alternatives considered

- 只查询运行应用通知并强退：能发现从其他入口启动的应用，但通知到达前应用可能已经写入，强退还会打断合法保存，不能冒充启动前阻止。
- 持久布尔值或 PID 标志：启动器读取简单，但崩溃、PID 重用和清理时序容易留下永久拦截；使用系统释放的锁。
- Endpoint Security 的执行授权：可覆盖系统执行路径，但需要 Apple 专门授权和额外部署，超出本轮原生入口范围。

## Consequences

常规原生入口能在真实应用启动前提示等待，同一应用的多个数据目录共用保护，其他应用仍可启动。代价是维护跨进程协议、旧入口升级和独立启动器提示。失效入口或锁文件不可检查时拒绝本次转发，用户需要回到 AppPorts 检查；该防误操作不能替代事务恢复或抵御不合作的同用户进程。

## Verification

共享/独占竞争、不同应用隔离、真实任务取消后的独立恢复、进程崩溃释放和符号链接拒绝均有隔离测试。直接数据服务、后台接续和缺失链接索引时的身份传递也有回归；最后一轮服务验证通过 47 项 XCTest 和 158 项 Swift Testing，包含 DataDirMover、APFS、传统数据恢复、签名依赖和启动保护。应用迁移、任务中心、入口资料及本地化的相关套件另行通过。

Release clean build 通过，内嵌启动器包含 arm64 与 x86_64。开发签名与安装版的指定要求一致，构建包通过系统现有完全磁盘访问授权要求的验签。隔离应用的原生入口在持锁时显示等待提示且未启动真实目标，释放锁后目标成功启动；真实文件和 URL 的系统关联打开流程未单独验收。

本机安装并启动 2.0.0（build 50），build 49 保留为可恢复备份。安装后授权要求仍匹配，三个已有数据卷的 UUID、原位挂载和 nobrowse 标记均保持；显式本地列表刷新后，微信及抽查的其他原生入口已升级为格式 6，启动壳验签通过。
