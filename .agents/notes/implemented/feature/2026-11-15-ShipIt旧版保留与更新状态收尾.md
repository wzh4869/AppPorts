# Agent Note: ShipIt 旧版保留失败接手与安装状态收尾

Status: implemented

## Problem

2026-11-15 的 10:11 实测中，新版完整缓存存在，但 ShipIt 因达到安装重试上限中止，并重新打开仍在外盘的旧版。此前清理下载和临时文件遗漏 ByHost 中的 SQRLInstallerOwnedBundle；该状态指向已删除的旧临时目录。原接手仅处理目标缺失，也只识别 Installation error 日志，因此没有接手这次失败。

独立补清 ByHost 后，10:17 从真实界面执行安装并重启，ShipIt 发生跨卷写回失败，AppPorts 自动安装并打开 0.2.2-rc.3。但成功接手后，ByHost 仍有旧包恢复记录与 SQRLShipItInstallationAttempts=1，后续更新会继续背负先前的失败状态。

## Decision

自动恢复的进程位置由[后台更新守护与主窗口设置](2026-11-16-后台更新守护与主窗口设置.md)扩展为无窗口更新代理；本篇旧版替换、正常退出、备份与安装状态收尾不变。新代理的实机更新仍需单独验收，不沿用本篇主进程实测结论。

恢复的触发与待办重试由[事件触发检查](2026-11-15-ShipIt事件触发检查.md)负责，本篇安装、退出、备份和状态收尾原则保持不变。

保留原缺失目标恢复；另识别明确的重试耗尽/中止失败。目标仍在时，仅在缓存版本更高、Bundle ID 相同且满足旧应用的原开发者签名要求时准备替换。新版在独立 staging 中复制、验证和同步完成后，持有启动保护请求目标正常退出，不强退；只请求一次，未退出就保留待办，确认应用和更新器均停止后再切换。

收据持久化旧目标身份和同卷备份路径。使用原子交换替换已核验的旧对象，旧对象转存隐藏备份并保留；中断后按新目标与旧备份 inode 补齐，不重复复制、覆盖或丢弃旧包。相同/较新版本、未知版本、不同应用或开发者均不自动替换。

确认新应用安装及入口刷新完成、请求仍未改变且更新器退出后，移除该应用 ShipIt 的 CurrentUser/CurrentHost 下两项安装状态，不动主应用偏好、会话或其他更新器。解析持久包记录只读 PropertyList，不实例化第三方归档类；归档须包含本次目标。同步并确认清空后再按请求启动，最后完成收据。旧版完成收据允许只补状态收尾，不重复启动应用。

## Alternatives considered

- 仅重新清理测试环境：可使首次流程通过，但用户真实失败状态可能相同，也不能替已保留旧版的安装收尾。
- 自动覆盖所有现存目标：实现短，但会替换相同版本、较新版或其他对象；必须以更高版本、原开发者身份和收据旧对象身份为准。
- 强退旧应用：可立即切换，但可能中断未保存工作；只请求正常退出，未退出时等待。

## Verification

- 最终代码专项为 31 项 XCTest（30 通过，1 项可选实盘夹具跳过）和 9 项 Swift Testing，均无失败。覆盖旧版替换、备份保留、同版/较新版拒绝、退出被拒后等待、中断续作、ByHost 两键清理、其他目标状态保留、既有完成记录补收尾且不重启。日志 `/tmp/AppPortsShipIt-extended-final-tests.log`。中断由夹具控制阶段重现，不是断电实验。
- 原证书签名 Release clean build 通过，日志 `/tmp/AppPortsShipIt-extended-final-release.log`。已安装 `/Applications/AppPorts.app`，仍为 2.2.1 / build 52；安装版与该构建产物的可执行文件 SHA-256 相同。此次扩展未额外升号。
- 旧完成收据的实机补收尾通过：ByHost 两键清空，DeepSeek 原运行 PID 保持，不重新启动应用。
- 目标缺失路径：从 0.2.1-rc.2 和空下载缓存开始，经 DeepSeek 界面下载并安装。10:39 ShipIt 跨卷写回失败，AppPorts 自动安装并打开 0.2.2-rc.3，刷新入口，收据 complete / installerStateCleaned 均为 true。偏好服务与稍后落盘文件确认两键清空；最初直接读磁盘仍见旧键属于偏好服务落盘延迟，不能据此判定清理失败。
- 旧版保留路径：同样从旧版和空下载缓存开始，经界面重新下载，仅设置 SQRLShipItInstallationAttempts=3 重现已知条件。11:06 ShipIt 明确报重试耗尽并重新打开旧版；AppPorts 正常请求退出，原子交换并保留旧对象，再自动打开 0.2.2-rc.3。“关于”界面、外盘主程序路径、入口版本、完成收据、ByHost 清空及完整签名均核对通过。备份是原 0.2.1-rc.2 的同一 inode，缓存新版仍保留；没有手工复制新版来代替自动接手。
- 实机材料和结果存于本地 `build/Validation/shipit-extended-20261115/REPORT.md`。其他 ShipIt 应用、系统重启和物理断电未验证；全量测试未跑（项目要求一次性 macOS runner）。未提交、推送或发布。

## Consequences

已明确失败但保留旧版的安装可自动完成，成功接手也不再遗留本次重试状态。旧版正常退出被拒时保留待办，只请求一次，待用户退出后续作。复制、签名、持久收据和锁沿用已有实现，新增旧对象交换与第三方状态收尾分支。

仍受 AppPorts 自身外盘权限和主进程运行条件限制。未知版本/归档格式保留现场。保留旧版备份占空间；没有以自动清理替代恢复能力。不保证其他更新框架或全部 ShipIt 变体可用。不改变锁定迁移默认值，也不自动解锁已锁定应用。
