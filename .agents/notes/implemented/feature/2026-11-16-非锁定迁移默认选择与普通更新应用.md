# Agent Note: 非锁定迁移默认选择与普通更新应用

Status: implemented

## Problem

维护者报告 WorkBuddy 在外盘更新时主动要求安装到“应用程序”文件夹；网易云非锁定本体更新成功，锁定后迁回再迁出时的缓存残锁另有修复。DeepSeek 的 ShipIt 失败接手已完成实机验证，维护者也报告 Qoder、OpenCode 更新成功。现有弹窗却仍高亮锁定，强调外部应用丢失；应用列表暴露 Sparkle/Electron 框架徽章，不能帮助用户选择迁移方式。

## Decision

WorkBuddy（com.tencent.workbuddy.mac）和网易云（com.netease.163music）按普通应用迁移，本体迁出及接回不出现更新锁定选择，也不因其他独立应用的批次锁定选择而新上锁。规则按实际包身份读取，改名不影响，同名其他应用不享受例外。确认列表和新锁判定共用例外，hasSelfUpdater 保留真实更新器检测。文件夹内逐个检测子应用：全为普通应用时跳过；还有其他更新器时保留整文件夹的既有选择及锁定语义。

其他检测到更新器的应用仍提供锁定与非锁定两种选择，非锁定放在右侧强调位置并设为 Return 默认操作。已批准的文案说明迁移可能影响更新：不加锁时可尝试继续应用内更新，设置中开启守护后可协助处理异常，但不保证所有应用处理成功；锁定可能限制更新，可先迁回本机。实际效果取决于应用自身更新方式，不承诺全部 ShipIt 变体成功，也不把网易云的自行更新说成守护介入。取消仍不提交操作。

设置字样前插入 SF Symbols gearshape。WarningSheetRequest 可携带 introText；普通 intro 保留完整无占位标记的可访问文本，其他警示仍使用原字符串。两种语言用格式占位符控制图标位置，不以 emoji 替代。WarningAction 的默认操作标记仅在本次非锁定按钮启用，其他已有 preferred 操作不改变快捷键。

应用本体徽章和应用数据列表中的 Sparkle/Electron 标记移除，非锁定徽章说明同步。扫描器生成候选时解析实际包身份，复用迁移服务的普通应用名单，将网易云与 WorkBuddy 的 needsLock 设为 false；真实更新器检测字段继续保留。未上锁的普通应用显示“已链接”，其他需要锁定选择的更新器保留“非锁定迁移”。徽章仍对已链接的更新应用读取真实锁状态，之前已锁定的普通应用继续显示“锁定迁移”；任务身份包括更新器检测值，避免轻量扫描之后漏查。签名核验、旧锁接管、显式解锁及缓存清锁不变，不自动解锁此前迁移的真实应用。

初始交付时文案仅完成简体中文和英文，并通过 `localized(fallbackLanguage:supportedLanguages:)` 将其他语言回退英文；两条新键的其余 20 种语言已由[本地化覆盖与英文占位守卫](../testing/2026-10-23-本地化覆盖与英文占位守卫.md)全部补齐，正文和设置标签恢复标准 `.localized` 全语言读取。旧弹窗与非锁定说明两项被新键替代。最终文案获维护者批准后，build 从未安装的 64 递增至 65。维护者随后授权安装，替换 /Applications/AppPorts.app；不提交、推送或发布。

## Alternatives considered

- 保留所有更新器的锁定推荐：无需调整历史保护规则，但与已验证的正常更新及守护接手能力不符，也让 WorkBuddy 无必要地要求用户作选择。
- 按显示名称跳过提示：实现直接，但改名即失效，同名其他包又被误排；读取实际 Bundle ID。
- 只删确认名单：单应用迁移足够，但混选其他应用并锁定时仍会给普通应用新上锁；新锁判定复用相同例外。
- 只在徽章中按应用名隐藏非锁定提示：改动更少，但扫描器仍将普通应用标为需要锁定，且改名失效；候选生成复用实际包身份和既有普通应用规则，同时保留真实旧锁显示。
- 把 ShipIt 描述为全部保证可更新：更肯定，但签名被替换或缓存不完整时恢复仍会拒绝；产品只说明已适配失败的恢复能力。
