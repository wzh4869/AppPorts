# Agent Note: 启动迁移应用时静默接回映像

Status: implemented

## Problem

本地原生启动入口在真实应用路径不存在时立即提示外部存储未连接。应用库映像即使可以自动附加，也需要先手工打开 AppPorts。只有应用本体可访问仍不足以启动：同一映像中的沙盒数据卷可能尚未挂回原目录，应用会看到离线入口或空数据位置。

## Decision

入口辅助程序依赖及安装位置要求由[按操作检查安装位置与普通入口独立启动](../bug-fix/2026-11-04-按操作检查安装位置与普通入口独立启动.md)收窄：只在应用或其数据关联映像时保存 helper；普通入口独立启动，既有入口随数据记录变化刷新元数据。

映像的主动卸载及持久化自动恢复暂停见[应用库映像主动卸载](../bug-fix/2026-11-08-应用库映像主动卸载.md)，物理磁盘重连不会解除该暂停。

原生 portal 在转发启动前运行 AppPorts 的无窗口 `--prepare-image-launch` 入口。成功时直接继续 NSWorkspace 启动，不展示准备界面；失败后才显示既有存储提示。启动、文件和 URL 请求在准备阶段排队，共用一次准备任务；启动共享租约从准备前保持到真实启动完成，避免数据迁移在准备和转发之间开始。

portal 格式升级到 8，保存本机 AppPorts 可执行路径；应用来自当前已记录应用库映像时，在入口保存映像记录。现有已迁移入口沿用完整 staging、签名与原子替换刷新机制升级，不修改外部真实应用。主程序与 SMB 连接子进程都在 SwiftUI 初始化之前分派，无需显示 AppPorts 主窗口。

准备任务只选择入口保存的映像和当前记录的映像中，与目标应用路径或相同 bundle identifier 的数据记录相关的项。计划先从本地记录生成，取得操作锁后重新读取。先恢复映像，再读取映像对应设备的卷 UUID；仅对属于该映像的应用数据记录调用既有挂载服务，并检查原路径的实际挂载 UUID。受管符号链接数据检查目标路径和存储 UUID，不重建链接或复制数据。物理外盘和其他软件的数据不参与自动挂载。

其他迁移可能长时间占用全局锁，因此取锁前先做只读就绪检查。映像要求记录有已核对的卷 UUID、没有弹出暂停、SMB 共享已挂载且映像仍在记录路径（本地底层卷按 UUID 解析后路径不变），应用库路径上挂载的 APFS UUID 与记录一致。数据卷要求属于该映像，并由 `ContainerVolumeMigrator.isMountedAsRecorded` 按 `mount(record:)` 已挂载分支的接受条件核对：手动卸载暂停、弹出暂停、记录仍存在、需人工处理标记、迁移路径策略、未完成的迁回意图、挂载 UUID 及所有权。受管链接沿用同一核对。全部满足时直接放行，不登记写入进程、不取锁；任一项不满足或检查出错时走加锁流程，行为不变。只读检查不连接共享、不附加或挂载、不写记录。

SMB 恢复仅使用系统已保存凭据，禁止认证窗口。底层沿用映像存储身份、挂载后 UUID 校验、主动弹出暂停、手动卸载暂停及容器挂载保护。准备入口不执行全局维护，不清理副本，不重签真实应用。单次系统命令最多 20 秒，同一执行器有 45 秒命令预算，锁最多等待 5 秒；文件检查与 SMB 连接仍遵循既有独立进程时限。等锁超时单独记录锁占用原因，界面沿用既有存储提示。写命令未确认退出时继续持锁等待，不能为启动超时而留下失控写进程。

## Alternatives considered

- 依赖登录代理定时重试无需修改启动器，但用户点开软件时数据未必已就绪，也无法消除首次错误提示。
- 把挂载命令直接编入启动壳可以减少辅助进程，但会复制映像身份、SMB 重连、容器记录及暂停规则；复用主程序无窗口服务可以保持这些规则一致。
- 先启动应用再后台接回数据看似更快，但应用可能先创建新数据或报错；只有准备完成才转发启动。
- 就绪检查只核对数据卷挂载 UUID 实现更少，但会绕过 `mount(record:)` 对手动卸载、弹出暂停和需人工处理状态的拒绝；弹出流程先记录暂停再请求 Finder 弹出，只看 UUID 可能在弹出过程中放行应用，因此按挂载接受条件完整核对。
- 锁被占用时改为提示“AppPorts 正在执行其他操作”说法更准确，但需要新增入口退出码和文案并决定补译；就绪检查覆盖已挂载场景后，剩余场景中映像或数据确实尚未就绪，且锁失败信息无法区分占锁者，本次保持原提示，只在日志中区分。提示“5 秒后重试”不准确：5 秒只是等锁上限，占锁操作可能持续数分钟。

## Consequences

通过新版原生 portal 打开、且映像可恢复时，不显示存储提示。连接失效、缺少凭据、需管理员权限或数据卷核对失败时不启动真实应用，记录失败并显示提示。准备失败不删除映像；不要求 AppPorts 界面运行，但本机 AppPorts 程序须仍可执行。正常启动增加辅助进程和少量状态检查；恢复共享或映像会增加等待，不能承诺固定秒数。

旧入口需要在映像在线时由新版 AppPorts 刷新后才具备能力。直接打开外部真实应用、仅迁移数据而仍直接运行本机原应用、普通符号链接入口和 iOS bash 包装入口不经过本轮原生 portal，因此不提供启动拦截。数据映像由当前已保存应用库记录关联；更换到另一数据映像后，没有持久化映像线索的旧数据记录仍依赖原有后台恢复。若需要跨多个历史数据映像恢复，应扩展独立的映像索引，不按同名物理卷猜测。

已就绪的映像应用不再受其他迁移占锁影响。就绪检查每次启动增加少量只读命令和检查进程，数据卷越多耗时越长。映像或数据尚未就绪且恰有其他操作占用全局锁时，5 秒后仍显示存储提示，日志可区分锁占用与存储离线。只读检查与加锁流程的接受条件需要同步维护，`isMountedAsRecorded` 与 `mountRecordedVolume` 的已挂载分支互相注明。

仅执行本次相关 Swift 文件的语法解析和笔记结构检查，不构建、安装或执行测试套件。真实 Finder/Dock 启动、准备期间文件及 URL 请求、无凭据失败和已有入口升级仍需新版实机验证。

就绪检查补充隔离用例：全部就绪时放行；任一检查存疑或报错时回到加锁流程，且不再执行后续检查；无数据卷时不查询映像卷清单。SMB 映像只在共享已挂载、路径未变且应用库 UUID 一致时就绪；本地映像换路径或处于弹出暂停时不就绪；两者均不运行 hdiutil。数据卷只读检查与 `mount(record:)` 对已挂载、需人工处理和手动暂停状态的判定一致，不发出挂载或卸载命令，外来卷和已删除记录不就绪。相关 20 个套件中 XCTest 57 项（3 项需真实环境，跳过）、Swift Testing 239 项通过，Release clean build 通过；其他迁移占锁时的实机启动尚未验证。
