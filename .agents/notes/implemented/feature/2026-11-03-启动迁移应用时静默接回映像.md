# Agent Note: 启动迁移应用时静默接回映像

Status: implemented

## Problem

本地原生启动入口在真实应用路径不存在时立即提示外部存储未连接。应用库映像即使可以自动附加，也需要先手工打开 AppPorts。只有应用本体可访问仍不足以启动：同一映像中的沙盒数据卷可能尚未挂回原目录，应用会看到离线入口或空数据位置。

## Decision

原生 portal 在转发启动前运行 AppPorts 的无窗口 `--prepare-image-launch` 入口。成功时直接继续 NSWorkspace 启动，不展示准备界面；失败后才显示既有存储提示。启动、文件和 URL 请求在准备阶段排队，共用一次准备任务；启动共享租约从准备前保持到真实启动完成，避免数据迁移在准备和转发之间开始。

portal 格式升级到 8，保存本机 AppPorts 可执行路径；应用来自当前已记录应用库映像时，在入口保存映像记录。现有已迁移入口沿用完整 staging、签名与原子替换刷新机制升级，不修改外部真实应用。主程序与 SMB 连接子进程都在 SwiftUI 初始化之前分派，无需显示 AppPorts 主窗口。

准备任务只选择入口保存的映像和当前记录的映像中，与目标应用路径或相同 bundle identifier 的数据记录相关的项。计划先从本地记录生成，取得操作锁后重新读取。先恢复映像，再读取映像对应设备的卷 UUID；仅对属于该映像的应用数据记录调用既有挂载服务，并检查原路径的实际挂载 UUID。受管符号链接数据检查目标路径和存储 UUID，不重建链接或复制数据。物理外盘和其他软件的数据不参与自动挂载。

SMB 恢复仅使用系统已保存凭据，禁止认证窗口。底层沿用映像存储身份、挂载后 UUID 校验、主动弹出暂停、手动卸载暂停及容器挂载保护。准备入口不执行全局维护，不清理副本，不重签真实应用。单次系统命令最多 20 秒，同一执行器有 45 秒命令预算，锁最多等待 5 秒；文件检查与 SMB 连接仍遵循既有独立进程时限。写命令未确认退出时继续持锁等待，不能为启动超时而留下失控写进程。

## Alternatives considered

- 依赖登录代理定时重试无需修改启动器，但用户点开软件时数据未必已就绪，也无法消除首次错误提示。
- 把挂载命令直接编入启动壳可以减少辅助进程，但会复制映像身份、SMB 重连、容器记录及暂停规则；复用主程序无窗口服务可以保持这些规则一致。
- 先启动应用再后台接回数据看似更快，但应用可能先创建新数据或报错；只有准备完成才转发启动。

## Consequences

通过新版原生 portal 打开、且映像可恢复时，不显示存储提示。连接失效、缺少凭据、需管理员权限或数据卷核对失败时不启动真实应用，记录失败并显示提示。准备失败不删除映像；不要求 AppPorts 界面运行，但本机 AppPorts 程序须仍可执行。正常启动增加辅助进程和少量状态检查；恢复共享或映像会增加等待，不能承诺固定秒数。

旧入口需要在映像在线时由新版 AppPorts 刷新后才具备能力。直接打开外部真实应用、仅迁移数据而仍直接运行本机原应用、普通符号链接入口和 iOS bash 包装入口不经过本轮原生 portal，因此不提供启动拦截。数据映像由当前已保存应用库记录关联；更换到另一数据映像后，没有持久化映像线索的旧数据记录仍依赖原有后台恢复。若需要跨多个历史数据映像恢复，应扩展独立的映像索引，不按同名物理卷猜测。
