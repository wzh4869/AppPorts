# Agent Note: 状态统计切换为精确目录筛选

Status: implemented

> 迁移自合订归档 AppPorts-调查大合订-20261009 / 原始报告快照/I/实施验收/implementation/summary-filter/README.md（S040）
> 早期方案来源：同归档 / 原始报告快照/I/实施验收/implementation/summary-navigation/README.md（S041）。

## Problem

目录很多时，用户点击已链接或挂载迁移统计，需要直接看到对应项目。仅滚动到第一项仍混着大量其他状态；若统计跟着快速筛选变小，又会失去切换到其他状态的入口。

## Decision

应用数据的状态统计按钮切换精确匹配行，保留路径上下文，和搜索及原有过滤取交集。统计数字基于快速状态筛选前的列表，保持其他状态可选；重复点击或清除筛选恢复未限定状态的列表。切换应用或页签重置快速选择。

筛选只影响呈现，不改变目录发现、迁移权限或记录状态。行只因与匹配项存在祖先关系，不应被误当作匹配业务目录。

## Related decisions

- 路径上下文、归属与统计含义由[容器归属、个人目录链接与大小显示](2026-10-01-container-ownership-presentation.md)约束。

## Alternatives considered

- **只展开并定位第一条匹配项**：早期实现保留全列表和周围语境，并支持重复定位；但用户仍需在混杂状态中查找其他匹配项，后续改为精确筛选并保留路径上下文。

原文档未记录第二个独立候选方案，不将普通清空筛选操作冒充当时另行评估的方案。

## Consequences

状态入口提供可重复、可切换的聚焦视图，搜索与既有过滤仍有效。代价是同时维护基础统计与当前可见行集合，并处理应用/页签切换后的旧选择，防止看似丢失目录。

## Verification

来源记录 23 项目录树测试和 3 项渲染测试通过；实际 NSTableView 有一个分区、两条匹配目录且都可见。较早 19 项定位测试只验证早期滚动行为，不能替代最终筛选验收。核对入口为 `DataDirsView`、`DataDirTreeTests` 和目录呈现测试；此次没有重新运行 UI 测试。
