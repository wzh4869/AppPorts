# Agent Note: 设置中的关于与更新渠道

Status: implemented

渠道偏好与双源检查的决定由[统一版本检查与更新方式选择](2026-10-26-统一版本检查与更新方式选择.md)取代；关于窗口复用仍有效。下文保留该阶段选择渠道的依据。

## Problem

更新入口位于关于窗口，用户需要先打开项目信息才能检查版本。原有检查同时等待 GitHub 和官网，GitHub 不可达时会拖慢国内用户的检查。

## Decision

设置提供关于按钮及独立更新区。关于按钮与系统应用菜单复用 `AboutWindowController.shared`，使两个入口定位同一个窗口。当前版本发现统一读取文档站，安装方式在发现新版后选择，具体契约见[统一版本检查与更新方式选择](2026-10-26-统一版本检查与更新方式选择.md)。界面不再读取旧渠道偏好。

初始渠道方案的动机是让国内检查不依赖 GitHub：单渠道查询、默认官网与保存偏好一起提供隔离。后续方案保留国内版本发现的独立性，将选择延后到安装阶段；这里仅保留该取舍的背景，不将旧渠道接口描述为当前界面流程。

GitHub 附件下载及安装由[GitHub 应用内更新](2026-10-26-GitHub应用内更新.md)负责；国内官网下载入口沿用网站地址。

## Alternatives considered

- 继续并行检查两个来源可自动挑选更高版本，但仍需要等待不可达的 GitHub 来源，不能保证国内渠道独立工作。
- 为两个渠道各放一个检查按钮可直接操作，但无法让启动检查沿用用户选择，因此采用持久化渠道选择和统一检查按钮。

## Consequences

用户可以在设置内完成检查并打开同一个关于窗口。代价是仍需维护设置和系统菜单两个入口的一致性；版本发现的可用性和来源差异由后续笔记持有。

相关历史笔记关键词检索没有发现相同的关于窗口复用决定；旧版更新锁笔记属于应用迁移锁机制，与本项无关。`f46d05a` 和 `aeb6334` 提供渠道演变依据；旧渠道测试不代表当前界面仍使用渠道偏好。本次只核对源码，窗口交互未重新验证。
