# Agent Note: 设置中的关于与更新渠道

Status: implemented

## Problem

更新入口位于关于窗口，用户需要先打开项目信息才能检查版本。原有检查同时等待 GitHub 和官网，GitHub 不可达时会拖慢国内用户的检查。

## Decision

设置提供关于按钮及独立更新区。关于按钮与系统应用菜单复用 `AboutWindowController.shared`，使两个入口定位同一个窗口。更新区通过 `UpdateChannel` 选择 GitHub 或国内官网，`UpdateChannel` 偏好默认使用官网并保存在 UserDefaults；手动检查及启动检查均显式传入选择的渠道。国内渠道使用既有官网 latest.json 与代码定义的国内下载地址，检查过程不请求 GitHub。

`UpdateChecker` 不传渠道时保留原来的双源比较能力，兼容现有调用契约；应用界面入口使用单渠道。渠道切换清空上次结果，检查期间禁用切换与重复点击，所选渠道失败时反馈失败，由用户选择另一渠道重试。

GitHub 附件下载及安装由[GitHub 应用内更新](2026-10-26-GitHub应用内更新.md)负责；国内官网下载入口沿用网站地址。

## Alternatives considered

- 继续并行检查两个来源可自动挑选更高版本，但仍需要等待不可达的 GitHub 来源，不能保证国内渠道独立工作。
- 为两个渠道各放一个检查按钮可直接操作，但无法让启动检查沿用用户选择，因此采用持久化渠道选择和统一检查按钮。

## Consequences

用户可以在设置内完成检查并进入对应下载页面，国内渠道不依赖 GitHub 连接。渠道之间的发布版本可能不同，单渠道检查只报告该渠道的版本；原有禁用 GitHub 的环境变量和偏好仍生效。

相关历史笔记关键词检索没有发现相同的更新渠道决策；旧版更新锁笔记属于应用迁移锁机制，与本项无关。定向验证使用 `UpdateCheckerTests`，新增用例检查渠道隔离及国内失败时不访问 GitHub；窗口交互仍需要真实应用确认。
