# Agent Note: 侧栏导航与存储空间展示

Status: implemented

## Problem

横向导航、共用存储路径和页面搜索连续占用多行，减少应用与数据列表的可见高度。用户还需要在操作时查看本机和目标目录所在卷的空间。

## Decision

主页面采用可调宽度的原生分栏。左侧承载四个导航项、任务中心、刷新、设置及底部存储操作；内容区只保留当前页面的搜索、筛选和必要的业务操作。继续保留已访问页面和现有刷新分发，不改变 externalDriveURL 的共享规则。

任务中心入口直接读取已观察的 `MigrationTaskCenter`：数字徽标表示排队和执行中的未结束任务数，归零时隐藏；存在需要处理的任务时独立显示警告标记。任务完成历史不计入数字，不另设侧栏计数状态，以保持提交、完成及重试后的显示与任务列表一致。

空间从本机数据卷及目标目录所在卷的系统容量属性读取，不遍历目录。读取放在后台，每 30 秒刷新，切换目标后放弃过期结果；失败显示无法读取，不用零代替未知值。已用为总容量减可用空间，百分比限制到 0–100%。映像内空间明确标为映像内空间，不冒充 NAS 容量。展示值不参与迁移准入或删除授权。

## Alternatives considered

- 顶部存储工具栏无需缩窄列表，但继续增加纵向占用，因此采用侧栏。
- 扫描文件夹大小能描述目录自身占用，但不是其所在磁盘的剩余空间，且在 SMB 上会产生大量访问，因此读取系统卷容量。

## Consequences

导航和共用存储操作不再占用内容区顶部；侧栏底部显示本机及所选目录所在卷的已用、空余和使用率；无目标和读取失败有明确状态。隐藏页面仍暂停扫描，目录迁移页保留独立目的地，不显示共用目标。侧栏可调整宽度；正文区保留 660 点最小宽度以容纳两个应用列表。

侧栏减少横向可用宽度，使用可调分栏与最小宽度保留双列表操作空间。APFS 共享容量、可清理空间和虚拟映像会影响系统容量口径；只展示系统报告，不把它当作迁移后释放空间的证明。

卷属性查询在后台运行，不能保证系统内核中的网络文件系统查询在固定时间内返回；切换目标后取消旧任务的发布，本机数据先独立发布。`/Volumes` 下的路径必须仍属于实际挂载卷，避免将离线挂载点的本地目录统计为目标空间。

## Verification

本次只执行 Swift 语法解析、本次文案的中英文目录静态核对和笔记结构检查，不执行编译。原生应用中的窄窗口布局、分栏拖动、页面切换、容量刷新及挂载状态变化仍需实际确认。

## Compiler compatibility

PR #102 的提交 `1e2f3c1` 在 GitHub runner 的 Xcode 26.6 上，Release 及 Debug 测试包都于 `SidebarStorageSection` 容量文字 HStack 报类型检查耗时过长；本机 Xcode 27 构建通过不能证明该工具链兼容。CI 的 Advisory 任务为绿色，但测试包未构建成功，测试没有执行。

容量摘要拆为同文件私有函数，先以明确的 String 类型完成空余、已用、总容量格式化和提示文字拼接，再构造 HStack。字符串键、显示顺序、间距、字体修饰和 help 均保持原样；不改变容量读取、估算、迁移和缓存规则。此次只修复编译兼容性，不新增运行时机制或测试。

本机 Xcode 27 的 arm64/x86_64 Release clean build 通过，日志为 `/tmp/AppPortsPR102Typecheck/release.log`；笔记树、格式与差异空白检查通过。Xcode 26.6 的 Release、Debug 测试包和全量回归交给 PR CI 验证，不以本机通过代替；未重新运行迁移实机测试，未安装或发布。

修复后的 CI 测试包越过侧栏代码，随后在原有 `DirectorySizeTraversalTests` 的泛型 XCTAssertEqual 算术表达式暴露同类类型检查超时。夹具的稀疏文件长度与期望总长度使用明确的 UInt64/Int64 局部值，复用同一稀疏长度，不改变文件大小、断言数值或验证范围。提交 `0503d11` 的 Xcode 26.6 Release CI 已通过，确认侧栏编译错误消除。本机最终 Debug 测试包构建通过，独立宿主执行目录遍历专项 3 项通过、1 项需显式启用的性能测试按预期跳过；日志及结果包位于 `/tmp/AppPortsPR102Typecheck/`。
