# Agent Note: SMB 上的 APFS 应用库映像

Status: implemented

## Problem

直接向 SMB 共享复制应用受服务端权限和元数据能力限制。已挂载的网络共享也不能通过 diskutil 的物理卷查询判断在线。需要让用户在共享中创建 APFS sparsebundle，并将其挂载卷交给现有应用迁移事务。

## Decision

外部应用库提供创建、打开、重新挂载映像入口。复用系统映像工具和现有命令执行器；创建不覆盖已有路径。创建时探测 `diskutil image create blank --help` 是否支持 UDSB，支持时使用现代创建接口和精确字节容量，否则使用旧系统的 hdiutil。挂载同样探测 DiskImages2，否则使用 hdiutil；现代接口执行失败不自动切换后端。通过 hdiutil 的映像设备关系及 diskutil 的 APFS UUID 核对目标，不按卷名称接受目标。

本地保存最近映像路径、独立挂载位置及已确认卷 UUID。启动 AppPorts 且当前应用库仍指向该映像时尝试重新挂载。仅管理应用库，不新增后台登录服务，不改变沙盒数据迁移方式、签名原包选盘或物理磁盘弹出规则。失败保留映像，不自动删除、强制卸载或修复。

新映像的挂载目录直接使用映像文件名，例如 `AppPorts.sparsebundle` 对应 `/Volumes/AppPorts`。路径冲突时停止并报告被占用的路径，不附加随机后缀。历史记录中的既有挂载路径继续有效，不自动改名或卸载，避免破坏已迁移应用的入口。卷 UUID 仍用于核对身份，不依赖目录名证明身份。

## Existing notes

- [签名原包选盘](../../implemented/architecture/2026-10-15-signature-backup-volume.md)：相邻但独立，仍排除磁盘映像，因此需要重签名的应用可能仍需合适的物理外盘保存原包。
- [物理磁盘弹出](../../implemented/feature/2026-10-23-explicit-disk-ejection.md)：相邻但独立，不将映像伪装为可弹出的物理外盘。
- [文档组织](../../implemented/architecture/2026-10-15-reader-first-docs-structure.md)：记录历史映像实验，不是本次应用库映像的实现契约。

## Alternatives considered

- 直接复制到 SMB 最简单，但仍受共享的元数据能力限制，因此提供显式的 APFS 映像路径。
- 完整接入沙盒原位挂载及登录后台服务可以覆盖更多使用场景，但增加数据迁移和卸载生命周期的范围；本轮限定为应用库，先验证系统映像方案。

## Consequences

外部应用库的“磁盘映像”菜单提供创建、打开及重新挂载入口。底层仍使用现有应用迁移事务，应用通过 APFS 保存文件元数据；用户需要管理映像容量与挂载生命周期。命令使用参数数组，不拼 shell；已有目标不覆盖；只有来自选定映像的单个可写 APFS 卷且 UUID 符合记录才成为应用库；失败保留文件并显示错误；共享不可用时不创建本地替代目录。新文案提供中英文，其他语言沿用既有回退，翻译审计只对这批明确列出的键放宽到中英文，不填英文占位。

创建失败可能留下部分映像，需要用户在 Finder 检查或重新命名；不会替用户判断残留文件是否可以删除。

旧版创建接口在当前 macOS 上实际返回“RPC 版本错误”，并提示改用 `diskutil image create blank`。错误弹窗保留系统错误末行，而不再把所有失败指向剩余空间；这项日志证据不能解释为 NAS 空间不足。

已创建的 SMB 映像在系统中实际提供 `WritableVolume = true`，不提供 `ReadOnlyVolume`；可写性检查使用前者并要求明确为 true。缺失属性或只读卷继续拒绝，映像来源、唯一卷和固定 UUID 的核对不变。

## Verification

隔离测试覆盖映像路径匹配、重复附件拒绝、已附加但未挂载的区别、名称/容量边界、新旧系统创建后端、10 GiB 的精确字节参数及失败不跨后端重试。加入实际 WritableVolume 属性与替代 UUID 的回归后，Debug 定向执行 11 个测试全部通过。本地化审计 19 个测试中 17 个通过，2 个因已有非映像文案的 stale 标记失败；本次映像文案的键、覆盖及占位符检查通过。Release 测试首次因未启用 testability 而未执行，随后使用项目规定的 Debug 配置执行上述定向测试。

Swift 语法解析、字符串目录静态核对和笔记结构检查通过。初次经授权运行 Release `xcodebuild clean build`，arm64 与 x86_64 编译成功，关闭正式签名，产物位于 `/tmp/AppPortsSMBBuild/Build/Products/Release/AppPorts.app`。

编译发现菜单与弹窗的两条创建文案只差省略号，Xcode 为其生成相同的本地化符号。两处现在共用“创建 APFS 映像”键，不关闭整个项目的符号生成，也不保留重复目录项。真实 SMB 创建、挂载及迁移仍未实测。

## Limits

真实 SMB 映像已由用户创建并挂载，Agent 只读检查 hdiutil 映像设备关系及 diskutil 的 APFS 卷信息，确认挂载卷可写；修复后的完整界面及迁移流程尚未实测。不在应用退出时自动卸载，因为迁出的应用可能仍在运行；需要映像时先打开 AppPorts，或在 Finder 手动挂载。同一映像不能供多台 Mac 同时写入。映像损坏和网络 I/O 仍需要独立备份保障。
