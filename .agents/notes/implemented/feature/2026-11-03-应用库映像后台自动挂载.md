# Agent Note: 应用库映像后台自动挂载

Status: implemented

## Problem

应用库映像只在界面第一次出现时尝试恢复，退出主程序后无人处理外部存储断线和登录后的挂载。仅记录本地映像路径也无法识别重新连接后改变了挂载目录的 SMB 共享或本地外置卷，包括 exFAT 硬盘和 U 盘。

## Decision

前台创建、打开、手动重挂以及自动恢复的运行位置检查见[按操作检查安装位置与普通入口独立启动](../bug-fix/2026-11-04-按操作检查安装位置与普通入口独立启动.md)。后台代理的恢复调度职责保持不变。

原生启动入口的按需准备见[启动迁移应用时静默接回映像](2026-11-03-启动迁移应用时静默接回映像.md)，独立于登录代理定时重试，只接回本次应用所需的映像及数据。

映像内卷定位沿用[按所选映像使用应用库卷](../bug-fix/2026-11-03-按所选映像使用应用库卷.md)，不再要求只有一个可写 APFS 卷，已有未挂载附件也可直接定位使用。

已有未挂载附件和退出等待的限制由[映像残留附件恢复与退出等待上限](../../implemented/bug-fix/2026-11-03-映像残留附件恢复与退出等待上限.md)部分收窄：已保存 APFS UUID 的附件核对成功后可原地挂载；退出等待超时会取消本次退出并提示重试。

现有无窗口挂载代理在选中映像时增加每 60 秒一次的系统触发，登录与卷变化触发继续有效。映像记录保存容纳映像的存储身份及映像相对路径：SMB 使用共享地址，本地外置卷使用 `backingVolumeUUID`，与映像内部 APFS 的 `volumeUUID` 分开。旧记录只在挂载服务完成映像 APFS 身份核对后补齐并保存；后台提前看到“已有挂载点”不足以升级旧记录。同名路径上的映像核对失败时，原记录必须保持原样。已保存的存储身份不因同名路径被别的磁盘占用而重新捕获。只恢复当前选中的应用库。共享重连通过带超时的独立 NetFS 进程执行，禁止认证界面，凭据交给系统处理。复用操作锁和卷 UUID 核对，不强制卸载、修复或重复附加残留设备。

本地存储定位位于映像挂载服务共用的底层：枚举已挂载卷，要求唯一匹配存储 UUID，再按相对路径找映像。磁盘缺失或 UUID 匹配不唯一时失败，不回退到同名旧路径。挂载前再次核对映像所在卷身份，挂载后沿用 APFS 身份校验；前台手动重新挂载也使用同一定位逻辑。USB 和 SMB 路径变化时均拒绝仍有旧路径附件的重复写入挂载。后台另行读取磁盘弹出暂停快照，读取失败或该盘暂停时不挂载映像，恢复暂停仍由现有物理重连接机制决定。

### Read-only probe boundary

映像先以 `--noMount` / `-nomount` 附加，再核对 APFS UUID，最后挂到应用库路径。hdiutil 仅列出 APFS 物理存储时，通过 diskutil 的 PhysicalStores 关联查找实际卷，不按卷名猜测。核对或挂载失败仅清理本次新附加且设备集合未变化的映像，使用非强制 detach；已有附件不接管、不卸载。附加后无法读取设备身份时保留未挂载附件，交由人工检查。写进程仍可能运行时不启动清理。

只读边界同时处理命令返回残留进程和取消时抛出未确认退出异常两条路径。SMB 共享恢复先于内部 APFS 查询，避免内部卷等待底层网络导致恢复顺序倒置。取消中的写进程等待使用独立休眠任务，避免取消令休眠立即失败而忙循环。

`AppLibraryAgentSync` 持有选择同步任务，快速切换选择时串行补做最新一轮，不取消已开始的配置写入。正常退出和更新退出均等待该任务结束，再重新检查退出条件；界面销毁不再丢失任务。

`AppLibraryImageFileAccess` 将卷枚举、源目录属性、路径占用、挂载 UUID 和存储身份捕获统一放进 `--inspect-library-image` 子进程，每次查询上限为 10 秒。生产服务不直接对 NAS 执行同步文件属性查询。请求和响应使用受大小限制的 Codable 数据；检查进程不创建、挂载、删除或修复用户文件。超时或未确认退出的只读检查返回普通读取失败，不进入挂载写进程的无限等待分支，因此不会长期保留全局操作锁。hdiutil / diskutil 的只读信息查询也采用此退出分类。真正创建或附加映像的写命令仍必须确认退出后才能释放锁。

只读检查由 `AppPortsEntryPoint.main` 在 `AppMoverApp.main()` 之前处理并退出，不初始化 SwiftUI 状态，也不登记写入进程。成功响应的标准输出只包含 JSON；写入登记回收旧记录时会输出日志，若先登记再检查，日志会混入响应，使打开映像、重新挂载和启动恢复均报数据格式错误。

目标文件夹变化后异步同步代理状态，等待锁期间可取消；取得锁后重新读取当前偏好，按最新选择安装、更新或卸载代理。操作锁暂时忙时继续等待，锁不可用或写入准入失败时停止。本路径覆盖选择普通文件夹后再次选中已记录映像的情况。前台 controller 在取得操作锁后刷新持久化映像记录；打开映像的复用判断、重新挂载和启动恢复均基于刷新后的记录，避免后台重定位被旧缓存覆盖。

## Alternatives considered

- 只在前台定时检查实现简单，但无法覆盖主程序退出后的恢复。
- 新建独立常驻服务可即时监听唤醒和网络，但需要另行管理后台服务生命周期；现有代理配合系统定时启动即可持续重试。
- 按磁盘名称或旧路径找文件无需保存卷身份，但外盘改名及同名 U 盘会使路径失效或指向另一个存储，因此按 UUID 查找，不能唯一确认时停止。
- 用 Task 取消或竞速超时包裹同步文件属性查询无需额外进程，但不能中断阻塞在内核中的 NAS 读取，也无法保证释放原任务持有的操作锁。独立只读进程增加启动成本，但能将读取失败与仍在写入的挂载命令分开处理。
- 在接收端跳过日志、截取 JSON 可以兼容混合输出，但会掩盖启动副作用并放宽响应格式；将只读入口提前可以直接保证响应独立，同时避免不必要的写入登记。
- 把映像恢复整体移到容器卷恢复之前实现最简单，也能让映像内的容器卷第一轮就出现；但慢速或离线 NAS 会推迟物理盘上容器卷的恢复。因此只在仍在等待的容器卷位于选中映像内时提前恢复映像。

## Consequences

仅映像也会保留代理，主程序退出后仍可重试。SMB 地址不落盘密码，重新连接后按相对路径定位；未选中的映像不自动挂载。即使 APFS 设备仍显示挂载，也检查其已记录的 SMB 共享是否存在，缺失时恢复共享。前台映像操作与后台共用 OperationLock，残留旧附件不重复附加；写进程未确认退出时继续持锁。创建、打开成功先持久化当前选中路径再注册代理，避免 SwiftUI 延后保存导致代理被误卸载。

每次文件检查可能额外启动一个只读进程，正常恢复需要多次检查，存在进程启动和注册开销；10 秒是单次读取上限，不是整轮创建或挂载操作的总时限。失联后设备仍残留挂载记录的情况继续保守处理，不通过强制卸载来伪装恢复成功。

容器卷原有恢复优先执行，NAS 操作随后进行，因此容器卷仍在等待恢复时，映像检查可能晚于系统定时触发。例外是仍在等待的容器卷位于当前选中映像的应用库路径内：这类卷在映像附加前不会出现，代理在该轮挂载后立即恢复映像，并在同一轮重试挂载，不再等满 180 秒窗口。每轮最多恢复一次映像，其他容器卷的顺序不变；映像恢复失败时仍按原窗口等待，下一轮再试。退出的代理由 launchd 再次触发，运行期间的定时触发不叠加进程。代价是最多每分钟产生一次后台检查，网络恢复和唤醒后不保证立即就位。没有选中映像的代理定义不增加定时触发。

系统凭据不可用时需在 Finder 重新连接；旧记录需要存储在线时运行一次新版以补齐身份。本地底层磁盘由 macOS 挂载，代理不负责强行挂载未加载的分区或解锁加密设备。无法取得底层卷 UUID 的本地记录仅能按原路径尝试，不能保证改名后的恢复；仍核对映像内部 APFS UUID。残留设备需要人工检查，不能把自动挂载视为断线期间的数据保护。当前仅支持一个选中的应用库，不自动恢复任意历史映像。

## Verification

只读入口提前后的两个 Swift 文件通过 `swiftc -frontend -parse` 语法检查；静态入口顺序检查确认检查进程先于 `AppMoverApp.main()` 执行，普通应用的写入登记仍保留。此修复未构建、安装或执行真实映像挂载，仍需使用新版确认打开已有映像、重新挂载及启动恢复。

补充只读命令直接抛出未确认退出异常、未挂载映像 UUID 错误时不占用应用库并清理自有附件、APFS 物理存储关联以及退出等待代理同步的隔离回归用例。新增协调器、修正后的服务和回归用例通过隔离依赖桩类型检查，测试用例未执行。

增加隔离测试用例，覆盖已挂载时不重连、共享离线后持续重试且保留记录、共享换路径但旧附件残留时拒绝重复附加、凭据清理、路径越界、旧记录兼容、选择条件和代理定时触发。本地卷补充重插后路径变化、同名异盘和重复 UUID 拒绝、已捕获身份不被覆盖及主动弹出暂停用例。测试只使用独立偏好域及注入的命令和存储边界，不操作真实共享或代理。

审查后的回归用例补充旧映像核对失败不保存身份、成功才补齐身份、只读检查超时不按未退出写进程处理、后台重定位后前台刷新及等待锁后按最新选择重新生成代理定时配置。既有映像测试显式注入本地文件检查边界，避免测试宿主启动真实检查进程。

本次 7 个应用源文件及 3 个相关测试文件通过 Swift 语法解析。隔离依赖桩下的类型检查覆盖映像服务、恢复模块、只读检查模块、前台 controller、代理选择同步及新增回归用例，使用真实 macOS SDK 的 Foundation / NetFS / SwiftUI 接口及 Swift Testing 宏；检查没有生成应用或测试二进制，不代表完整应用编译或测试执行通过。94 篇笔记通过目录、链接及格式门禁。新增测试尚未执行，未构建、安装或访问真实 NAS；登录、休眠唤醒、系统凭据、真实断网恢复和 U 盘插拔仍需实机验收。

恢复顺序补充隔离用例：映像内容器卷第一轮未就位时先恢复映像，再在同一轮重试；映像外的卷、已就位的卷、需人工处理的卷及让路轮次不触发恢复；每轮最多恢复一次，且只针对选中映像；重挂循环在映像接回后直接结束，不等待目录变化。代理源码接线审计用例继续通过。真实登录时映像内数据卷的恢复耗时尚未实机验证。
