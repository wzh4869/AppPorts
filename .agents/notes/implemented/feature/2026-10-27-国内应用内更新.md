# Agent Note: 国内应用内更新

Status: implemented

## Problem

更新窗口的国内入口只打开 OpenList 页面。GitHub 不可达时，用户无法在应用内完成下载、校验和安装，还需自行处理下载隔离。

## Decision

国内更新通过固定 HTTPS OpenList `/api/fs/get` 查询 `/AppPorts/AppPorts{version}.dmg`，只接受窗口所示版本的非目录文件。包大小和 HTTPS 存储直链来自站点接口，SHA-256 来自同一版本的官网 latest.json；缺失或无效散列时不下载，不借用 GitHub digest，不把 OpenList sign 当作内容校验。安装沿用现有准备、隔离属性处理、独占锁、退出替换、启动确认和恢复流程。

## Alternatives considered

- 在 latest.json 配置直链可以跳过文件站 API，适合永久静态地址；当前站点解析至对象存储地址，继续使用 OpenList 解析可避免把存储地址作为发布契约。
- 通过 GitHub 获取同名 DMG 的 digest 能复用已发布校验信息，但国内更新会再次依赖 GitHub 可达性，因此使用官方国内版本信息的散列。

## Consequences

国内更新在应用内下载且不依赖 GitHub，安装仍需用户点击“安装并重新启动”。准备包共用大小与 SHA-256 校验，再检查 bundle ID、版本、架构、系统要求和已有签名完整性；仅从验证后的应用移除 quarantine。失败时在操作按钮下方提供原国内下载页面，避免三种动作挤在同一行。现有 GitHub 名称大小写兼容性保留，国内包名继续精确匹配。

OpenList API 和 `AppPorts{version}.dmg` 命名是新增依赖；当前只解析该命名的通用 DMG，未来拆分架构或更换包名需要扩展显式契约。发布方必须确保版本、DMG 和散列一致；更新本地 feed 不会发布线上站点。HTTPS 与版本信息散列不构成独立的发布签名，站点完全失陷时不能提供独立身份保证。下载对象存储地址可以变化，但必须使用 HTTPS、无内嵌凭据，包必须匹配官网散列。

历史审计中，[GitHub 应用内更新](2026-10-26-GitHub应用内更新.md)的来源校验、准备、隔离处理及安装恢复约束继续成立，本篇扩展下载源；[统一版本检查与更新方式选择](2026-10-26-统一版本检查与更新方式选择.md)的默认版本发现及 GitHub 按 tag 解析继续成立，国内网页入口由本篇扩展为应用内更新及失败时手动下载。其余 latest.json 记录涉及文档站部署，与本决定无关；无完全吸收或过时的提案。
