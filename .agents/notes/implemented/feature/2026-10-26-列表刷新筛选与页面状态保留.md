# Agent Note: 列表刷新筛选与页面状态保留

Status: implemented

## Problem

应用、工具目录、应用数据和自选目录的刷新入口分散，人工大小重测不易发现。原先隐藏已迁移项的开关也不能单独查看已链接应用。切换页面时若销毁视图或对整棵列表施加动画，会影响页面状态与列表更新的呈现。

## Decision

`ContentView.cacheRefreshButton` 按当前页面分发刷新：应用页调用 `scanBothAppsAtomic(forceSizeRefresh: true)`；数据目录和自选目录通过各自的 `refreshTrigger` 请求强制重测。子页面向父页面报告扫描状态，按钮在当前页扫描或操作阻止交互时禁用。应用两侧面板仍保留各自的刷新入口。

应用页使用“全部 / 已链接 / 未链接”筛选，并与搜索和既有签名筛选组合。“已链接”严格对应 `AppStatus.linked`，“未链接”是其补集，不表示应用一定在本地。切换筛选后将两侧选择集合收窄到当前可见项，避免批量操作隐藏的已选应用。名称、大小排序与行布局复用 `AppListColumns`，不改变迁移服务的授权边界。

应用页持续保留；数据目录和自选目录在首次打开后保留。`AppPageVisibility` 只对可见性做淡入淡出，隐藏页不响应点击且不进入辅助功能树；数据页面继续通过 `isActive` 暂停扫描。列表事务关闭隐式布局动画，按钮反馈复用 `AppPressButtonStyle`，两者尊重系统减少动态效果设置。保留视图不能代替扫描取消及过期结果检查。

页面动画与同上下文刷新呈现的后续调整见[页面切换与目录列表显示](../bug-fix/2026-10-29-页面切换与目录列表显示.md)，本篇其余生命周期、权限和加载态约束继续适用。

## Alternatives considered

以下对照提交中的旧实现与当前实现，不将源码比较当作原作者讨论记录。

- 各页面独立放置缓存刷新按钮：入口能贴近各自内容，但用户需要在不同区域寻找相同操作，因此主导航提供按当前页面分发的统一入口。
- 仅提供隐藏已迁移项开关：控制简单，但无法只看已链接项，因此改为三个互斥筛选值。
- 切换时重建应用页并对整个容器使用动画：视图生命周期较短，但列表布局也会进入动画范围，因此保留页面并将动画限制在透明度和按钮反馈。

## Consequences

刷新入口和状态集中，隐藏选择不会继续参与批量操作。代价是父子页面需维护刷新触发和扫描状态契约，保留页面也会保留内存中的列表及扫描快照。缓存仍可能陈旧，人工刷新继续承担重测；页面常驻不允许隐藏页持续扫描。

## Verification

实现依据为 `aa82e80`、`b716357` 及当前 `ContentView`、`CustomDirsView`、`AppMotion`。本次仅核对源码并校验笔记，未重跑应用测试；筛选后批量选择、各页刷新状态、页面切换和减少动态效果需要在真实应用中确认。
