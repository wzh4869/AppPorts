# Agent Note: ShipIt 更新失败后自动安装缓存新版

Status: implemented

## Problem

2026-11-15 DeepSeek Harness 的 ShipIt 先把外盘旧版移到本机临时目录，再复制新版回外盘时收到 EPERM。相同时刻的系统日志显示可移动宗卷 TCC 授权因 attribution chain 构造失败而失败。旧版与完整新版仍在更新目录，原目标缺失。仅观察本机新版或以符号链接代替启动壳不能处理这个已发生的故障。

## Decision

本篇仅主进程运行、不注册更新代理的范围由[后台更新守护与主窗口设置](2026-11-16-后台更新守护与主窗口设置.md)扩展。自动执行位于无窗口代理，主界面观察结果；恢复安装的证据、签名、路径与收据规则保持。下面保留首次实现的运行范围、理由和实机验证，后台服务的验证单独记录。

本篇首次实现中“仅填补缺失目标、不替换现存旧版”的限制，由[旧版保留失败接手与安装状态收尾](2026-11-15-ShipIt旧版保留与更新状态收尾.md)扩展；其余复制、缓存保留和调度原则继续适用。

首次实现的固定五秒轮询由[ShipIt 事件触发检查](2026-11-15-ShipIt事件触发检查.md)替换。AppPorts 主进程在受管应用对应的 ShipIt 状态和日志变化时检查，启动及系统通知补查，只有未完成候选恢复才五秒重试，不依赖当前可见页面。仅接手已明确失败并退出的更新器；正常更新、被用户删除的入口、已迁回记录和脱机卷均跳过。现存旧版仅按扩展笔记的版本、签名与备份规则处理。不注册新的登录代理，主进程完全退出期间不接手，下次启动继续检查。

失败和目标路径按同一次安装尝试关联，不要求出现在同一行。ShipIt 恢复安装失败时，最终错误行可能只有 OSStatus -67068，目标只出现在此前的移动或回退记录；按最后一次安装开始标记截取日志，避免把上一轮失败或其他目标当作当前失败。

自动接手和主动回退从标准错误日志末尾最多读取 1 MiB，在字节中找到最后一个完整的安装开始标记，再解码本轮内容。窗口可能从上一轮的半个 UTF-8 字符开始。缺少完整标记时，守护跳过该候选，回退也不从残片提取旧包路径。安装请求和收据仍须完整读取。

仅安装请求指向的完整缓存应用，不应用增量补丁，不重签应用。Bundle ID、Developer ID 签名和嵌套资源均须校验。来源缓存、旧版临时目录与下载包不删除。操作取得共享 token、全局操作锁和启动保护，目标卷与父目录身份复核后，在同卷 staging 复制、同步、验证，再独占 rename 到缺失目标；绝不覆盖后来出现的文件或软链接。

独立收据记录准备路径、目标父身份、候选 inode 和完成状态。切换前中断只重做自己的准备副本；切换后中断以同一候选身份确认已安装，只补入口和启动。已有入口使用现有刷新实现，手工删除的入口不重建。请求要求重启时调用系统打开真实应用；完成记录避免下一轮重复启动。

## Existing note audit

- 与[持久化迁移生命周期](../../implemented/architecture/2026-10-10-verified-transfer-lifecycle.md)部分重叠：复用复制、验证、锁和持久化切换原则；恢复安装不迁移缓存源，也不删旧副本，不能直接使用移动应用事务。
- 与[入口启动保护](../../implemented/feature/2026-10-24-portal-data-migration-launch-protection.md)部分重叠：沿用共享启动锁，不增加执行拦截。
- 与[旧更新保护锁](../../implemented/bug-fix/2026-10-17-legacy-update-lock-adoption.md)部分重叠：不改变锁定迁移默认值，不自动解锁已有应用。
- 与[后台映像挂载](../../implemented/feature/2026-11-03-应用库映像后台自动挂载.md)职责独立：不改其注册条件和调度。
- proposed 中临时目录、并行复制与迁移引导提案不处理更新器失败，不吸收或撤销它们；未发现同职责的现存提案。

任务中心状态展示与用户主动的干净回退见[ShipIt 任务状态与干净回退](2026-11-15-ShipIt任务状态与干净回退.md)。自动接手仍沿用本篇规则；用户主动回退成功后才清理本次更新材料。

## Alternatives considered

- 提高整份日志的大小上限只能暂时容纳积累的空重试。11 月 21 日的 DeepSeek 日志在安装前已有 66,733,594 字节，本轮安装只新增 3,574 字节；只读末尾即可保留本轮证据及第三方的完整日志。
- 传统整包软链接：改动少，但这次更新器已正确找到外盘路径，仍在写回时失败；不能据此承诺解决权限归属问题。
- 接管所有应用更新或自己处理增量补丁：可覆盖更多情况，但需要兼容不同更新协议、下载验证及重启方式，超出本次实证故障。
- 自动迁出本机新版：可复用已有迁移，但这次本机没有安装完成的新版，只有 ShipIt 缓存，不能覆盖故障。

## Consequences

失败更新可自动从现存完整缓存安装新版并按请求重启，用户无需选择副本或点击恢复；不增加新的常驻服务和更新协议。保留恢复收据和必要暂存材料，当前事件调度的成本与验证边界见事件触发笔记。

AppPorts 本身无外盘访问权限时仍会失败，不能绕过系统首次授权。ShipIt 状态/日志并非稳定公共协议，未知格式保留材料并跳过。主进程完全退出期间无法即时接手，下次启动重新检查。无有效缓存时保留现场，不自动猜测或恢复旧版临时目录；本功能不保证修复所有更新器或 TCC 根因。覆盖其他更新器、完全退出时的接手和无有效新版时的自动回退，需要另行验证和决定。
