# Agent Note: 欢迎页重构与边界共识一次性确认

Status: implemented

## Problem

1. 原版 `WelcomeView` 仍停留在早期软链与 Launchpad 口径，未反映当前版本（Stub Portal 启动壳、容器 APFS 挂载迁移、应用库映像、任务中心与还原）的真实能力，也不适合承载较长的使用边界说明。
2. 维护者需要在应用内明确呈现「关于 AppPorts 的边界与共识」：既要让全新用户和从旧版本升级而来的老用户都至少知晓并确认一次，又要保证确认后不再重复打扰，同时在「设置」顶部卡片中提供随时重看的入口。
3. `LegacyPermissionResetter` 依赖 `UserDefaults` 中的 `welcomeCompleted == true` 区分老用户以在签名变更后自动清理失效 TCC 权限记录；如果通过重置 `welcomeCompleted` 来触发老用户查看边界共识，会破坏旧版权限自愈契约。

## Decision

1. **双键分离与版本化确认（`WelcomeLaunchPolicy`）**：保留 `welcomeCompleted` 原语义不变，新增整型持久化键 `boundaryConsensusAcknowledgedVersion`（当前常量 `currentBoundaryConsensusVersion = 1`）。
   - `welcomeCompleted == false` → 返回 `.fullOnboarding`（完整 3 步欢迎页：① 核心能力概览 → ② 边界与共识 → ③ 准备情况），完成后同时写入 `welcomeCompleted = true` 与 `boundaryConsensusAcknowledgedVersion = 1`。
   - `welcomeCompleted == true` 且 `boundaryConsensusAcknowledgedVersion < 1` → 返回 `.boundaryConsensusOnly`（单屏「边界与共识」），确认后仅写入 `boundaryConsensusAcknowledgedVersion = 1`，不改动 `welcomeCompleted`。
   - 两项均满足时返回 `nil`，直接进入 `ContentView`。
2. **顶层路由承接**：`AppMoverApp` 在挂载 `ContentView` 之前根据 `WelcomeLaunchPolicy.presentationMode()` 决定是否展示 `WelcomeView`，避免老用户一次性确认与 `ContentView.onAppear` 中的权限清理提示、签名替换提醒、版本更新或 App Store 引导弹窗冲突。
3. **单一内容源与确认门槛**：`BoundaryConsensusContentView` 作为唯一正文实现，复用在欢迎页第 2 步、升级老用户单屏模式及设置页 `BoundaryConsensusSheet`。欢迎流程中要求用户勾选「我已阅读并了解以上使用边界与数据风险」才解锁继续按钮；设置页弹窗为只读回顾，无勾选门槛，并接入 `AppUpdatePresentationDismissal` 在进入应用内更新时自动收起。
4. **富文本内联链接与多语言兼容**：`EditorialRichText` 以 `AttributedString` 拼接行内加粗小标题、强调备份提示和可点击外链（官方文档链接按当前界面语言通过 `DocumentationLink.homeURL` 动态解析），避免 `Text + Text` 弃用告警与 CommonMark 在中日文标点边界的解析失败；设置页顶卡按钮行在 macOS 13+ 使用 `SettingsWrapRowLayout` 自动换行，防止长语种（如法语、俄语）在双栏设置窄宽下裁切。

## Alternatives considered

- **重置 `welcomeCompleted` 让老用户重走欢迎页**：实现最简单，但会破坏 `LegacyPermissionResetter` 对老用户的识别前提，且迫使已配置好权限的老用户重复走能力介绍和权限检查，体验割裂。
- **在 `ContentView` 中以 `.sheet` 弹出老用户边界共识**：无需改动 `AppMoverApp`，但会与主界面启动时的旧权限清理、签名替换提醒、更新检查和 App Store 引导弹窗竞争展示，存在弹窗互相吞掉的风险。
- **把边界共识全文直接平铺在设置卡片内**：无需新增 Sheet，但会显著拉长设置页右侧栏并破坏 660pt/940pt 双栏视觉平衡，因此改为按钮 + 只读 Sheet。
- **使用 `AttributedString(markdown:)` 解析整段带加粗的本地化文本**：写法更短，但 CommonMark 在中文全角冒号/标点紧邻 `**` 处存在右边界解析失败风险，且将 URL 暴露在翻译字符串中易被误改；改为 `EditorialRichText` 模板插值后无此问题。

## Consequences

- **收益**：新老用户都只需明确确认一次使用边界与备份注意，且随时可在「设置」重看；欢迎页文案与 2.4.0 实际架构保持一致；不破坏旧版权限自愈逻辑；通过整型版本号保留未来重大修订时重新确认的能力。
- **代价**：新增 26 条界面文案并在 `Localizable.xcstrings` 维护全部 22 种语言；后续若修改边界与共识内容，需同步更新对应多语言翻译，并决定是否递增 `currentBoundaryConsensusVersion`。
