# Agent Note: 特定应用本体迁出需明确确认

Status: implemented

## Problem

Clash Verge 2.5.5 在独立 APFS 卷启动时要求替换本机入口，取消后直接退出。开发者工具移走也可能影响使用它们的工具链。维护者希望 Clash Verge、Visual Studio Code、Xcode 和 Claude 桌面端默认留在本机，并保留用户自行决定迁出的选项。VS Code、Xcode 与 Claude 桌面端属于产品预防策略，本轮没有观察到这几款的实际运行故障。

## Decision

普通迁出和整包符号链接迁出共用风险选择，按包标识识别 Clash Verge、VS Code 正式版和 Insiders、Xcode 及 Claude 桌面端（`com.anthropic.claudefordesktop`）。选择取消不开始任何迁移，混合批次可只移动其余项。整文件夹是一个迁移单位，包含受限应用时整个文件夹随该选择处理。用户选择“无视风险迁移”后，界面只向本次任务传递确认过的包路径。迁移服务在复制前复核，直接调用服务默认也需要确认。

对于 AppPorts 自身，包标识对应独立的本机安装策略。列表在应用名下显示「自有」，点开说明其自有更新机制及安装位置要求。选择迁出时先展示说明，混选时只允许继续处理其他项目。服务在复制前复核包标识，风险确认无法放行 AppPorts。未切换的旧迁出记录在重试时也复核，已经切换的记录仍可清理。

「应用数据」页按同一身份排除 AppPorts，列表、搜索和容量统计共用过滤后的应用集合。同名的其他应用仍可查看数据。

风险名单上的应用省略更新状态徽章；运行、链接、锁定状态仍按实际情况显示。列表和迁移服务从同一包标识策略判断，更新框架和守护开关均不改变名单。

## Alternatives considered

完全禁止迁出能避免误操作，但会阻止已了解限制的用户选择外盘。让 AppPorts 也使用这一放行入口会允许用户迁出管理程序本身，与本机安装要求冲突，因此为其单独限制。保存永久偏好可减少再次确认，也会把一次授权扩展到后来选择的其他应用。采用当次显式放行，批次中的正常项目仍可继续。

## Consequences

更新可用性描述安装新版的路径，应用本体能否迁出单独判断。迁回本机、链接已有外盘副本、迁移应用数据仍使用原流程。实际运行表现已观察到的范围仅为 Clash Verge 2.5.5，在隔离机取消厂商移回要求后，外盘旧包签名有效。

## Verification

由迁移事务测试覆盖改名的应用、同名的普通应用、包含 Insiders 的文件夹、混合选择、默认拒绝后的两处文件状态、显式放行的真实迁出与无额外确认的迁回。

macOS 15.7.7 隔离机通过实际 AppPorts 窗口迁出改名后的厂商签名 Clash Verge 2.5.5。取消后本机仍为完整应用，目标库没有副本。点击“无视风险迁移”后外盘副本签名有效，本机变为入口；在界面迁回后本机恢复为原签名完整应用。VS Code 与 Xcode 使用带对应标识的测试包验证拦截与往返，没有迁移用户的开发环境。
