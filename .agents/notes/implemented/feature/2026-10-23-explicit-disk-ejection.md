# Agent Note: 主动弹出外盘时暂停恢复挂载

Status: implemented

## Problem

Finder 已能联动弹出分散挂载的 APFS 卷，但 AppPorts 的主程序和登录代理可能把部分已卸载卷重新接回。用户需要在 AppPorts 发起弹出，由系统提示占用，并在再次插盘前保持暂停。

## Decision

本篇显式“取消弹出并恢复挂载”的决定由[仅通过重连接恢复](../simplification/2026-10-24-disk-reconnect-only.md)取代；以下保留该选择的原理由和对应验证，其余主动弹出与暂停规则继续适用。

在外部应用库标题旁加入弹出入口及暂停后的重试、恢复入口。用户于 2026-10-23 确认实施；新增文案现已[补齐全部 22 语言](../testing/2026-10-23-本地化覆盖与英文占位守卫.md)，临时中英文范围与定向英文回退已结束。

弹出服务与数据操作共用 OperationLock，先确认目标是外置物理盘，按当前磁盘清单收集整盘卷 UUID、容器 UUID 和挂载路径，排除 EFI 分区身份，再持久化暂停状态后向 Finder 发送 eject Apple event。Finder 负责系统占用提示；脚本返回成功仅证明请求已接受，必须另查物理介质是否离线。NSWorkspace 原型在占用时仅返回 OSStatus -47，不符合复用 Finder 提示的目标。

暂停文件与迁移账本分开，沿用同一数据目录和操作锁；读取失败时停止自动维护，不能默认为没有暂停。暂停按卷/容器和精确路径边界影响目标盘。主程序、登录代理、自动恢复和底层挂载入口共同检查。WriterAdmission 能力更新，避免运行中的旧代理忽略新状态。

恢复依据物理 IOMedia 的 registry entry ID 和 boot session，而非设备号、目录通知或卷重新挂载。相同物理连接上任意挂载不解除暂停；相同盘的卷 UUID 在新物理连接上出现时解除。查询失败保留状态，用户可以明确取消弹出并恢复挂载。状态持久化前失败不发起弹出；发起后失败或超时保留暂停及重试/恢复入口，不强制卸载、不退出占用应用。

## Independent physical observation

AppPorts 的结果显示独立于 Finder。`PhysicalDiskMonitor` 只注册 Disk Arbitration 的 whole-media appeared/disappeared 通知，不注册审批、不拦截、不发起磁盘操作。通知经过 AsyncStream 的 newest-one 缓冲触发刷新，现有五秒兜底查询覆盖漏事件或监听不可用；每个可见菜单的任务取消时注销会话。注册、回调、注销在同一串行队列，停止可重复调用，也处理流终止回调从该队列重入的情况。

`PhysicalDiskState.query` 按原 boot session 和 IOMedia registry entry ID 查询内核：原连接存在为 online，原连接已消失为 offline，查询失败为 unknown。不能把 eligible APFS 清单没找到、某个卷卸载或 Finder 脚本返回 0 当作物理离线。离线文案只报告“磁盘已离线”，不把设备消失扩大为安全弹出成功的证明。

请求期间保持“正在请求弹出”；请求返回后，原连接仍在线且有文件系统挂载时显示“磁盘尚未弹出，自动挂载已暂停”，所有卷已卸载但介质对象仍在时显示“所有卷已卸载，设备仍连接”，原介质已消失显示等待重新连接，查询失败显示无法确认并保留暂停。磁盘在线不能证明用户点了取消，因此不自动恢复挂载。用户可以选择“取消弹出并恢复挂载”，确认先关闭原生弹出提示后，再使用既有显式恢复流程。

物理观察可在操作锁忙时读取原子发布的暂停快照并查询内核；账本 reconcile 仍只在持锁时取得新磁盘清单后执行，不能拿锁外旧清单清除新暂停。刷新请求合并、事务 revision 丢弃过期结果。多窗口有独立被动会话，共享 controller 合并查询，关闭窗口不影响其他窗口的会话。

每块暂停盘只有一个弹出动作：确认仍有文件系统挂载时“重试弹出”，全部卸载、离线或未知时不提供弹出动作；未知状态仍允许明确取消暂停。已暂停的当前盘不再重复显示顶层“弹出外置硬盘”，但用户选中的另一块盘仍有自己的初次弹出入口。选择路径被其他卷 UUID 的磁盘复用时按当前盘身份保留新入口，不能因为旧暂停的路径相同把新盘入口隐藏。重新连接后，reconcile 清除对应暂停，菜单恢复普通弹出入口，已打开的过期恢复确认也随记录消失关闭。

暂停文档继续 schema 1；增加拒绝重复 connectionID 的校验，避免一份损坏的状态文件生成重复键。当前保留文案覆盖全部 22 种语言，使用常规语言选择链。


2026-10-24 用户报告的 RTL9210C NVMe 桥接盒在三个 APFS 卷的 MountPoint 都为空时，物理 disk4、APFS 容器 disk5 及原 IOMedia registry entry 仍存在。仅检查 IOMedia 不能把“文件系统全部卸载”和“介质离线”区分开。观察阶段复用 `DiskUtility.kernelMountTable()` 的 caller-owned getmntinfo_r_np 快照：把原物理盘、全部分区及映射的 APFS 容器/卷 BSD 节点与挂载来源匹配，包含隐藏卷、EFI 和 snapshot@/dev 形式的快照挂载。任意相关挂载仍在就不能报告全部卸载；挂载表读取失败、物理归属清单不全时报告 unknown，不能以空路径或缺清单证明已卸载。

新增的 BSD 名称集合仅是本轮观察材料，不进入暂停文件或恢复准入；EFI 的 UUID 仍排除于持久身份。内核挂载表提取与原诊断分类共用实现，避免两套读取口径。全部卸载时不再提供依赖已挂载 Finder alias 的重试入口，仍允许用户明确取消暂停；此状态不声称 DADiskEject 已完成或设备已物理断开。

清单完整性独立记录：物理盘上声明的 APFS store 必须全部映射，容器和卷必须都有 BSD 节点。缺少整个 APFS 容器、容器节点或任一卷节点时，即使物理根节点仍存在，也只能报告 unknown，不能凭部分清单宣布全部卸载。

## Library reconnection

暂停状态和应用列表各自更新。`pause.circle` 表示仍有保存的暂停记录，`eject` 表示没有该记录，不能单独当作磁盘在线证明。2026-10-23 用户接回真实外盘后，暂停记录已清空、两个数据卷由代理在 13:57:18 挂回，但界面仍显示空外部列表和孤立入口；13:57:28 手动扫描得到 40 个外部应用。这个失败归属于列表刷新缺口，不是要求用户再退出应用。

`AppLibraryVolumeObserver` 同时监听 workspace 的 didMount 和 didUnmount，ContentView 将两类事件接到既有一秒防抖扫描：重新打开当前外部目录及 `.noindex` 目录监控，并以同一轮扫描更新本地入口和外部应用。挂载事件仍触发原有后台维护，卸载事件不主动重挂；忙碌期间沿用 needsAppRescan 的延后刷新。目录描述符属于旧挂载会话，不能用“新卷挂到相同路径”证明旧 FolderMonitor 仍有效。

监听对象支持停止和重启，用 generation 拒绝停止前已排队的主线程回调，避免离开视图后重新启动目录监控。暂不按通知路径过滤，系统自动挂载和数据卷切换的多个事件由既有防抖合并，避免漏掉分散挂载对本地入口状态的影响。

恢复确认文案使用“如果 Finder 仍显示弹出提示”的条件表达，它不是占用检测结果；该恢复入口后由重连接方案移除，当前保留提示已补齐全语言。

## Alternatives considered

- **NSWorkspace 直接弹出**：不需要 Finder 自动化，但实测占用时立即返回错误，没有 Finder 的占用提示。
- **模拟点击 Finder 按钮**：与人工操作接近，但依赖窗口、坐标和辅助功能权限；使用 Finder 的公开脚本接口。
- **只刷新暂停图标或只在恢复操作后扫描**：暂停与列表状态来源不同，而且后台代理可能先清除暂停；必须监听实际卷事件以覆盖 Finder 操作、自动接回和部分卸载。
- **IOMedia 存在即认定卷仍在线**：身份稳定，适合防止把部分卸载误认作整盘消失；但桥接盒可在全部卷卸载后继续保留介质对象。增加内核挂载状态，并使用“全部卸载但仍连接”的独立状态，而不放宽物理重连接识别。
- **根据 Finder 窗口、脚本退出码或超时推断取消/成功**：接近用户操作，但退出码只证明请求已接受，仍在线也可能只是原生对话框等待，无法可靠判定取消；独立观察内核物理连接，并保留明确恢复入口。
- **捕获全部外部弹出请求**：覆盖用户直接操作 Finder，但引入常驻仲裁、内部请求区分和原请求替换。本轮只覆盖 AppPorts 入口。
- **重试前严格读取全部应用记录**：可以一次得到整库合法性，但一条无关损坏 plist 会阻塞已切换事务的清理；单条严格读取已足够取得当前事务的暂停范围，其他诊断继续由 inventory 展示。

## Recovery and compatibility

暂停覆盖整盘已知卷、容器和原挂载路径，并在自动应用/数据事务重试、签名历史备份搬迁、材料删除、原位挂载入口共同生效。签名备份的新目的地在准备目录前过滤，选址后也核对，避免尚未保存目的地的旧记录绕过暂停。多物理成员的 APFS 构造拒绝全部已知成员，即使其中一个还有普通分区。

`AppMigrationService.retryTransfer` 持锁后按请求的 operationID 严格读取单条应用记录，再检查其卷身份与源、目标、暂存路径是否暂停。无关损坏记录继续由 inventory 隔离并显示，不能在暂停检查时通过严格整库 records() 阻塞合法事务；选中的损坏或缺失记录仍拒绝重试，暂停文件无法读取仍拒绝恢复。原有内容基线、切换凭据和旧副本清理规则继续由事务执行器验证。

EFI FAT UUID 在本机两块无关外盘上实际相同，因此只保留物理分区映射，不将 EFI 的 UUID 或路径作为数据盘身份。其他重复数据卷 UUID 保持歧义拒绝，不能仅凭同名或 diskN 恢复。

界面初次刷新遇到操作锁竞争会持续重试；磁盘清单查询失败仍显示可读的暂停记录和手动恢复入口，连接状态保持未知。后台查询成功才据物理连接清除暂停。旧主程序/登录代理不具备新 writer capability 时必须重新启动到支持暂停的版本，不能让旧进程忽略暂停状态。

## Consequences

用户可以从一个入口请求系统弹出，并在部分卸载或失败后保持暂停，避免自动任务立即把卷接回；重试和明确恢复仍可用。代价是维护独立持久状态、物理连接识别以及跨后台入口的准入约束。Finder 自动化首次使用需要系统授权，拒绝时提供可恢复错误。系统占用提示不保证识别全部占用者。注册身份与磁盘查询属于时间点观察，发出请求前要重新校验目标；不能对同名替代盘操作。隔离映像与模拟测试不能代替真实受管应用的最终验收。
