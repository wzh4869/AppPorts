# Agent Note: 普通入口适配 Tauri 外盘更新

Status: implemented

## Problem

CC Switch 4.0.30 通过本机入口启动后，应用内安装 4.0.38 时两次报告跨卷移动错误。旧版官方 Tauri 插件会在系统临时目录准备应用，再用只支持同卷的移动操作替换外盘应用。等用户点击更新时，进程已经继承了启动环境。

## Decision

标准 Tauri 发行包的两个 plist 字段用于缩小检查范围。AppPorts 在真实主程序的 Mach-O 中查找官方更新插件的源码路径，按稳定版本选择行为。2.10.0 至 2.13.1 的应用通过原有本机入口启动时，入口为该进程提供同一卷的私有临时目录。2.13.2 引入上游的跨卷修复，已识别的后续 2.x 仍使用插件本身的安装方式。检测结果按可执行文件的设备、inode、大小和状态变更时间复用。位置受限的 Clash Verge 沿用原有迁移风险规则。

AppPorts 在创建或维护入口时为该用户和应用准备一处可复用的 0700 目录。入口只核验已有目录的文件属性，避免它以独立进程身份再次读取厂商可执行文件或写入外盘。只有应用与系统临时目录确实跨卷、目录类型、属主、权限和卷均可核对时才传递 TMPDIR。目标锁定或目录不可用时保留正常打开流程。文件和 URL 与常规启动共用原入口转发逻辑。应用已经运行时不要求它退出，也不修改系统环境、应用包和更新守护。

仅准备成功的旧插件入口保存对应标记。维护扫描只为需要旧插件适配的既有标准入口补齐这项能力，即使厂商应用版本未变也能刷新。旧插件在迁出前可以预判兼容性，迁出后要确认是指向该应用的已适配入口才能显示可用。直接通过外盘或传统链接启动的旧插件没有这项辅助。

旧版插件需要入口传递启动环境，而此前迁移会将 Dock 固定项指向外盘本体。经维护者确认，迁出、链接或升级旧入口时，仅将这类应用已有的固定项指向核实过的本机入口。路径、卷、应用标识和临时目录均需匹配。沿用现有的书签核验、并发检查、受管理偏好保护和原位写入。升级到原生支持的插件并刷新入口后，固定项重新指向外盘本体。迁回后指向本机应用。没有固定项时不会新增；启动时 Dock 可能短暂出现两个图标。

## Alternatives considered

- 更新前提供专用启动按钮。可以由用户限定生效时机，但要求先退出、重新打开，再在应用里重新触发更新。
- 仅根据 Tauri 应用名称或框架标志设置 TMPDIR。部分应用未启用官方插件，新插件也已具备同卷安装能力。
- 用守护接手安装。原厂插件已能完成下载、签名核验和安装，只需在启动时使旧插件取得正确的临时位置。

## Consequences

从 Dock、Finder 或文件关联经过标准入口的下一次正常启动即可获得适配。无法识别版本、非标准打包或没有适配入口时，列表保持保守。旧插件运行期间，应用自己的其他临时文件也可能写入该私有目录。从旧插件更新至新插件后，即使 AppPorts 已退出，原入口仍可继续打开新版。下一次维护扫描会清除旧提示，之后的新进程使用系统默认临时目录。厂商应用仍负责下载、签名核验和安装。

## Verification

2026 年 11 月 21 日在 Apple Silicon Mac 上使用官方更新插件 2.10.0 至 2.14.1 的十个稳定版逐一测试。各测试应用从系统盘非锁定迁至物理 APFS 外盘，通过既有固定项的系统书签启动、应用内校验并安装签名更新、原入口冷启动外盘新版，再迁回本机。六个旧版由入口传入同卷临时目录，四个新版保留系统默认值。固定项的 GUID、顺序、标识和书签逐次核对。Dock 偏好使用独立测试存储，图标显示时长未经桌面实测。

厂商签名包另核对 CC Switch 4.0.30 内置 2.10.0、GitButler 0.23.5 内置 2.10.1。CC Switch 厂商应用内 4.0.30 到 4.0.38 属于之前的隔离机测试。此次测试使用官方插件测试应用。249 项迁移、Dock、扫描和入口相关回归通过，无失败或跳过。双架构 Release 洁净构建和严格签名校验均通过。详细记录位于本地 `build/Validation/tauri-portal-Z1xPAAwV/REPORT.md`。
