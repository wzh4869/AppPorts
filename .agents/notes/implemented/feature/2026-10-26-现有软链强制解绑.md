# Agent Note: 现有软链强制解绑

Status: implemented

## Problem

工具缓存的现有软链可能指向已断开的外置盘。规范化管理需要读取目标数据，无法满足舍弃本地关联、直接从空目录重新开始的需求。

## Decision

“链接详情”同时提供规范化管理和强制解绑。强制解绑要求勾选确认：原路径改为空目录，旧数据不会自动恢复。该操作保留外部目标数据，不检查目标是否在线，也不遍历目标目录。

`DataDirMover.resetExistingLink` 在底层执行路径策略、父路径、已有迁移重叠、关联应用退出和软链目标检查；界面状态不授予文件删除权限。实际链接目标必须与用户确认时的目标一致。普通目录、父级经过软链或挂载点的路径，以及存在受管迁移记录的路径均不能借此绕过原恢复流程。

替换复用 `switchEntry`：先在同一父目录下准备空目录，再将原软链保存在临时目录中，完成替换后仅清理已验证身份的软链。替换失败时沿用原有回滚行为；错误清理只使用 `rmdir` 清除空目录，保留尚未处理的条目并报告其位置。

操作沿用任务中心的资源互斥、应用退出检查和完成后刷新。新增文案进入现有字符串目录。

## Alternatives considered

- 先规范化再还原：复用原有管理流程，但依赖外部数据可读且会搬回全部数据，无法处理目标离线的场景。
- 直接递归删除原路径再创建目录：步骤较少，但普通目录替换软链时可能误删数据，也失去替换失败时恢复原链接的机会。
- 解绑时清空外部目标：可以回收外部空间，但目标可能断开，且本需求只需恢复本地可用目录，因此不扩大删除范围。

## Consequences

解绑完成后，应用可重新生成缓存或数据，外部原件仍在原位置。受管迁移与受保护的系统目录仍使用各自恢复流程。替换中断时，临时目录可能保留原软链；不会把这种情况报告为完成。

`xcodebuild test -only-testing:AppPortsTests/ExistingLinkResetTests` 的 4 项定向测试通过，覆盖外部数据保留、断开的相对软链、普通目录拒绝、确认后目标变化和软链父路径拒绝。测试使用临时目录，未在真实用户数据上执行解绑。笔记格式、目录及相对链接校验通过。
