# Agent Note: 就绪权限展示与默认窗口尺寸

Status: implemented

## Problem

维护者截图中，App 管理权限已经就绪，卡片仍提供系统设置按钮，与同页完全磁盘访问权限的就绪展示不同。应用数据页在原默认宽度下，统计文字和已链接状态出现换行，维护者要求默认窗口更大。

## Decision

App 管理明确 granted 时，LaunchReadinessChecker 的检查项 action 为 nil，ReadinessCard 复用既有无按钮分支，只显示已就绪。denied 与 unknown 继续提供 App 管理设置入口，权限查询、三态文案、提示点及打开权限页前关闭弹窗的行为保持原样。本决定部分取代[App 管理实际授权检查](../bug-fix/2026-11-15-App管理实际授权检查.md)和[准备检查与迁移锁定判定](../bug-fix/2026-11-15-准备检查与迁移锁定判定.md)的入口常驻要求，不取代状态查询与误报修复。

MainWindowAppearance 将新窗口默认内容尺寸从 952 × 624 改为 1200 × 780，并按该窗口所在屏幕的 visibleFrame 限制尺寸，无所在屏幕时回退到主屏幕。既有最小内容尺寸 930 × 620、手动调整窗口及关闭后保留窗口状态的规则不变；全屏窗口沿用现有跳过初始调整的分支。仅扩大默认空间，不改变应用数据页的列宽、字体或业务操作。

没有新增界面文案。交付随缓存解锁修复以 build 54 安装；验证产物放在被忽略的 build/Validation/readiness-window-20261116/。

## Existing-note audit

- App 管理实际授权检查：部分重叠，仅收起已就绪入口；原系统预检实现、未知状态与两个权限的独立性继续成立。
- 准备检查与迁移锁定判定：部分重叠，已就绪入口由本篇收窄；迁移锁定、存储能力和文档链接不受影响。
- [完全磁盘访问拖拽引导](2026-11-04-完全磁盘访问拖拽引导.md)：复用现有关闭来源弹窗与浮窗逻辑，拒绝或无法确认时仍有引导。
- 活跃 proposed、implemented、rejected 笔记中没有默认窗口尺寸的独立决定，没有完全吸收或需要归档的记录。

## Alternatives considered

- 保留已就绪的系统设置按钮可随时核对权限，但维护者反馈这种展示令人误以为仍需处理；改为与完全磁盘访问就绪状态一致，需要授权或无法确认时再提供入口。
- 提高最小窗口尺寸能持续保证更多显示空间，但会限制用户缩小窗口和小屏使用；只提高默认尺寸，继续允许主动缩小。
- 重排应用数据页统计行能适应窄宽度和较长翻译，但会扩大本轮布局变更；先落实维护者要求的默认窗口空间，既有窄窗口换行行为保留。

## Consequences

所有准备项就绪时只显示状态，App 管理的授权或核对入口仅在需要处理时出现。默认打开窗口更大，应用数据详情区域获得更多宽度；小屏幕按可见区域限制，用户仍可缩小窗口，因此本变更不保证每一种手动窄窗口或长翻译都不换行。代码继续复用 macOS 12 支持的既有窗口桥接，没有新增窗口场景或布局组件。
