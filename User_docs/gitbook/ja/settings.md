# 設定

AppPorts の設定ページは、メインウィンドウ右上の歯車アイコンから開きます。

## App Store と iOS の設定 <a href="#app-store-と-ios-の設定" id="app-store-と-ios-の設定"></a>

| 設定項目 | 説明 | デフォルト |
|--------|------|--------|
| Mac App Storeアプリの移行を許可 | App Store アプリの移行を許可します。macOS 15.1 より前のバージョンでこれらのアプリを移行する場合は、手動で有効にする必要があります | オフ |
| 非ネイティブアプリの移行を許可 | iOS/iPadOS アプリ（Mac 版）の移行を許可します | オフ |

{% hint style="success" %}
**macOS 15.1+ をお使いの場合**

macOS 15.1 以降では、App Store アプリを外部ストレージに直接インストールできます。AppPorts の手動移行設定よりも、App Store の設定で「容量の大きいアプリを別のディスクにダウンロードおよびインストール」を有効にする方法を優先してください。
{% endhint %}

## 署名の設定 <a href="#署名の設定" id="署名の設定"></a>

| 設定項目 | 場所 | 説明 | デフォルト |
|--------|------|------|--------|
| Re-sign after migration | データディレクトリページ上部のツールバー。**クラシックモードでのみ表示** | シンボリックリンク移行の完了後、関連するアプリを Ad-hoc で再署名します | オフ |
| ログイン時自動再署名 | 設定ページ | 署名バックアップで元から Ad-hoc だったアプリをログイン時に再署名し、再起動後の署名の無効化に対処します。サンドボックスアプリはスキップします（クラシックモードではスキップしません） | 新規インストールではオフ。ログインエージェントをすでにインストールしている既存ユーザーはオンのまま |

クラシックモード以外では、どの操作からもサンドボックスアプリを再署名しません。再署名すると、macOS 27 で開けなくなる可能性があるためです。コンテナデータには、署名を変更しない[マウント移行](datamigrae/mount-migration.md)を使用します。

元のアプリ全体のバックアップがある新形式の記録は、ログイン時のスクリプトで再署名しません。AppPorts が検証と安全な置換を行います。アプリの起動時には、インストール済みのスクリプトを同期します。

「ログイン時自動再署名」は LaunchAgent `com.shimoko.AppPorts.re-sign` をインストールし、ログを AppPorts のデフォルトのログファイルに書き込みます。再署名とバックアップの対象は、ローカルの起動用シェルではなく、外部ドライブにあるアプリの実体です。[再署名とクラッシュ対策](datamigrae/resign.md)を参照してください。

## クラシックデータ移行モード（非推奨） <a href="#classic-data-migration-mode" id="classic-data-migration-mode"></a>

設定ページの下部にある「クラシックデータ移行モード（非推奨）」は、デフォルトでオフです。1.8.1 の旧方式を使っていて、すぐに切り替えられないユーザー向けに残しています。外部ドライブが APFS でない場合は、APFS の要件を避けるためにこのモードを有効にせず、コンテナデータをローカルに残してください。[外部ドライブに APFS が必要な理由](why-apfs.md#what-to-do)を参照してください。有効にする前に、確認ダイアログの「上記のリスクを理解しました」にチェックを入れる必要があります。macOS 27 では、再署名されたサンドボックスアプリを開けなくなる可能性があることを設定の横に表示します。有効にすると、次のように変わります。

| 項目 | オフ（デフォルト） | オン |
|------|--------------|------|
| コンテナディレクトリのボタン | 「マウント移行」のみ | シンボリックリンクによる「Migrate」と「マウント移行」を並べて表示 |
| コンテナ移行前の再署名ダイアログ | 表示しない | 表示する。デフォルトは移行のみ |
| サンドボックスアプリの再署名 | すべての操作で拒否 | 許可。毎回、影響を説明する追加確認を表示 |
| 「Re-sign after migration」設定 | 非表示 | データディレクトリページのツールバーに表示 |
| コンテナディレクトリの「整理」「再リンク」「リンクの詳細」 | 無効。先に復元してからマウント移行するよう案内 | 利用可能 |

クラシックモードは、リスクを含めて旧方式をそのまま復活させます。再署名されたサンドボックスアプリは macOS 27 で開けなくなる可能性があり、その場合はデータの復元と再インストールが必要です。AppPorts はこれらのアプリに「署名置換済み」バッジを付け、起動時にも通知します。[macOS 27 へのアップグレード](macos-27.md)を参照してください。クラシックモードをオフにしても、既存のシンボリックリンク移行項目は変更されず、「Restore」は引き続き使えます。

## マウント移行に関する設定 <a href="#マウント移行に関する設定" id="マウント移行に関する設定"></a>

マウント移行には独立した設定項目はありません。設定ページの「準備状況」で、フルディスクアクセス、AppPorts のインストール場所、外部ストレージの形式を確認し、対処が必要な項目を案内します。最初のマウント移行に成功すると、AppPorts はログインエージェント `com.shimoko.AppPorts.container-mount` をインストールします。ログイン後、接続されているボリュームをコンテナディレクトリに自動で再マウントします。最後のマウント記録を復元すると、エージェントを自動的にアンインストールします。macOS 12 などの旧システムでは、エージェントから管理者パスワードのダイアログを表示できないため、ログイン後に AppPorts を開いて再マウントしてください。

## ログの設定 <a href="#ログの設定" id="ログの設定"></a>

| 設定項目 | 説明 | デフォルト |
|--------|------|--------|
| ログ記録を有効にする | 実行ログをファイルに書き込みます | オン |
| 最大ログサイズ | 上限を超えると、古い方の半分を自動的に切り詰めます | 2 MB |
| ログの保存場所 | ログファイルのパス | `~/Library/Application Support/AppPorts/AppPorts_Log.txt` |

### ログの操作 <a href="#ログの操作" id="ログの操作"></a>

| 操作 | 説明 |
|------|------|
| Finderで表示 | ログファイルのあるディレクトリを開きます |
| 診断パッケージを書き出す | ログ、操作記録、システム情報を含む ZIP ファイルを作成します |
| ログを消去 | 現在のログファイルの内容を消去します |

詳しくは[ログと診断](logging.md)を参照してください。

手動でバックアップ、再署名、復元を行う前に、AppPorts は現在のログインセッションのバックグラウンド再署名タスクを停止し、その子プロセスが終了するまで待ちます。復元したばかりの署名がバックグラウンドで上書きされることを防ぎます。ログインエージェントの設定は保持し、次回ログイン時も設定に従って動作します。バックグラウンドタスクの停止を確認できない場合、その手動操作を中止します。
