# 常見問題

## 安裝與授權 <a href="#安裝與授權" id="安裝與授權"></a>

### AppPorts 需要什麼權限？ <a href="#appports-需要什麼權限" id="appports-需要什麼權限"></a>

AppPorts 需要**完整磁碟取用權限**，用於讀取和修改 `/Applications` 目錄。首次啟動時會引導授權，你也可以在系統設定 → 隱私權與安全性 → 完整磁碟取用權限中手動新增 AppPorts。

### 支援哪些 macOS 版本？ <a href="#支援哪些-macos-版本" id="支援哪些-macos-版本"></a>

AppPorts 最低支援 macOS 12.0（Monterey）。macOS 15.1（Sequoia）及以上版本額外支援將 App Store 應用程式安裝到外接儲存裝置，並在外接儲存裝置上原地更新。

### 可以使用 NAS 或網路掛載磁碟作為外接儲存裝置嗎？ <a href="#可以使用-nas-或網路掛載磁碟作為外接儲存裝置嗎" id="可以使用-nas-或網路掛載磁碟作為外接儲存裝置嗎"></a>

AppPorts 主要面向本機外接儲存裝置，例如行動硬碟、外接 SSD 或硬碟盒。NAS、SMB、rclone、SFTP 等網路掛載路徑在理論上可以被 macOS 當作檔案系統路徑使用，但穩定性、權限、延遲和斷線恢復能力取決於掛載方案本身。

如果要嘗試網路掛載磁碟，建議先用不重要的應用程式或可重建的資料目錄測試，並確認以下條件：

- 掛載路徑在 AppPorts 啟動前已經可取用。
- 網路斷開後可以自動重新掛載到相同路徑。
- 檔案系統支援應用程式所需的權限、延伸屬性和符號連結行為。
- 不要先遷移微信、虛擬機器、遊戲庫等高價值或高頻寫入資料。

## 應用程式遷移 <a href="#應用程式遷移" id="應用程式遷移"></a>

### 如何掃描非 /Applications 目錄中的應用程式？ <a href="#如何掃描非-applications-目錄中的應用程式" id="如何掃描非-applications-目錄中的應用程式"></a>

按一下「Mac 本地應用程式」標題欄右側的「+」按鈕，選擇要額外掃描的目錄。適用於 JetBrains Toolbox、Steam 等將應用程式安裝在自訂目錄的工具。新增的目錄會自動儲存，下次啟動 AppPorts 時會自動掃描，也會自動監控目錄變化。新增後，標題欄會顯示自訂目錄數量；開啟該計數選單可檢視或移除已新增的目錄。

### 遷移後應用程式打不開怎麼辦？ <a href="#遷移後應用程式打不開怎麼辦" id="遷移後應用程式打不開怎麼辦"></a>

1. 確認外接儲存裝置已連線且可取用。
2. 檢查應用程式狀態徽章。如果顯示「孤立連結」，說明外部應用程式已遺失，需要手動解除連結。
3. 如果系統提示應用程式「已損壞」，先試重新安裝；仍不行再右鍵「重簽名此應用」，注意沙盒應用程式會被拒絕。
4. 如果仍無法解決，可在外部應用程式庫中選擇「遷回本機」，先恢復到本機執行狀態。
5. 如果是按兩下沒反應、圖示閃一下就消失，見 [macOS 27 升級說明](macos-27.md)。

### 出現「已損壞」提示怎麼辦？ <a href="#出現「已損壞」提示怎麼辦" id="出現「已損壞」提示怎麼辦"></a>

這通常是 macOS 的程式碼簽名機制偵測到應用程式套件結構發生變化。可按以下步驟處理：

1. 先從官網或 App Store 重新下載安裝一次，多數情況能解決。
2. 仍然提示，在 AppPorts 中右鍵按一下該應用程式，選擇「重簽名此應用」。AppPorts 會備份原始簽名並執行 Ad-hoc 重簽名。
3. 沙盒應用程式會被拒絕：重簽名後它在 macOS 27 上可能無法開啟，這類應用程式只能重新安裝。

詳細機制請參閱[重簽名與當機防護](datamigrae/resign.md)。

### 外接儲存裝置拔掉後應用程式會不會當機？ <a href="#外接儲存裝置拔掉後應用程式會不會當機" id="外接儲存裝置拔掉後應用程式會不會當機"></a>

本機入口（Stub Portal）會嘗試呼叫 `open` 開啟外部應用程式。如果外接儲存裝置未連線，應用程式無法啟動，但本機入口本身不會當機。重新連接外接儲存裝置後，即可恢復正常使用。

### 為什麼有些應用程式遷移後仍然顯示捷徑箭頭？ <a href="#為什麼有些應用程式遷移後仍然顯示捷徑箭頭" id="為什麼有些應用程式遷移後仍然顯示捷徑箭頭"></a>

這是舊版 AppPorts 可能出現的情況。新版 AppPorts 對一般 `.app` 應用程式預設使用 Stub Portal，本機會顯示為一般應用程式圖示，通常不會再出現捷徑箭頭。

如果你仍然看到箭頭，多半是舊版本建立的歷史入口仍在使用整體符號連結。建議先將應用程式遷回本機，再使用目前版本重新遷移。

### 遷移後能不能更新應用程式？ <a href="#遷移後能不能更新應用程式" id="遷移後能不能更新應用程式"></a>

取決於應用程式類型：

| 應用程式類型 | 能否自動更新 | 說明 |
|----------|:---:|------|
| 原生應用程式（無自更新） | ✓ | 可按原方式更新 |
| Chrome、Edge（自訂更新器） | ✓ | 更新安裝到本機，AppPorts 偵測到本機版本更高後標記「待遷出」 |
| Sparkle / Electron 應用程式 | ✗ | 鎖定後會阻止應用程式內更新，需透過 AppPorts 遷回本機後更新 |
| App Store 應用程式（macOS 15.1+） | ✓ | App Store 可在外接硬碟原地更新 |
| App Store 應用程式（macOS <15.1） | ✗ | 需手動再次遷移 |

### 「待遷出」是什麼意思？ <a href="#「待遷出」是什麼意思" id="「待遷出」是什麼意思"></a>

「待遷出」表示本機存在一個真實應用程式，並且 AppPorts 判斷它比外接儲存裝置中的同一應用程式副本更新。常見場景是 Chrome、Edge 或其他自訂更新器把新版本安裝回本機，而外接儲存裝置上仍是舊版本。

看到該狀態時，可以重新執行「遷移至外部」，讓本機新版替換外部舊副本。AppPorts 會優先按 Bundle ID 比對應用程式，再改以正規化名稱補充比對；如果版本號缺失、無法比較，或同名應用程式的 Bundle ID 不一致，就不會顯示「待遷出」。

### 外部目標已經存在時會被覆蓋嗎？ <a href="#外部目標已經存在時會被覆蓋嗎" id="外部目標已經存在時會被覆蓋嗎"></a>

不會直接覆蓋。AppPorts 只會在以下情況下自動清理外部目標並繼續遷移：

- 目前應用程式處於「待遷出」狀態，外部目標可視為同一應用程式的舊副本。
- 外部目標被辨識為 AppPorts 建立的舊 Stub Portal、舊 Deep Contents Wrapper 或整體符號連結入口。
- 外部目標是 AppPorts 遷移流程留下的舊殘留。

如果外部位置存在無法確認歸屬的真實應用程式或目錄，AppPorts 會停止遷移並提示目標衝突，避免誤刪使用者資料。

### App Store 應用程式怎麼遷移到外接硬碟？ <a href="#app-store-應用程式怎麼遷移到外接硬碟" id="app-store-應用程式怎麼遷移到外接硬碟"></a>

**macOS 15.1+**：在 App Store 設定中開啟「下載並安裝大型 App 到獨立磁碟」，並選擇與 AppPorts 外部應用程式庫相同的外接儲存裝置。

**macOS <15.1**：在 AppPorts 設定中開啟「允許遷移 Mac App Store 應用程式」。此方式需要手動遷移，應用程式更新後也需要再次遷移以覆蓋外部副本。

### 為什麼遷移前提示「受保護的應用」？ <a href="#為什麼遷移前提示「受保護的應用」" id="為什麼遷移前提示「受保護的應用」"></a>

App Store 應用程式或歸屬系統（root）的應用程式通常受 macOS 權限保護，本機副本可能無法被 AppPorts 直接刪除或替換。看到該提示時，更穩妥的做法是先在 Finder 中手動把應用程式拖到外接儲存裝置（系統會要求管理者密碼），然後回到 AppPorts 為外部應用程式建立本機連結。仍可選擇繼續自動遷移，但可能以「權限不足」失敗。

### App Store 更新後出現多個開啟方式或版本不一致怎麼辦？ <a href="#app-store-更新後出現多個開啟方式或版本不一致怎麼辦" id="app-store-更新後出現多個開啟方式或版本不一致怎麼辦"></a>

v1.8.0 及以上版本會自動同步外接應用程式的版本資訊到本機 Stub Portal，「開啟方式」選單會自動更新。如果仍出現版本不一致，可按一下重新整理按鈕手動觸發同步。

舊版本（v1.7.0 及以下）的處理方式：

1. 開啟 AppPorts，重新整理本機應用程式和外部應用程式清單。
2. 如果本機版本更新，重新執行遷移，讓新版本覆蓋外部副本。
3. 如果只是本機入口狀態異常，先解除連結，再從外部應用程式庫執行「連結回本地」。

macOS 15.1 及以上版本建議優先使用 App Store 的原生外接安裝能力，減少版本分叉。

### 按兩下文件後應用程式能啟動，但沒有開啟對應檔案怎麼辦？ <a href="#按兩下文件後應用程式能啟動-但沒有開啟對應檔案怎麼辦" id="按兩下文件後應用程式能啟動-但沒有開啟對應檔案怎麼辦"></a>

這類問題常見於 Office、WPS 等依賴檔案關聯參數的應用程式。舊版本 Stub Portal 可能只啟動外部應用程式本體，沒有正確傳遞被按兩下檔案的路徑。請先升級到 v1.6.2 或更高版本，然後將相關應用程式遷回本機並重新遷移，或在外部應用程式庫中重新執行「連結回本地」。

如果問題仍然存在，請匯出診斷包並提交 Issue，說明應用程式安裝來源（App Store、官網 `.pkg`、DMG 等）和重現步驟。

### Adobe、Office 等應用程式套件可以遷移嗎？ <a href="#adobe、office-等應用程式套件可以遷移嗎" id="adobe、office-等應用程式套件可以遷移嗎"></a>

可以嘗試，但這類應用程式往往不是單個獨立 `.app`，而是多個應用程式、共享元件、背景服務和授權模組組成的套件。AppPorts 會盡量以目錄為單位處理應用程式套件，但相容性仍取決於應用程式自身結構。

建議遷移前關閉套件內所有應用程式，並確認已經登入或啟用。遷移後如果出現授權異常、關聯檔案打不開或元件找不到，可先遷回本機，再只遷移體積較大的獨立應用程式或資料目錄。

### 遷移速度慢/卡住怎麼辦？ <a href="#遷移速度慢-卡住怎麼辦" id="遷移速度慢-卡住怎麼辦"></a>

- 進度到達 100% 附近時可能會停頓一至兩秒，這是在建立本機入口並完成收尾檢查。
- 大型應用程式（如 Xcode、Adobe 系列）遷移時間較長，屬於正常現象。
- 如果長時間無進展，請檢查外接儲存裝置連線是否穩定。
- USB 2.0 介面速度較慢，建議使用 USB 3.0 及以上介面或 Thunderbolt。

## 資料目錄遷移 <a href="#資料目錄遷移" id="資料目錄遷移"></a>

### 資料目錄遷移後應用程式資料會不會遺失？ <a href="#資料目錄遷移後應用程式資料會不會遺失" id="資料目錄遷移後應用程式資料會不會遺失"></a>

正常情況下不會。AppPorts 會先將資料完整複製到外接儲存裝置，確認複製成功後再刪除本機原始目錄並建立符號連結。任一步驟失敗時，會嘗試自動回復。

如果外部目標目錄已經存在，AppPorts 只會在其中的 `.appports-link-metadata.plist` 與目前來源路徑、目標路徑和資料目錄類型完全一致時接續恢復。沒有比對 metadata 的真實目錄會被視為衝突，AppPorts 不會僅憑大小相近就接管或覆蓋。

### 什麼情況下資料目錄遷移可能導致應用程式異常？ <a href="#什麼情況下資料目錄遷移可能導致應用程式異常" id="什麼情況下資料目錄遷移可能導致應用程式異常"></a>

- 應用程式使用檔案鎖或 SQLite WAL 日誌。
- 跨符號連結取用時，延伸屬性可能遺失或行為不一致。
- 同一 Team 下多個應用程式共享 `Group Containers` 目錄。

`~/Library/Containers/` 和 `~/Library/Group Containers/` 下的目錄用的是掛載遷移而不是符號連結，需要 APFS 外接磁碟，第一次開啟應用程式要在授權對話框中按一下允許。見[掛載遷移](datamigrae/mount-migration.md)。

### 微信的聊天記錄能不能放到外接磁碟？ <a href="#微信的聊天記錄能不能放到外接磁碟" id="微信的聊天記錄能不能放到外接磁碟"></a>

能，用「掛載遷移」。在「應用程式資料」裡選取微信，`Containers` 群組下的 `xwechat_files` 子目錄（按帳號分）和 `Application Support/com.tencent.xinWeChat` 都可以掛載遷移。外接磁碟必須是 APFS；遷移後第一次開啟微信會彈授權對話框，按一下允許。

**不要**用舊版本的"遷移 + 重簽名"方式，那會讓微信在 macOS 27 上打不開。

### 微信資料遷移後看不到聊天記錄怎麼辦？ <a href="#微信資料遷移後看不到聊天記錄怎麼辦" id="微信資料遷移後看不到聊天記錄怎麼辦"></a>

分兩種情況：

- **用 1.9.0 掛載遷移的**：檢查外接磁碟是否連線、AppPorts 裡狀態是否「已掛載」、授權對話框是不是按了拒絕。排查步驟見[故障排除](troubleshooting.md#gua-zai-qian-yi-hou-ying-yong-cheng-shi-kan-bu-dao-zi-liao)。
- **用舊版本符號連結遷移的**：沙盒微信讀不到容器外的資料，這是機制問題不是故障。先在 AppPorts 裡把該目錄「還原」回本機；如果當時選過「同意重簽名」，還要從官網重新安裝微信。步驟見 [macOS 27 升級說明](macos-27.md#xiu-fu)。

**不要**用重簽名來修，它只會把事情弄得更糟。

### 我的外接磁碟是 exFAT，能遷移微信資料嗎？ <a href="#我的外接磁碟是-exfat-能遷移微信資料嗎" id="我的外接磁碟是-exfat-能遷移微信資料嗎"></a>

不能，掛載遷移只支援 APFS。**不改也完全沒問題**：微信資料留在本機照常使用，應用程式本體和其他資料目錄照常遷移到這個磁碟。以後想遷移時，換一個 APFS 磁碟最省事；想在這個磁碟上騰出空間的話，如果磁碟已有未配置空間，可以在滿足分割區配置條件時建立 APFS 分割區；如果 exFAT 佔滿整個磁碟，macOS 和 Windows 的系統內建工具都不能直接縮小它，需要先備份再重新分割區。exFAT 內部的剩餘容量不等於未配置空間。我們試過在 exFAT 上放磁碟映像檔的繞路方案，拔除磁碟測試裡映像檔整個報廢，所以沒有提供。詳見[為什麼外接磁碟必須是 APFS](why-apfs.md#what-to-do)。應用程式本體和其他資料目錄不受這個限制。

### 掛載遷移後 Finder 裡會多出磁碟圖示嗎？ <a href="#掛載遷移後-finder-裡會多出磁碟圖示嗎" id="掛載遷移後-finder-裡會多出磁碟圖示嗎"></a>

不會。AppPorts 掛載資料卷宗時會讓它不出現在 Finder 側邊欄和桌面上；外接磁碟剛接入的一兩秒內可能短暫閃現，接回後就消失。「磁碟工具程式」裡仍能看到名為 `AppPorts-…` 的卷宗，那就是遷移過去的資料，不要清除或刪除。詳見[掛載遷移：日常使用](datamigrae/mount-migration.md#ri-chang-shi-yong)。

### 我的外接磁碟加密了，為什麼不能掛載遷移？ <a href="#我的外接磁碟加密了-為什麼不能掛載遷移" id="我的外接磁碟加密了-為什麼不能掛載遷移"></a>

掛載遷移建立的資料卷宗不會繼承原卷宗的密碼，照常遷移會讓本來受保護的資料落在沒有密碼的卷宗上。AppPorts 在這種情況下停下，不做悄悄降級。詳見[加密的外接磁碟](why-apfs.md#encrypted-drives)。

### 刪除 AppPorts 之前要做什麼？ <a href="#刪除-appports-之前要做什麼" id="刪除-appports-之前要做什麼"></a>

如果用過掛載遷移，先在「應用程式資料」裡把這些目錄「還原」回本機。不還原的話資料仍在外接卷宗上，但登入後沒人把它接回來，應用程式會看到空目錄；重新安裝並開啟一次 AppPorts 即可恢復。

### 升級 macOS 27 後應用程式突然打不開，是之前的資料遷移導致的嗎？ <a href="#升級-macos-27-後應用程式突然打不開-是之前的資料遷移導致的嗎" id="升級-macos-27-後應用程式突然打不開-是之前的資料遷移導致的嗎"></a>

資料沒壞，是簽名的問題。舊版本遷移容器資料時如果選了「同意重簽名」，應用程式的沙盒身分被拆掉，macOS 27 開始拒絕它取用自己的容器。修法是還原資料、重新安裝應用程式，見 [macOS 27 升級說明](macos-27.md)。

### Crossover、Parallels、虛擬機器或遊戲庫適合遷移嗎？ <a href="#crossover、parallels、虛擬機器或遊戲庫適合遷移嗎" id="crossover、parallels、虛擬機器或遊戲庫適合遷移嗎"></a>

這些軟體的應用程式本體通常不一定很大，真正占用空間的往往是虛擬機器映像檔、容器、遊戲庫或模型快取。相比遷移應用程式本體，更建議優先檢視「資料目錄」和「工具目錄」中是否辨識到了對應的大型資料目錄。

如果資料目錄包含虛擬磁碟、資料庫或頻繁寫入的檔案，請確保外接儲存裝置效能穩定，並先備份。網路掛載磁碟不建議直接承載這類高頻寫入資料。

### 如何還原遷移的資料目錄？ <a href="#如何還原遷移的資料目錄" id="如何還原遷移的資料目錄"></a>

在資料目錄清單裡找到已遷移的目錄，按一下「還原」。符號連結遷移的目錄會把資料複製回本機再刪掉連結和外部副本；掛載遷移的目錄會把卷宗上的資料複製回本機再刪除卷宗，外接磁碟要保持連接。

## 其他 <a href="#其他" id="其他"></a>

### AppPorts 會收集我的資料嗎？ <a href="#appports-會收集我的資料嗎" id="appports-會收集我的資料嗎"></a>

不會。AppPorts 完全離線執行，不收集、不上傳使用者資料。日誌檔案儲存在本機 `~/Library/Application Support/AppPorts/` 目錄下。

### 如何回報問題？ <a href="#如何回報問題" id="如何回報問題"></a>

請在專案 [Issues](https://github.com/wzh4869/AppPorts/issues) 頁面提交回報。建議同時附上診斷包（選單欄 → 日誌 → 匯出診斷包），以便更快定位問題。
