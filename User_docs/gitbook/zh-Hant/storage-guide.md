# 外接儲存裝置指南

外接儲存裝置的穩定性會直接影響遷移後的應用程式啟動、資料目錄取用和後續更新體驗。建議優先選擇效能穩定、容量充足的外接 SSD。

## 建議設定 <a href="#建議設定" id="建議設定"></a>

| 設定項 | 建議值 | 說明 |
|--------|--------|------|
| 容量 | 256 GB 及以上 | 具體需求取決於遷移的應用程式和資料目錄數量 |
| 介面 | USB 3.0 及以上 / Thunderbolt | USB 2.0 速度較慢，大型應用程式遷移耗時較長 |
| 檔案系統 | APFS | 遷移容器資料的唯一支援格式；也支援複製、快照和空間共享，效能最佳 |

## 介面效能對比 <a href="#介面效能對比" id="介面效能對比"></a>

| 介面 | 理論速度 | 實際遷移速度 | 適用場景 |
|------|----------|-------------|----------|
| USB 2.0 | 480 Mbps | ~30 MB/s | 不建議，遷移大型應用程式時耗時較長 |
| USB 3.0 (USB-A) | 5 Gbps | ~350 MB/s | 基本夠用 |
| USB 3.1 Gen 2 (USB-C) | 10 Gbps | ~700 MB/s | 建議 |
| Thunderbolt 3/4 | 40 Gbps | ~2500 MB/s | 最佳效能 |
| NVMe (Thunderbolt) | 40 Gbps | ~2800 MB/s | 最佳效能 |

## 檔案系統建議 <a href="#檔案系統建議" id="檔案系統建議"></a>

### APFS（建議） <a href="#apfs-建議" id="apfs-建議"></a>

- 支援複製、快照和空間共享
- 效能最佳，尤其適合 SSD
- macOS 原生支援
- **遷移容器資料（`~/Library/Containers/`，如微信聊天記錄）只支援 APFS 外接磁碟**，原因和實驗見[為什麼外接磁碟必須是 APFS](why-apfs.md)

### HFS+ <a href="#hfs" id="hfs"></a>

- 相容性較好，適合舊款 Mac
- 不支援複製和快照
- 適合機械硬碟

### exFAT <a href="#exfat" id="exfat"></a>

- 跨平台相容性較好，適合在 macOS 與 Windows 之間共用
- 不支援硬連結和複製
- 效能相對較低
- 適合需要在多系統間交換檔案的場景
- 不能遷移容器資料；需要同時兼顧 Windows 時，可以使用獨立的 APFS 分割區給 AppPorts。exFAT 佔滿整個磁碟時，系統內建工具無法直接縮小它，需先備份再重新分割區，見[分割區條件與處理方式](why-apfs.md#prepare-apfs)

## 容量規劃 <a href="#容量規劃" id="容量規劃"></a>

AppPorts 遷移後的外接儲存裝置使用量取決於遷移的應用程式和資料目錄大小。以下為常見應用程式的參考大小：

| 應用程式類型 | 大小 |
|----------|------|
| Chrome | ~500 MB |
| Microsoft Office | ~5 GB |
| Adobe Creative Cloud | ~20-50 GB |
| Xcode | ~15 GB |
| Final Cut Pro | ~5 GB |
| 本機大語言模型（Ollama） | ~4-30 GB |

{% hint style="success" %}
**容量建議**

- 輕度使用（5-10 個應用程式）：128 GB
- 中度使用（10-20 個應用程式）：256 GB
- 重度使用（20+ 應用程式 + 資料目錄）：512 GB 及以上
{% endhint %}

## 注意事項 <a href="#注意事項" id="注意事項"></a>

- 外接儲存裝置需保持連接；離線時，已遷移的應用程式和資料目錄將無法使用。
- 建議定期備份外接儲存裝置上的重要資料。
- 遷移過程中不要拔出外接儲存裝置，避免複製中斷或狀態不一致。
- 拔除磁碟前先退出使用外接資料的應用程式；掛載遷移的目錄建議先在 AppPorts 裡按一下「卸載」。
- 不要手動用一般檔案佔用 AppPorts 的外部資料目錄目標路徑；AppPorts 只會接回或正規化真實目錄。
- 如果外接儲存裝置出現故障，可在恢復連線後嘗試透過 AppPorts 將應用程式遷回本機。
