# 문제 해결

## 이중 클릭해도 반응이 없고 아이콘이 곧 사라짐 <a href="#이중-클릭해도-반응이-없고-아이콘이-곧-사라짐" id="이중-클릭해도-반응이-없고-아이콘이-곧-사라짐"></a>

가장 흔한 원인은 AppPorts로 재서명한 앱이 macOS 27 업그레이드 후 자신의 컨테이너 접근을 거부당하는 것입니다. 모든 재서명 앱이 해당하는 것은 아니지만 WeChat에서 확인했습니다. 데이터는 손상되지 않았습니다.

확인 방법:

```bash
codesign -dv --verbose=4 /Applications/<应用名>.app 2>&1 | grep -E "Signature|TeamIdentifier"
# 出现 Signature=adhoc 和 TeamIdentifier=not set 即是
```

복구 순서: 컨테이너 데이터 복원 → 공식 경로에서 재설치 → 필요하면 마운트 마이그레이션. **다시 재서명하지 마세요.** 데이터만 복원하고 해결됐다고 생각해서도 안 됩니다. 전체 단계는 [macOS 27 업그레이드 안내](macos-27.md#undefined)를 참고하세요.

## 마운트 마이그레이션 실패 <a href="#마운트-마이그레이션-실패" id="마운트-마이그레이션-실패"></a>

| 안내 | 원인 | 처리 방법 |
|------|------|------|
| 외장 저장 장치가 APFS가 아님 | exFAT / NTFS / HFS+ | 그대로 유지해도 됩니다. 컨테이너 데이터만 이 Mac에 두고 다른 항목은 평소처럼 옮기세요. 나중에 APFS 드라이브를 쓰거나 [APFS 준비](why-apfs.md#prepare-apfs)를 따르세요. 기본 도구로 exFAT를 직접 줄일 수는 없습니다 |
| 외장 저장 장치가 암호화됨 | 암호화된 APFS이며 새 볼륨은 암호를 상속하지 않음 | 그대로 유지하거나 암호화되지 않은 APFS 위치 선택. [암호화된 외장 드라이브](why-apfs.md#encrypted-drives) 참고 |
| 공간 부족 | 마이그레이션 시 외장 또는 복원 시 이 Mac의 공간 부족 | 공간을 확보한 뒤 재시도. 볼륨 생성과 복사 전에 검사하므로 데이터는 변경되지 않음 |
| 디스크 명령 실패 … `kDAReturnNotPrivileged` | macOS 12 등 이전 시스템이 일반 사용자의 사용자 지정 경로 마운트를 허용하지 않음 | AppPorts가 관리자 암호 창으로 재시도하므로 암호 입력. 1.9.0 이전에는 이 단계가 없음 |
| 관리자 인증 취소 | 암호 창을 취소함 | 작업 다시 실행 |
| 마운트 지점이 비어 있지 않음 | 볼륨이 없을 때 앱이 로컬 폴더에 기록함 | 파일을 다른 곳으로 옮긴 뒤 ‘마운트’ |
| 마운트 후 검증 실패 | 볼륨이 예상 경로에 있지 않음 | 진단 패키지를 내보내 Issue 제출 |
| 외장 볼륨을 찾을 수 없음 | 드라이브 미연결 또는 볼륨 삭제 | 연결 후 새로 고침. 볼륨을 삭제했다면 데이터 복구 불가 |

실패하면 AppPorts가 새 볼륨을 삭제하고 원래 디렉토리를 복원합니다. 디스크 유틸리티에서 `AppPorts-`로 시작하는 잔여 볼륨이 없는지 확인할 수 있습니다.

## 마운트 마이그레이션 후 앱에 데이터가 보이지 않음 <a href="#마운트-마이그레이션-후-앱에-데이터가-보이지-않음" id="마운트-마이그레이션-후-앱에-데이터가-보이지-않음"></a>

다음 순서대로 확인하세요.

1. **드라이브 연결과 마운트 여부:** ‘앱 데이터’에서 해당 디렉토리가 ‘마운트됨’이어야 합니다. ‘마운트 대기 중’이면 ‘마운트’를 누르고 ‘외장 드라이브 연결 안 됨’이면 드라이브를 연결하세요.
2. **권한 창에서 거부했는지:** 시스템 설정 → 개인정보 보호 및 보안 → 파일 및 폴더에서 앱의 ‘이동식 볼륨’을 켜세요. 터미널에서 `tccutil reset SystemPolicyRemovableVolumes <Bundle ID>`를 실행해 다시 묻게 할 수도 있습니다.
3. **시스템 기본 앱인지:** `/System/Applications` 아래 앱은 권한 창 없이 거부됩니다. AppPorts는 이런 앱의 데이터 마이그레이션을 지원하지 않습니다.
4. 시스템 로그 확인:

   ```bash
   log show --last 2m --style compact 2>/dev/null | grep -E "deny\(1\)|RemovableVolumes"
   ```

   `kTCCServiceSystemPolicyRemovableVolumes`가 나오면 2번에 해당합니다.

## 마이그레이션 후 앱이 시작되지 않음 <a href="#마이그레이션-후-앱이-시작되지-않음" id="마이그레이션-후-앱이-시작되지-않음"></a>

1. 외장 드라이브가 연결되었는지 확인하세요.
2. ‘고아 링크’는 외장 앱이 사라졌다는 뜻이므로 링크를 해제해야 합니다.
3. 손상 메시지가 나오면 먼저 재설치하세요. 그래도 안 될 때 우클릭 ‘이 앱 재서명’을 고려하되 샌드박스 앱은 거부됩니다. [재서명과 충돌 방지](datamigrae/resign.md)를 참고하세요.
4. `uchg`로 잠긴 앱의 자체 업데이터가 작동하지 않는 것은 정상입니다.
5. 메뉴 막대 → ‘로그’ → ‘Finder에서 보기’에서 관련 오류를 찾으세요.
6. ‘외부 드라이브’에서 ‘이 Mac으로 다시 이동’을 실행해 드라이브가 원인인지 확인하세요.

## 서명 복원 실패 <a href="#서명-복원-실패" id="서명-복원-실패"></a>

| 원인 | 처리 방법 |
|------|------|
| 백업 파일 없음 | 복구 기록이 없으므로 공식 경로에서 재설치. 이미 정리됐을 수도 있어 기록 부재만으로 재서명 여부를 판단할 수 없음 |
| 이전 백업에 원본 앱이 없음 | 같은 버전의 공식 원본 `.app` 선택 또는 재설치. 새 전체 백업은 개발자 개인 키 불필요 |
| 앱 업데이트 또는 백업 검증 실패 | 현재 앱과 백업을 보존하고 덮어쓰기 중단. 일치하는 공식 원본 선택 또는 재설치 |
| 시스템 보호로 앱 교체 불가 | 앱과 백업 보존. App Store 또는 공식 설치 프로그램으로 재설치 |
| 앱 소유자가 root | 소유자 변경을 위한 관리자 암호 창 표시. 취소하면 실패 |
| 샌드박스 앱 | 기본적으로 재서명 거부. 클래식 모드로 재서명했다면 컨테이너 데이터를 먼저 복원한 뒤 원본 서명 복원 |

## 마이그레이션 중단 <a href="#마이그레이션-중단" id="마이그레이션-중단"></a>

외장 드라이브 분리, 시스템 충돌, AppPorts 강제 종료 시:

- **심볼릭 링크 마이그레이션:** AppPorts를 다시 열면 외장 디렉토리의 `.appports-link-metadata.plist`를 검사합니다. 완전히 일치하면 자동으로 이어서 처리하고 아니면 확인을 기다립니다. 목록의 ‘정리 필요’ 또는 ‘다시 연결 대기’를 확인하세요.
- **마운트 마이그레이션:** 작업 중 실패는 자동 롤백합니다. AppPorts 자체를 강제 종료했다면 다시 연 뒤 원래 디렉토리를 확인하세요. 그대로 있으면 정상이며 추가로 생긴 `AppPorts-` 볼륨은 디스크 유틸리티에서 삭제할 수 있습니다. 원래 디렉토리가 `.appports-migration-backup-*`로 바뀌었다면 원래 이름으로 되돌리세요.

## 외장 저장 장치 오프라인 <a href="#외장-저장-장치-오프라인" id="외장-저장-장치-오프라인"></a>

- 심볼릭 링크 디렉토리: 유효하지 않은 경로를 가리켜 앱이 데이터를 읽지 못합니다.
- 마운트 마이그레이션 디렉토리: 빈 디렉토리로 보이며 앱이 로컬 데이터를 기록하지 않습니다.
- 실제 앱: 로컬 실행 껍데기는 외장 앱을 열 수 없지만 껍데기 자체가 충돌하지는 않습니다.

다시 연결하면 자동으로 재스캔하고 볼륨을 다시 마운트합니다. 이전 시스템은 관리자 암호를 한 번 입력해야 합니다.

## App Store 앱을 외장으로 옮길 수 없음 <a href="#app-store-앱을-외장으로-옮길-수-없음" id="app-store-앱을-외장으로-옮길-수-없음"></a>

**macOS 15.1 미만:** 기본 외장 설치를 지원하지 않습니다. AppPorts 설정에서 ‘Mac App Store 앱 마이그레이션 허용’을 켜고 수동으로 옮기세요. 앱 업데이트 후에도 다시 옮겨야 합니다.

**macOS 15.1 이상:** App Store 설정에서 큰 앱을 별도 디스크에 다운로드하고 설치하는 옵션을 켜고 AppPorts와 같은 드라이브를 선택하세요.

## 대상이 이미 존재한다는 안내 <a href="#대상이-이미-존재한다는-안내" id="대상이-이미-존재한다는-안내"></a>

- **앱:** ‘내보내기 대기’에 해당하는 이전 사본이나 AppPorts가 인식하는 이전 진입점이 아니면 중단합니다. Finder에서 대상이 무엇인지 확인한 뒤 결정하세요.
- **데이터 디렉토리:** 일치하는 AppPorts 표식이 없으면 자동으로 관리하지 않습니다. 크기가 비슷해도 덮어쓰지 않으므로 내용을 확인하고 수동 처리하세요.
- **로컬 복원:** 같은 이름의 실제 앱이나 다른 외장 앱을 가리키는 링크는 덮어쓰지 않습니다.

## 데이터 디렉토리 목록 표시 이상 <a href="#데이터-디렉토리-목록-표시-이상" id="데이터-디렉토리-목록-표시-이상"></a>

1. AppPorts는 파일 시스템 변화를 감시해 보통 자동으로 새로 고칩니다.
2. 앱을 빠르게 바꿔도 이전 결과가 현재 앱을 덮어쓰지 않습니다. 잠깐 빈 목록이 보이면 스캔이 끝날 때까지 기다리세요.
3. 갱신되지 않으면 상단 새로 고침 버튼을 누르세요.
4. 계속 이상하면 로그의 스캔 오류를 확인하세요.
