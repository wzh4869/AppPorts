# 자주 묻는 질문

## 설치와 권한 <a href="#설치와-권한" id="설치와-권한"></a>

### AppPorts에는 어떤 권한이 필요한가요? <a href="#appports에는-어떤-권한이-필요한가요" id="appports에는-어떤-권한이-필요한가요"></a>

`/Applications`를 읽고 수정하기 위해 **전체 디스크 접근 권한**이 필요합니다. 처음 실행할 때 안내하며, 시스템 설정 → 개인정보 보호 및 보안 → 전체 디스크 접근 권한에서 AppPorts를 수동으로 추가할 수도 있습니다.

### 어떤 macOS 버전을 지원하나요? <a href="#어떤-macos-버전을-지원하나요" id="어떤-macos-버전을-지원하나요"></a>

최소 macOS 12.0(Monterey)을 지원합니다. macOS 15.1(Sequoia) 이상에서는 App Store 앱을 외장 저장 장치에 설치하고 그 자리에서 업데이트할 수도 있습니다.

### NAS나 네트워크 마운트 드라이브를 외장 저장 장치로 사용할 수 있나요? <a href="#nas나-네트워크-마운트-드라이브를-외장-저장-장치로-사용할-수-있나요" id="nas나-네트워크-마운트-드라이브를-외장-저장-장치로-사용할-수-있나요"></a>

AppPorts는 주로 이동식 하드 드라이브, 외장 SSD, 외장 케이스 같은 로컬 외장 저장 장치를 대상으로 합니다. NAS, SMB, rclone, SFTP 마운트 경로도 이론적으로 macOS 파일 시스템 경로로 쓸 수 있지만 안정성, 권한, 지연 시간, 연결 복구 능력은 마운트 방식에 달려 있습니다.

시험하려면 중요하지 않은 앱이나 다시 만들 수 있는 데이터 디렉토리부터 사용하고 다음을 확인하세요.

- AppPorts 실행 전에 마운트 경로에 접근할 수 있어야 합니다.
- 네트워크 연결이 끊긴 뒤 같은 경로에 자동으로 다시 마운트되어야 합니다.
- 앱에 필요한 권한, 확장 속성, 심볼릭 링크 동작을 지원해야 합니다.
- WeChat, 가상 머신, 게임 라이브러리 같은 고가치·고빈도 쓰기 데이터부터 옮기지 마세요.

## 앱 마이그레이션 <a href="#앱-마이그레이션" id="앱-마이그레이션"></a>

### /Applications 밖의 앱은 어떻게 스캔하나요? <a href="#applications-밖의-앱은-어떻게-스캔하나요" id="applications-밖의-앱은-어떻게-스캔하나요"></a>

‘로컬 앱’ 제목 오른쪽의 ‘+’를 눌러 추가 스캔할 디렉토리를 선택하세요. JetBrains Toolbox, Steam처럼 사용자 지정 위치에 앱을 설치하는 도구에 적합합니다. 추가한 디렉토리는 저장되어 다음 실행 때 자동 스캔하고 변경도 감시합니다. 제목에 사용자 지정 디렉토리 수가 표시되며 그 메뉴에서 목록을 보거나 제거할 수 있습니다.

### 옮긴 앱이 열리지 않으면 어떻게 하나요? <a href="#옮긴-앱이-열리지-않으면-어떻게-하나요" id="옮긴-앱이-열리지-않으면-어떻게-하나요"></a>

1. 외장 저장 장치가 연결되어 접근 가능한지 확인하세요.
2. ‘고아 링크’면 외장 앱이 사라진 것이므로 링크를 수동 해제해야 합니다.
3. 손상 메시지가 나오면 먼저 재설치하세요. 그래도 안 될 때 우클릭 ‘이 앱 재서명’을 시도하되 샌드박스 앱은 거부됩니다.
4. 해결되지 않으면 ‘외부 드라이브’에서 ‘이 Mac으로 다시 이동’으로 로컬 실행 상태를 복구하세요.
5. 이중 클릭해도 반응이 없고 아이콘만 잠깐 나타난다면 [macOS 27 업그레이드 안내](macos-27.md)를 참고하세요.

### 손상되었다는 메시지가 나오면 어떻게 하나요? <a href="#손상되었다는-메시지가-나오면-어떻게-하나요" id="손상되었다는-메시지가-나오면-어떻게-하나요"></a>

대개 macOS 코드 서명 검사가 앱 번들 구조의 변경을 감지한 것입니다.

1. 공식 사이트나 App Store에서 다시 다운로드해 설치하세요. 대부분 해결됩니다.
2. 계속 표시되면 AppPorts에서 앱을 우클릭하고 ‘이 앱 재서명’을 선택하세요. 원본 서명을 백업한 뒤 Ad-hoc 재서명합니다.
3. 샌드박스 앱은 재서명 후 macOS 27에서 열리지 않을 수 있어 거부합니다. 이런 앱은 재설치해야 합니다.

자세한 내용은 [재서명과 충돌 방지](datamigrae/resign.md)를 참고하세요.

### 외장 저장 장치를 뽑으면 앱이 충돌하나요? <a href="#외장-저장-장치를-뽑으면-앱이-충돌하나요" id="외장-저장-장치를-뽑으면-앱이-충돌하나요"></a>

로컬 진입점(Stub Portal)은 `open`으로 외장 앱을 열려고 합니다. 드라이브가 없으면 앱은 시작되지 않지만 진입점 자체는 충돌하지 않습니다. 다시 연결하면 정상적으로 사용할 수 있습니다.

### 옮긴 앱에 바로가기 화살표가 남아 있는 이유는 무엇인가요? <a href="#옮긴-앱에-바로가기-화살표가-남아-있는-이유는-무엇인가요" id="옮긴-앱에-바로가기-화살표가-남아-있는-이유는-무엇인가요"></a>

이전 AppPorts에서 생길 수 있는 현상입니다. 새 버전은 일반 `.app`에 기본적으로 Stub Portal을 사용하므로 로컬에 보통의 앱 아이콘이 표시되고 대개 화살표가 없습니다.

화살표가 남아 있다면 예전 진입점이 전체 심볼릭 링크를 사용하고 있을 가능성이 큽니다. 앱을 이 Mac으로 복원한 뒤 현재 버전으로 다시 옮기는 것이 좋습니다.

### 마이그레이션 후 앱을 업데이트할 수 있나요? <a href="#마이그레이션-후-앱을-업데이트할-수-있나요" id="마이그레이션-후-앱을-업데이트할-수-있나요"></a>

앱 유형에 따라 다릅니다.

| 앱 유형 | 자동 업데이트 | 설명 |
|----------|:---:|------|
| 자체 업데이터가 없는 네이티브 앱 | ✓ | 기존 방식으로 업데이트 가능 |
| Chrome, Edge 등 사용자 지정 업데이터 | ✓ | 업데이트를 로컬에 설치하며 더 높은 버전을 감지하면 ‘내보내기 대기’ 표시 |
| Sparkle / Electron 앱 | ✗ | 잠금 후 앱 내부 업데이트 차단. AppPorts로 로컬 복원 후 업데이트 필요 |
| App Store 앱(macOS 15.1+) | ✓ | App Store가 외장 드라이브에서 직접 업데이트 |
| App Store 앱(macOS <15.1) | ✗ | 수동으로 다시 마이그레이션 필요 |

### ‘내보내기 대기’는 무슨 뜻인가요? <a href="#내보내기-대기-는-무슨-뜻인가요" id="내보내기-대기-는-무슨-뜻인가요"></a>

로컬에 실제 앱이 있으며 AppPorts가 외장 저장 장치의 같은 앱보다 새 버전이라고 판단한 상태입니다. Chrome, Edge 등의 업데이터가 로컬에 새 버전을 설치하고 외장에는 이전 버전이 남은 경우가 대표적입니다.

다시 외장으로 마이그레이션하면 로컬 새 버전이 외장 이전 사본을 교체합니다. AppPorts는 Bundle ID를 우선 비교하고 필요하면 정규화한 이름으로 확인합니다. 버전이 없거나 비교할 수 없거나 같은 이름의 Bundle ID가 다르면 이 상태를 표시하지 않습니다.

### 외장 대상이 이미 있으면 덮어쓰나요? <a href="#외장-대상이-이미-있으면-덮어쓰나요" id="외장-대상이-이미-있으면-덮어쓰나요"></a>

바로 덮어쓰지는 않습니다. 다음 경우에만 외장 대상을 자동 정리하고 계속합니다.

- ‘내보내기 대기’ 상태이며 외장 대상이 같은 앱의 이전 사본입니다.
- AppPorts가 만든 이전 Stub Portal, Deep Contents Wrapper 또는 전체 심볼릭 링크 진입점으로 인식됩니다.
- AppPorts 마이그레이션 과정의 이전 잔여 항목입니다.

소유 관계를 확인할 수 없는 실제 앱이나 디렉토리가 있으면 대상 충돌을 알리고 중단해 사용자 데이터를 잘못 삭제하지 않도록 합니다.

### App Store 앱은 어떻게 외장 드라이브로 옮기나요? <a href="#app-store-앱은-어떻게-외장-드라이브로-옮기나요" id="app-store-앱은-어떻게-외장-드라이브로-옮기나요"></a>

**macOS 15.1+:** App Store 설정에서 큰 앱을 별도 디스크에 다운로드하고 설치하는 옵션을 켜고 AppPorts의 외부 앱 라이브러리와 같은 저장 장치를 선택하세요.

**macOS <15.1:** AppPorts의 ‘Mac App Store 앱 마이그레이션 허용’을 켜세요. 수동으로 옮겨야 하며 업데이트 후에도 외장 사본을 바꾸기 위해 다시 옮겨야 합니다.

### 마이그레이션 전에 ‘보호된 앱’이 표시되는 이유는 무엇인가요? <a href="#마이그레이션-전에-보호된-앱-이-표시되는-이유는-무엇인가요" id="마이그레이션-전에-보호된-앱-이-표시되는-이유는-무엇인가요"></a>

App Store 앱이나 root 소유 앱은 대개 macOS 권한으로 보호되어 AppPorts가 로컬 사본을 직접 삭제하거나 바꾸지 못할 수 있습니다. Finder에서 앱을 외장 저장 장치로 직접 드래그하고 관리자 암호를 입력한 뒤 AppPorts에서 로컬 링크를 만드는 편이 더 확실합니다. 자동 마이그레이션을 계속할 수도 있지만 권한 부족으로 실패할 수 있습니다.

### App Store 업데이트 후 ‘다음으로 열기’가 여러 개이거나 버전이 다릅니다 <a href="#app-store-업데이트-후-다음으로-열기-가-여러-개이거나-버전이-다릅니다" id="app-store-업데이트-후-다음으로-열기-가-여러-개이거나-버전이-다릅니다"></a>

v1.8.0 이상은 외장 앱의 버전을 로컬 Stub Portal에 자동 동기화하며 ‘다음으로 열기’ 메뉴도 갱신합니다. 계속 다르면 새로 고침 버튼으로 수동 동기화하세요.

v1.7.0 이하에서는 다음과 같이 처리합니다.

1. AppPorts를 열고 로컬 및 외장 앱 목록을 새로 고칩니다.
2. 로컬 버전이 더 높으면 다시 마이그레이션해 외장 사본을 교체합니다.
3. 로컬 진입점만 이상하다면 링크를 해제한 뒤 외부 앱 라이브러리에서 ‘로컬로 다시 연결’을 실행합니다.

macOS 15.1 이상에서는 버전이 갈라지는 일을 줄이기 위해 App Store의 기본 외장 설치를 우선 권장합니다.

### 문서를 이중 클릭하면 앱은 열리지만 파일이 열리지 않습니다 <a href="#문서를-이중-클릭하면-앱은-열리지만-파일이-열리지-않습니다" id="문서를-이중-클릭하면-앱은-열리지만-파일이-열리지-않습니다"></a>

Office, WPS처럼 파일 연결 인수에 의존하는 앱에서 흔합니다. 이전 Stub Portal은 외장 앱만 실행하고 문서 경로를 올바르게 전달하지 못할 수 있습니다. v1.6.2 이상으로 업그레이드한 뒤 앱을 로컬로 복원하고 다시 마이그레이션하거나 외부 앱 라이브러리에서 ‘로컬로 다시 연결’을 실행하세요.

계속되면 진단 패키지를 내보내 Issue를 제출하세요. 설치 출처(App Store, 공식 `.pkg`, DMG 등)와 재현 단계를 함께 적어주세요.

### Adobe, Office 같은 앱 제품군도 옮길 수 있나요? <a href="#adobe-office-같은-앱-제품군도-옮길-수-있나요" id="adobe-office-같은-앱-제품군도-옮길-수-있나요"></a>

시도할 수 있지만 단일 `.app`이 아니라 여러 앱, 공유 구성 요소, 백그라운드 서비스와 인증 모듈로 구성된 경우가 많습니다. AppPorts는 가능한 한 디렉토리 단위로 처리하지만 호환성은 앱 자체 구조에 달려 있습니다.

제품군의 모든 앱을 종료하고 로그인이나 활성화가 완료됐는지 확인한 뒤 옮기세요. 인증 문제, 연결된 파일 열기 실패, 구성 요소 누락이 생기면 로컬로 복원하고 용량이 큰 독립 앱이나 데이터 디렉토리만 옮겨보세요.

### 마이그레이션이 느리거나 멈춘 것 같아요 <a href="#마이그레이션이-느리거나-멈춘-것-같아요" id="마이그레이션이-느리거나-멈춘-것-같아요"></a>

- 100% 부근에서 로컬 진입점을 만들고 마지막 검사를 하느라 1~2초 멈출 수 있습니다.
- Xcode, Adobe 같은 대형 앱은 오래 걸리는 것이 정상입니다.
- 오랫동안 진행되지 않으면 외장 연결이 안정적인지 확인하세요.
- USB 2.0은 느리므로 USB 3.0 이상이나 Thunderbolt를 권장합니다.

## 데이터 디렉토리 마이그레이션 <a href="#데이터-디렉토리-마이그레이션" id="데이터-디렉토리-마이그레이션"></a>

### 데이터를 옮기면 앱 데이터가 사라지나요? <a href="#데이터를-옮기면-앱-데이터가-사라지나요" id="데이터를-옮기면-앱-데이터가-사라지나요"></a>

정상적인 경우에는 아닙니다. 먼저 외장으로 완전히 복사하고 성공을 확인한 뒤 로컬 원래 디렉토리를 삭제하고 심볼릭 링크를 만듭니다. 어느 단계든 실패하면 자동 롤백을 시도합니다.

대상이 이미 있으면 `.appports-link-metadata.plist`가 현재 원본 경로, 대상 경로, 데이터 디렉토리 유형과 완전히 일치할 때만 복구를 이어갑니다. 일치하는 메타데이터가 없는 실제 디렉토리는 충돌로 보며 크기가 비슷하다는 이유로 관리하거나 덮어쓰지 않습니다.

### 데이터 디렉토리 마이그레이션이 앱 문제를 일으키는 경우는 무엇인가요? <a href="#데이터-디렉토리-마이그레이션이-앱-문제를-일으키는-경우는-무엇인가요" id="데이터-디렉토리-마이그레이션이-앱-문제를-일으키는-경우는-무엇인가요"></a>

- 앱이 파일 잠금이나 SQLite WAL 로그를 사용합니다.
- 심볼릭 링크를 통한 접근에서 확장 속성이 사라지거나 다르게 동작합니다.
- 같은 Team의 여러 앱이 `Group Containers`를 공유합니다.

`~/Library/Containers/`와 `~/Library/Group Containers/`는 심볼릭 링크 대신 마운트 마이그레이션을 사용합니다. APFS 외장 드라이브가 필요하고 앱 첫 실행 때 권한을 허용해야 합니다. [마운트 마이그레이션](datamigrae/mount-migration.md)을 참고하세요.

### WeChat 채팅 기록을 외장 드라이브에 둘 수 있나요? <a href="#wechat-채팅-기록을-외장-드라이브에-둘-수-있나요" id="wechat-채팅-기록을-외장-드라이브에-둘-수-있나요"></a>

네, ‘마운트 마이그레이션’을 사용하세요. ‘앱 데이터’에서 WeChat을 선택하면 `Containers`의 계정별 `xwechat_files` 하위 디렉토리와 `Application Support/com.tencent.xinWeChat` 모두 마운트 마이그레이션할 수 있습니다. 외장 드라이브는 APFS여야 합니다. 완료 후 처음 WeChat을 열 때 권한을 허용하세요.

이전 버전의 마이그레이션과 재서명 조합은 **사용하지 마세요**. macOS 27에서 WeChat이 열리지 않게 됩니다.

### WeChat 데이터를 옮긴 뒤 채팅 기록이 보이지 않습니다 <a href="#wechat-데이터를-옮긴-뒤-채팅-기록이-보이지-않습니다" id="wechat-데이터를-옮긴-뒤-채팅-기록이-보이지-않습니다"></a>

두 경우를 구분하세요.

- **1.9.0 마운트 마이그레이션:** 외장 연결, ‘마운트됨’ 상태, 권한 거부 여부를 확인하세요. [문제 해결](troubleshooting.md#마운트-마이그레이션-후-앱에-데이터가-보이지-않음)을 참고하세요.
- **이전 심볼릭 링크 마이그레이션:** 샌드박스 WeChat은 컨테이너 밖 데이터를 읽지 못합니다. 고장이 아니라 시스템 동작 방식입니다. AppPorts에서 디렉토리를 먼저 로컬로 ‘복원’하세요. 당시 재서명에 동의했다면 공식 사이트에서 WeChat도 재설치해야 합니다. [macOS 27 복구 단계](macos-27.md#복구)를 참고하세요.

재서명으로 고치려 하지 **마세요**. 상황만 악화됩니다.

### exFAT 외장 드라이브에 WeChat 데이터를 옮길 수 있나요? <a href="#exfat-외장-드라이브에-wechat-데이터를-옮길-수-있나요" id="exfat-외장-드라이브에-wechat-데이터를-옮길-수-있나요"></a>

마운트 마이그레이션은 APFS만 지원하므로 불가능합니다. **그대로 사용해도 괜찮습니다.** WeChat 데이터는 이 Mac에 두고 앱과 다른 데이터 디렉토리는 해당 드라이브로 평소처럼 옮기세요. 나중에 옮기려면 다른 APFS 드라이브를 쓰는 것이 가장 간단합니다. 기존 드라이브에 미할당 공간이 있다면 파티션 배치 조건에 맞춰 APFS 파티션을 만들 수 있습니다. exFAT가 전체를 차지한다면 macOS와 Windows 기본 도구로 직접 줄일 수 없으므로 백업 후 다시 파티션해야 합니다. exFAT 안의 여유 공간은 미할당 공간과 다릅니다. 디스크 이미지를 두는 우회 방법도 시험했지만 분리 시험에서 이미지 전체가 망가져 제공하지 않습니다. [APFS가 필요한 이유](why-apfs.md#what-to-do)를 참고하세요. 실제 앱과 다른 데이터 디렉토리는 이 제한을 받지 않습니다.

### 마운트 마이그레이션 후 Finder에 디스크 아이콘이 추가되나요? <a href="#마운트-마이그레이션-후-finder에-디스크-아이콘이-추가되나요" id="마운트-마이그레이션-후-finder에-디스크-아이콘이-추가되나요"></a>

아닙니다. 데이터 볼륨은 Finder 사이드바와 데스크탑에 표시되지 않습니다. 연결 직후 1~2초 잠깐 보일 수 있지만 다시 연결되면 사라집니다. 디스크 유틸리티에는 `AppPorts-…` 볼륨이 보이며 옮긴 데이터가 들어 있으므로 지우거나 삭제하지 마세요. [마운트 마이그레이션의 일상 사용](datamigrae/mount-migration.md#일상-사용)을 참고하세요.

### 암호화된 외장 드라이브는 왜 마운트 마이그레이션할 수 없나요? <a href="#암호화된-외장-드라이브는-왜-마운트-마이그레이션할-수-없나요" id="암호화된-외장-드라이브는-왜-마운트-마이그레이션할-수-없나요"></a>

새 데이터 볼륨은 원래 볼륨의 암호를 상속하지 않습니다. 그대로 옮기면 보호받던 데이터가 암호 없는 볼륨에 저장됩니다. AppPorts는 몰래 보호 수준을 낮추지 않고 중단합니다. [암호화된 외장 드라이브](why-apfs.md#encrypted-drives)를 참고하세요.

### AppPorts를 삭제하기 전에 무엇을 해야 하나요? <a href="#appports를-삭제하기-전에-무엇을-해야-하나요" id="appports를-삭제하기-전에-무엇을-해야-하나요"></a>

마운트 마이그레이션을 썼다면 ‘앱 데이터’에서 해당 디렉토리를 이 Mac으로 ‘복원’하세요. 생략해도 외장 볼륨에 데이터는 남지만 로그인 후 다시 연결해 줄 프로그램이 없어 앱에 빈 디렉토리가 보입니다. AppPorts를 재설치하고 한 번 열면 복구됩니다.

### macOS 27 업그레이드 후 앱이 갑자기 안 열리는 것은 예전 데이터 마이그레이션 때문인가요? <a href="#macos-27-업그레이드-후-앱이-갑자기-안-열리는-것은-예전-데이터-마이그레이션-때문인가요" id="macos-27-업그레이드-후-앱이-갑자기-안-열리는-것은-예전-데이터-마이그레이션-때문인가요"></a>

데이터는 정상이며 서명이 문제입니다. 이전 컨테이너 마이그레이션에서 재서명에 동의하면 샌드박스 신원이 제거됩니다. macOS 27은 자신의 컨테이너 접근을 거부하기 시작합니다. 데이터 복원 후 앱을 재설치하세요. [macOS 27 업그레이드 안내](macos-27.md)를 참고하세요.

### Crossover, Parallels, 가상 머신이나 게임 라이브러리도 옮기기 적합한가요? <a href="#crossover-parallels-가상-머신이나-게임-라이브러리도-옮기기-적합한가요" id="crossover-parallels-가상-머신이나-게임-라이브러리도-옮기기-적합한가요"></a>

실제 앱보다 가상 머신 이미지, 컨테이너, 게임 라이브러리, 모델 캐시가 공간을 많이 차지하는 경우가 많습니다. 앱 자체를 옮기기보다 ‘데이터 디렉토리’와 ‘도구 디렉토리’에서 해당 대형 디렉토리를 인식했는지 먼저 확인하는 것이 좋습니다.

가상 디스크, 데이터베이스, 자주 기록하는 파일이 있다면 외장 저장 장치 성능이 안정적인지 확인하고 먼저 백업하세요. 이런 고빈도 쓰기 데이터를 네트워크 마운트 드라이브에 바로 두는 것은 권장하지 않습니다.

### 옮긴 데이터 디렉토리는 어떻게 복원하나요? <a href="#옮긴-데이터-디렉토리는-어떻게-복원하나요" id="옮긴-데이터-디렉토리는-어떻게-복원하나요"></a>

목록에서 마이그레이션한 디렉토리를 찾아 ‘복원’을 누르세요. 심볼릭 링크 방식은 데이터를 로컬로 복사한 뒤 링크와 외장 사본을 삭제합니다. 마운트 방식은 볼륨 데이터를 로컬로 복사한 뒤 볼륨을 삭제합니다. 외장 드라이브를 계속 연결해 두세요.

## 기타 <a href="#기타" id="기타"></a>

### AppPorts는 내 데이터를 수집하나요? <a href="#appports는-내-데이터를-수집하나요" id="appports는-내-데이터를-수집하나요"></a>

아닙니다. AppPorts는 완전히 오프라인으로 작동하며 사용자 데이터를 수집하거나 업로드하지 않습니다. 로그는 로컬 `~/Library/Application Support/AppPorts/`에 저장됩니다.

### 문제는 어떻게 알리나요? <a href="#문제는-어떻게-알리나요" id="문제는-어떻게-알리나요"></a>

프로젝트 [Issues](https://github.com/wzh4869/AppPorts/issues)에 제출하세요. 메뉴 막대 → ‘로그’ → ‘진단 패키지 내보내기’로 만든 진단 패키지를 첨부하면 원인을 더 빨리 찾을 수 있습니다.
