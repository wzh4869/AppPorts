# 설정

AppPorts 설정은 기본 윈도우 오른쪽 상단의 톱니바퀴 아이콘에서 열 수 있습니다.

## App Store 및 iOS 설정 <a href="#app-store-및-ios-설정" id="app-store-및-ios-설정"></a>

| 설정 | 설명 | 기본값 |
|--------|------|--------|
| Mac App Store 앱 마이그레이션 허용 | App Store 앱을 마이그레이션하도록 허용합니다. macOS 15.1 이전 버전에서 이 앱을 옮기려면 직접 켜야 합니다 | 꺼짐 |
| 비기본 앱 마이그레이션 허용 | Mac용 iOS/iPadOS 앱 마이그레이션을 허용합니다 | 꺼짐 |

{% hint style="success" %}
**macOS 15.1+ 사용자**

macOS 15.1 이상에서는 App Store 앱을 외장 저장 장치에 직접 설치할 수 있습니다. AppPorts의 수동 마이그레이션 스위치보다 App Store 설정의 “대용량 앱을 별도의 디스크에 다운로드 및 설치”를 먼저 사용하는 것이 좋습니다.
{% endhint %}

## 서명 설정 <a href="#서명-설정" id="서명-설정"></a>

| 설정 | 위치 | 설명 | 기본값 |
|--------|------|------|--------|
| 마이그레이션 후 재서명 | 데이터 디렉토리 페이지 상단 도구 막대. **클래식 모드에서만 표시** | 심볼릭 링크 마이그레이션이 끝나면 연결된 앱에 Ad-hoc 재서명을 수행합니다 | 꺼짐 |
| 로그인 시 자동 재서명 | 설정 페이지 | 서명 백업에서 원래 Ad-hoc 서명이었던 앱을 로그인할 때 다시 서명하여 재시동 후 서명이 무효화되는 문제를 처리합니다. 샌드박스 앱은 건너뛰지만 클래식 모드에서는 건너뛰지 않습니다 | 새 설치에서는 꺼짐. 이미 로그인 에이전트를 설치한 기존 사용자는 켜짐 유지 |

클래식 모드가 아니면 어떤 경로에서도 샌드박스 앱을 재서명하지 않습니다. 재서명한 샌드박스 앱은 macOS 27에서 열리지 않을 수 있기 때문입니다. 컨테이너 데이터는 서명을 변경할 필요가 없는 [마운트 마이그레이션](datamigrae/mount-migration.md)으로 옮깁니다.

원본 앱 전체 백업이 있는 새 기록은 로그인 스크립트가 다시 서명하지 않습니다. 서명 작업은 AppPorts가 검증하고 안전하게 교체하는 방식으로 처리합니다. AppPorts를 시작할 때 설치된 스크립트도 동기화합니다.

“로그인 시 자동 재서명”은 LaunchAgent `com.shimoko.AppPorts.re-sign`을 설치하며, 로그를 AppPorts의 기본 로그 파일에 기록합니다. 재서명과 백업은 로컬 실행 셸이 아니라 외장 드라이브의 실제 앱에 적용됩니다. [재서명 및 충돌 방지](datamigrae/resign.md)를 참조하세요.

## 클래식 데이터 마이그레이션 모드(권장하지 않음) <a href="#classic-data-migration-mode" id="classic-data-migration-mode"></a>

설정 페이지 하단에 있는 스위치로, 기본값은 꺼짐입니다. 이미 1.8.1의 이전 방식에 의존하고 있어 당장 전환할 수 없는 사용자를 위해서만 남겨 두었습니다. 외장 드라이브가 APFS가 아니라면 이 모드를 켜서 APFS 요구 사항을 우회하지 말고 컨테이너 데이터를 Mac에 둔 채 현재 상태를 유지하는 것이 좋습니다. [외장 드라이브에 APFS가 필요한 이유](why-apfs.md#what-to-do)를 참조하세요. 켜기 전에 확인 대화상자에서 “위 위험을 이해했습니다”를 선택해야 합니다. macOS 27에서는 재서명한 샌드박스 앱이 열리지 않을 수 있다는 안내가 스위치 옆에 표시됩니다. 켜면 다음과 같이 바뀝니다.

| 항목 | 꺼짐(기본값) | 켜짐 |
|------|--------------|------|
| 컨테이너 디렉토리 버튼 | “마운트 마이그레이션”만 표시 | “마이그레이션”(심볼릭 링크)과 “마운트 마이그레이션”을 나란히 표시 |
| 컨테이너 마이그레이션 전 재서명 대화상자 | 표시 안 함 | 표시하며, 기본값은 “동의하지 않음, 마이그레이션만” |
| 샌드박스 앱 재서명 | 모든 경로에서 거부 | 허용하지만 매번 결과를 설명하는 추가 확인 필요 |
| “마이그레이션 후 재서명” 스위치 | 표시 안 함 | 데이터 디렉토리 페이지 도구 막대에 표시 |
| 컨테이너 디렉토리의 “정리”, “다시 연결”, “링크 세부 정보” | 비활성화하고 복원 후 마운트 마이그레이션하도록 안내 | 사용 가능 |

클래식 모드는 위험까지 포함하여 이전 방식을 그대로 되살립니다. 재서명한 샌드박스 앱이 macOS 27에서 열리지 않으면 데이터를 복원하고 앱을 다시 설치해야 합니다. AppPorts는 이러한 앱에 “서명 교체됨” 배지를 표시하고 시작할 때 알려 줍니다. [macOS 27 업그레이드 안내](macos-27.md)를 참조하세요. 클래식 모드를 꺼도 기존 심볼릭 링크 마이그레이션 항목은 변경되지 않으며 “복원”을 계속 사용할 수 있습니다.

## 마운트 마이그레이션 관련 설정 <a href="#마운트-마이그레이션-관련-설정" id="마운트-마이그레이션-관련-설정"></a>

마운트 마이그레이션에는 별도 설정 항목이 없습니다. 설정 페이지의 “준비 상태”에서 전체 디스크 접근 권한, AppPorts 설치 위치, 외장 저장 장치의 형식을 검사하고 어떤 항목을 처리해야 하는지 알려 줍니다. 첫 마운트 마이그레이션에 성공하면 AppPorts가 로그인 에이전트 `com.shimoko.AppPorts.container-mount`를 설치합니다. 로그인 후 연결된 볼륨을 컨테이너 디렉토리에 자동으로 다시 마운트하며, 마지막 마운트 기록을 복원하면 에이전트도 자동으로 제거됩니다. macOS 12 등 이전 시스템에서는 에이전트가 관리자 암호 대화상자를 표시할 수 없으므로 로그인 후 AppPorts를 열어 다시 마운트해야 합니다.

## 로그 설정 <a href="#로그-설정" id="로그-설정"></a>

| 설정 | 설명 | 기본값 |
|--------|------|--------|
| 로깅 활성화 | 실행 로그를 파일에 기록합니다 | 켜짐 |
| 최대 로그 크기 | 로그 파일이 한도를 넘으면 이전 내용의 절반을 자동으로 잘라냅니다 | 2 MB |
| 로그 위치 | 로그 파일 저장 경로 | `~/Library/Application Support/AppPorts/AppPorts_Log.txt` |

### 로그 작업 <a href="#로그-작업" id="로그-작업"></a>

| 작업 | 설명 |
|------|------|
| Finder에서 보기 | 로그 파일이 있는 폴더를 엽니다 |
| 진단 패키지 내보내기 | 로그, 작업 기록, 시스템 정보를 포함한 ZIP 파일을 만듭니다 |
| 로그 지우기 | 현재 로그 파일의 내용을 지웁니다 |

자세한 내용은 [로깅 및 진단](logging.md)을 참조하세요.

수동 백업, 재서명 또는 복원 전에 AppPorts는 이번 로그인 세션의 백그라운드 재서명 작업을 중지하고 하위 프로세스가 종료될 때까지 기다립니다. 이렇게 하면 방금 복원한 서명을 백그라운드에서 덮어쓰지 않습니다. 로그인 에이전트 설정은 유지되며 다음 로그인 때도 스위치 설정에 따라 실행됩니다. 백그라운드 작업이 중지되었는지 확인할 수 없으면 이번 수동 작업은 중단됩니다.
