# 故障排除

## 应用双击无反应，图标闪一下就没了 <a href="#应用双击无反应-图标闪一下就没了" id="应用双击无反应-图标闪一下就没了"></a>

最常见的原因：这个应用被 AppPorts 重签名过，升级到 macOS 27 后被系统拒绝访问自己的容器（不是每个重签名过的应用都会，微信已确认）。数据没有坏。

确认方法：

```bash
codesign -dv --verbose=4 /Applications/<应用名>.app 2>&1 | grep -E "Signature|TeamIdentifier"
# 出现 Signature=adhoc 和 TeamIdentifier=not set 即是
```

修复：还原容器数据 → 从官方渠道重装 → 需要的话再挂载迁移。**不要**再点重签名，也不要只还原数据就当修好。完整步骤见 [macOS 27 升级说明](macos-27.md#xiu-fu)。

## 挂载迁移失败 <a href="#挂载迁移失败" id="挂载迁移失败"></a>

| 提示 | 原因 | 处理 |
|------|------|------|
| 外部存储不是 APFS 格式 | 外置盘是 exFAT / NTFS / HFS+ | 可以保留现状：容器数据留在本机，其它照常迁移。想迁移时换一块 APFS 盘，或按[准备 APFS 外置盘](why-apfs.md#prepare-apfs)操作；exFAT 不能用系统自带工具直接缩小 |
| 外部存储已加密 | 外置盘是加密的 APFS，新建的数据卷不会继承密码 | 保留现状，或改选未加密的 APFS 位置，见[加密的外置盘](why-apfs.md#encrypted-drives) |
| 空间不足 | 外置盘（迁移）或本机（还原）剩余空间不够 | 清理空间后重试；检查在建卷或复制之前进行，没有改动任何数据 |
| 磁盘命令执行失败 … `kDAReturnNotPrivileged` | 旧系统（如 macOS 12）不允许普通用户挂到自定义路径 | AppPorts 会弹管理员密码框重试，输入密码即可；1.9.0 之前的版本没有这一步 |
| 用户取消了管理员授权 | 密码框被取消 | 重新执行一次 |
| 挂载点目录不为空 | 卷没挂时应用在本地目录里写了文件 | 把目录里的文件移走再点「挂载」 |
| 挂载后校验失败 | 卷挂上了但不在预期路径 | 导出诊断包提交 Issue |
| 找不到外置卷 | 外置盘没连接，或卷被删了 | 连上外置盘后刷新；卷已被删则数据不可恢复 |

失败时 AppPorts 会回滚：删掉新建的卷，把原目录改回来。可以在磁盘工具里确认没有残留的 `AppPorts-` 开头的卷。

## 挂载迁移后应用看不到数据 <a href="#挂载迁移后应用看不到数据" id="挂载迁移后应用看不到数据"></a>

按顺序检查：

1. **外置盘是否连接、卷是否挂载**：AppPorts「应用数据」页里该目录状态应是「已挂载」。「待挂载」就点「挂载」，「外置盘未连接」就连上外置盘。
2. **授权框是不是点了拒绝**：系统设置 → 隐私与安全性 → 文件和文件夹，找到该应用把「可移动宗卷」打开；或终端执行 `tccutil reset SystemPolicyRemovableVolumes <Bundle ID>` 让它下次重新问。
3. **是不是系统自带应用**：`/System/Applications` 下的应用不会弹授权框，直接拒绝，AppPorts 不支持迁移它们的数据。
4. 看系统日志：

   ```bash
   log show --last 2m --style compact 2>/dev/null | grep -E "deny\(1\)|RemovableVolumes"
   ```

   出现 `kTCCServiceSystemPolicyRemovableVolumes` 就是第 2 条。

## 应用迁移后无法启动 <a href="#应用迁移后无法启动" id="应用迁移后无法启动"></a>

1. 确认外置盘已连接。
2. 看应用状态徽章：「孤立链接」表示外置盘上的应用丢了，需要解除链接。
3. 如果系统提示「已损坏」，先试重装；仍不行再考虑右键「重签名」，注意沙盒应用会被拒绝，见[重签名与崩溃防护](datamigrae/resign.md)。
4. 被 `uchg` 锁定的应用，自更新程序可能无法运行，属于预期。
5. 菜单栏 → 日志 → 在 Finder 中查看，搜索相关错误。
6. 在外部应用库里「迁回本地」，确认问题是否由外置盘引起。

## 签名恢复失败 <a href="#签名恢复失败" id="签名恢复失败"></a>

| 原因 | 处理 |
|------|------|
| 备份文件不存在 | 没有可用恢复记录，请从官方渠道重装；记录也可能已被清理，不能据此判断是否重签过 |
| 旧版备份不含原始应用 | 选择同版本官方原版 `.app`，或重装。新版完整备份不需要开发者私钥 |
| 应用已更新或备份校验失败 | 保留当前应用和备份，停止覆盖；选择匹配的官方原版或重新安装 |
| 应用受系统保护，无法替换 | 保留当前应用与备份；通过 App Store 或官方安装器重装 |
| 应用归 root 所有 | 会弹管理员密码框修改所有者，取消则失败 |
| 应用是沙盒应用 | 默认拒绝重签名；经典模式重签后，先还原容器数据，再恢复原始签名 |

## 迁移中断 <a href="#迁移中断" id="迁移中断"></a>

外置盘断开、系统崩溃或 AppPorts 被强退时：

- **符号链接迁移**：重新打开 AppPorts，它会检查外置盘目录里的 `.appports-link-metadata.plist`，完整匹配时自动接续，否则停下等你确认。列表里看「待规范」或「待接回」。
- **挂载迁移**：过程中失败会自动回滚。如果 AppPorts 本身被强退，重新打开后：原目录如果还在就没事，多出来的 `AppPorts-` 卷可以在磁盘工具里删掉；原目录变成了 `.appports-migration-backup-*` 就把它改回原名。

## 外部存储离线 <a href="#外部存储离线" id="外部存储离线"></a>

- 符号链接迁移的目录：链接指向无效路径，应用读不到数据。
- 挂载迁移的目录：显示为空目录，应用不会写本地数据。
- 应用本体：本地启动壳打不开外置盘上的应用，但壳本身不会崩。

重新连接后 AppPorts 会自动重新扫描，挂载迁移的卷会自动挂回。旧系统需要输一次管理员密码。

## App Store 应用无法迁移到外置盘 <a href="#app-store-应用无法迁移到外置盘" id="app-store-应用无法迁移到外置盘"></a>

**macOS 15.1 以下**：系统不支持原生外置安装。在 AppPorts 设置里开启「App Store 应用迁移」手动迁移，应用更新后要再迁一次。

**macOS 15.1 及以上**：App Store 设置 → 开启「下载并安装大型 App 到独立存储盘」，选和 AppPorts 相同的外置盘。

## 迁移时提示目标已存在 <a href="#迁移时提示目标已存在" id="迁移时提示目标已存在"></a>

- **应用**：外部目标不是「待迁出」对应的旧副本，也不是 AppPorts 能识别的旧入口时会停下。到 Finder 里确认那个目标是什么再决定。
- **数据目录**：外部目录没有匹配的 AppPorts 标记时不会自动接管，不会因为大小相近就覆盖。确认内容后手动处理。
- **迁回本地**：本地已有同名真实应用，或不属于当前外部应用的链接时不覆盖。

## 数据目录列表显示异常 <a href="#数据目录列表显示异常" id="数据目录列表显示异常"></a>

1. AppPorts 监控文件系统变化，通常会自动刷新。
2. 快速切换应用时旧结果不会覆盖当前应用；短暂看到空列表等扫描完成即可。
3. 没刷新就点顶部刷新按钮。
4. 持续异常看日志里的扫描错误。
