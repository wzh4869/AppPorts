# 外接磁碟與日常使用

外接磁碟會成為遷移後應用或資料的實際存放位置。選擇連線穩定、空間足夠的裝置，比只看標稱速度更重要；需要頻繁啟動應用或讀寫小檔案時，外接 SSD 通常更合適。

## 哪些操作需要 APFS {#apfs}

| 要做的事 | 儲存要求 |
| --- | --- |
| 容器資料的掛載遷移 | 目前需要 APFS 儲存，檢查通過後才能繼續。 |
| 普通應用、工具目錄或自選資料夾遷移 | 按所選內容、檔案系統能力和權限檢查，不能據容器要求一概判斷。 |
| NAS（SMB 共享）或非 APFS 外接磁碟存放應用 | 直接複製受伺服器端權限和檔案系統能力限制；可建立 [APFS 應用庫映像](/docs/storage-guide#app-library-image) 來完整保留應用簽名與檔案屬性。直接掛載的網路目錄本身不能替代容器 APFS 掛載遷移。 |

若只是想遷移普通應用，不需要先為了容器功能重格式化整塊磁碟。格式不合適時，可以換一個目標、使用應用庫映像存放應用，或讓容器資料留在本機。原因見[資料遷移方式](/docs/datamigrae/baseinfo)。

## 使用 APFS 應用庫映像 {#app-library-image}

在左側邊欄「目的地儲存」右側選單（`…`）中，可以使用 APFS 稀疏捆綁映像（`.sparsebundle`）作為外部應用庫，按實際寫入佔用空間，適合已掛載的 SMB 共享或 exFAT 等外接磁碟：

1. 確保 AppPorts 位於「應用程式」資料夾，且承載映像的共享或外接磁碟已在 Finder 中掛載。
2. 在「目的地儲存」選單選擇「建立APFS鏡像」（填寫存放位置、磁碟名稱和最大容量後點選「建立並使用」），或選擇「開啟現有影像...」。
3. AppPorts 會核對承載儲存身份（SMB 共享位址或底層卷宗 UUID）與映像內 APFS 卷宗 UUID，不會覆蓋已有檔案，也不會按卷名猜測目標。

開啟「設定 → 背景代理」中的「磁碟維護代理」後，登入、卷宗變化和背景每分鐘檢查都會嘗試恢復目前選取的應用庫映像；已重新整理本機入口（版本 8）的應用在雙擊啟動前，也會先無視窗接回所需映像及映像內關聯的資料卷宗。若升級自較早版本，請在映像線上時開啟一次 AppPorts 完成掃描，以重新整理本機入口。

不再需要掛載時，可在「目的地儲存」的退出選單選擇「卸載映像」。**主動卸載映像會持續暫停自動掛載**：重新啟動 AppPorts、重新插拔外接磁碟或重連 NAS 都不會自動解除，只有明確選擇「再次安裝映像」（或重新開啟該映像）才會恢復。

使用映像時請留意以下邊界：

- **映像不是獨立備份**：映像損壞、NAS 故障或網路中斷仍需獨立備份保障；同一映像同一時間只在一台 Mac 上寫入。
- **僅自動恢復目前選取的映像**：歷史映像需手動重新掛載；結束 AppPorts 不會自動卸載映像，因為遷出的應用可能仍在執行。
- **憑據、底層掛載與卷名**：SMB 未儲存系統憑據時需先在 Finder 重連，加密卷宗仍需解鎖；映像掛載路徑依賴卷名，在 Finder 中改名會導致核驗失敗，改回原名即可恢復。
- **簽名原包仍需實體外接磁碟**：`AppPorts Backups` 不使用磁碟映像，手動重簽應用時仍需連線合適的本機實體外接磁碟。

## 準備 APFS 儲存 {#prepare-apfs}

1. 先備份盤上已有內容，在「磁碟工具程式」中檢視裝置和卷宗的格式。
2. 已有合適的 APFS 儲存時，返回 AppPorts 選擇該位置並重新檢查。
3. 確需更改格式時，先確認備份可用，再按磁碟工具程式的說明操作。**抹掉磁碟會清除所選物件的資料**，不能把它當作普通的設定開關。

AppPorts 會為掛載遷移建立專用資料卷宗；通常無需自己為每個資料目錄預建卷宗或指定固定大小。

## 加密的外接磁碟 {#encrypted-drives}

AppPorts 支援在加密 APFS 目標上建立獨立加密的資料卷宗。遷移檢查後按「設定資料卷宗密碼」輸入並確認密碼，再繼續遷移；它不會繼承外接磁碟現有密碼，也不會更改原磁碟密碼和檔案。微信拆分遷移的多個新卷宗共用本次設定。

儲存到本機鑰匙圈以便連接外接磁碟後自動解鎖的選項預設勾選，可取消。儲存僅用於這台 Mac，不同步密碼；未儲存或鑰匙圈不可用時，需要手動解鎖，背景不會反覆彈出密碼框。密碼不寫入遷移記錄或日誌；未儲存的密碼在程序內暫存，結束後可能需要重新輸入。請妥善保存密碼，遺忘後無法恢復加密資料。

普通未加密 APFS 目標也能遷移，但磁碟遺失後他人可能讀取其中資料；同磁碟另一卷宗有密碼不代表新卷宗也已加密。查看遷移前提示並確認新卷宗的保護方式，不要為了通過檢查先解除已有加密。

## 外接磁碟是否記得檔案屬於誰 {#owners}

macOS 的某些儲存不保存檔案擁有者：exFAT 和 FAT32 沒有這個欄位；HFS+ 在以忽略擁有權的方式掛載時，新建檔案會被記成預留使用者。一般讀寫不受影響，但少數以管理員權限核對歸屬的應用（例如帶特權背景服務的 clash-verge）會拒絕工作，並給出 `chown` 修復建議——這條指令在這類卷上會被核心靜默丟棄，看似成功、實際無效。

APFS 即使在忽略擁有權的掛載下也保存真實歸屬，因此不在提示範圍。遷移一般資料目錄或自選資料夾時，AppPorts 會在確認框中說明目標磁碟的這個情況，不阻擋繼續。建議把這類應用的資料留在本機，或改用 APFS 格式的磁碟；HFS+ 可以在 Finder 的「顯示簡介」裡取消「忽略此磁碟區上的擁有權」後重新遷移。exFAT 沒有這個開關。

## 每天怎樣連線和斷開 {#daily}

- 使用前先連線外接磁碟，必要時開啟 AppPorts，確認資料狀態為「已掛載」或連結正常。
- 斷開前儲存工作，結束正在使用外接磁碟資料的應用，正常退出儲存裝置。
- 重啟或重新插盤後，開啟了「磁碟維護代理」的系統會在磁碟上線、解鎖和系統授權後嘗試自動接回，但不能保證早於所有登入應用。
- 移動或更新 AppPorts 後開啟一次，讓背景代理核對程式位置。

遷移不是備份。請檢查自己的備份工具是否覆蓋外接磁碟，尤其是重要的聊天記錄、專案和個人檔案。

## 空間、換盤和離線 {#space}

預留更新、複製和恢復所需的額外空間，不要只按目前資料夾大小把外接磁碟裝滿。APFS 卷宗可能共享空間，刪除或還原後的可用容量也可能稍後才更新；側欄僅展示本機磁碟與目標儲存的實際容量使用，不再用外部檔案邏輯大小估算本機節省空間。

換盤前先[還原到本地](/docs/restore#data)，再選擇新目標重新遷移。直接拖動受管資料或改卷名、目錄結構，可能讓已有入口失效。外接磁碟找不到、資料沒有接回時，先看[問題排查](/docs/faq#offline)。

## 外接磁碟上的簽名原包 {#signature-backups}

手動重簽官方應用後，外接磁碟可能出現可見的 `AppPorts Backups` 資料夾。AppPorts 自動選擇合適外接磁碟儲存完整官方原包，裡面的 `README.txt` 說明用途與刪除影響；應用仍在內建磁碟時也採用這一方式。恢復時需要接回儲存原包的磁碟，保留資料夾原位置。

原包不包含個人資料，也不是另一套獨立災備。內建磁碟應用重簽時仍需要臨時空間，跨卷儲存經核驗完成後才清理內部原件。選擇外接磁碟、檢視和清理的方法見[簽名原包說明](/docs/settings#signature-backups)。

## 從 AppPorts 退出整塊外接磁碟 {#eject}

1. 儲存工作，結束使用外接磁碟應用或資料的程式，等待進行中的檔案操作結束。
2. 在側欄「目的地儲存」區域的退出選單選擇「退出外接磁碟」。此操作針對**整塊實體磁碟及其所有卷宗**，包括接到本機資料目錄的專用卷宗，不只是目前選取的應用庫。
3. AppPorts 先暫停該磁碟的自動掛載，再請求 Finder 退出。已發出請求不代表已經退出；按系統結果和選單狀態確認後再拔除。
4. 仍有卷宗掛載或系統拒絕時，結束佔用程式後使用「重試退出」，不要強行拔除。

主動退出實體外接磁碟後，即使取消了 Finder 的退出或全部卷宗已卸載，自動掛載仍保持暫停。**拔下並重新插入裝置**，識別到同一磁碟的新連接後才會恢復；重新整理列表、重開 AppPorts 或等待逾時都不代替重插，也沒有手動取消暫停並恢復掛載的按鈕。注意這與「卸載映像」或資料目錄中單個資料卷宗的「卸載」不同：後兩者不會因重新插拔磁碟解除暫停，需手動選擇「再次安裝映像」或「掛載 / 恢復自動掛載」。出現權限錯誤時，檢查 Finder 自動化權限並保留提示。
