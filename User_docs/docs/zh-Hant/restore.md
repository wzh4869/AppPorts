# 還原、接回與解除連結

先確認你想改變的是**存放位置**還是**存取入口**。開始前連線原來的外接磁碟，儲存工作並結束相關應用；還原到本機還需要足夠的本地空間。

## 選擇正確的操作 {#choose}

| 目的 | 操作 | 完成後的資料位置 |
| --- | --- | --- |
| 把應用從外接磁碟搬回 Mac | 遷移回本地 | 真實應用回到本機。 |
| 把已遷移的資料搬回原目錄 | 還原 | 資料回到本機原位置。 |
| 應用在外接磁碟，只缺啟動入口 | 連結回本地 | 真實應用仍在外接磁碟。 |
| 資料在外接磁碟，本地連結丟了 | 接回 | 資料仍在外接磁碟，重建本地存取入口。 |
| 資料卷宗線上但未接到原目錄 | 掛載 / 恢復自動掛載 | 資料仍在外接磁碟，恢復原路徑存取與自動掛載。 |
| 暫時斷開單個已掛載的資料卷宗 | 卸載 | 資料仍在外接磁碟，本機留唯讀空目錄並持續暫停自動掛載。 |
| 外接磁碟不在，只移除資料軟連結並重建空目錄 | 連結詳情 → 強制解除連結 | 本機變為空目錄，外接磁碟原件保留不動。 |
| 只移除應用的本地入口 | 本地列表列右側 `…`（更多操作）或右鍵選單 → 刪除本機入口 | 外接磁碟上的真實應用保留。 |

## 把應用遷回本地 {#apps}

1. 在外部應用庫選取應用，點選「遷移回本地」。
2. 核對本地目標。若外接磁碟本身缺少部分檔案屬性能力，AppPorts 會在應用套件外探測並提示副本可能已降級；存在同名真實應用或其他衝突時也請先處理提示，不要自行覆蓋。
3. 等待複製、檢查和收尾完成。遷回時也會一併清除關聯更新快取上的保護鎖。
4. 從 Finder 或 Dock 開啟應用，檢查它現在使用的本地副本。

遷回應用本體不會自動遷回另行管理的資料。需要一起恢復時，繼續處理下面的資料目錄。

## 把資料還原到原位置 {#data}

1. 在「應用程式資料」「工具目錄」或「目錄遷移」中找到受管項目，點選「還原」。符合條件的舊容器符號連結也可透過恢復流程直接遷回本機，不會自動重簽應用。
2. 確認應用已結束、原外接磁碟線上、本機空間足夠。
3. 等待 AppPorts 將資料複製回原位置並完成切換。
4. 開啟應用檢查內容和儲存功能，確認最終狀態。

還原完成後，AppPorts 會處理可安全清理的外部副本或專用卷宗。若提示仍有保留內容或未完成清理，先保留它們並按提示繼續；不要把「能開啟應用」當成全部收尾已經完成。

## 只恢復入口 {#reconnect}

應用顯示「未連結」或只有外部副本時，選取後使用「連結回本地」。資料顯示「待接回」時，核對外部目標後使用「接回」；指向預期受管位置的現有連結在確認後也可補齊管理記錄。「待掛載」的容器卷宗使用「掛載」；若先前手動點過單個資料卷宗的「卸載」，自動掛載會一直保持暫停，直到你明確點選「掛載」或「恢復自動掛載」。

這些操作不把資料搬回內建磁碟。若本地原位置已經產生新內容，先確認兩份資料的用途，不能用覆蓋來強行恢復入口。

對「現有軟連結」使用「規範化管理」前，目標必須是實際存在的目錄。目標遺失、是一般檔案或本身仍是符號連結時，無法使用此按鈕。若外接磁碟離線且你想取回資料，請先接回原磁碟，再確認目標。掃描會過濾微信容器內指向 `~/Library` 的 macOS 系統捷徑，AppPorts 也會阻擋還原或解除這些連結。

## 解除應用連結與資料強制解除連結 {#unlink}

在本地應用列表中，找到已連結應用並點選列右側的 `…`（「更多操作」）按鈕或右鍵開啟選單，選擇「刪除本機入口」；孤立連結也可在列操作或右鍵選單中選擇「刪除孤立連結」。這會移除 AppPorts 管理的本地入口，外接磁碟上的真實應用保留。**它不是資料目錄的還原操作。** 之後仍可重新「連結回本地」。

對工具目錄或普通資料目錄，如果外接磁碟已不在身邊、不需要取回舊內容，只想讓應用重新產生本機檔案，可在「連結詳情」中選擇「強制解除連結」。確認後 AppPorts 會移除本機軟連結、清理對應的舊連結記錄並在原路徑建立空目錄，無需連線外接磁碟，也不會刪除外接磁碟原件；之後新產生的本機資料不會與外接磁碟舊資料自動合併。

刪除 AppPorts 前，先還原仍由它管理的容器資料；否則自動掛載任務可能失去所需程式。中斷、離線或目標衝突的處理見[常見問題與排查](/docs/faq)。

## 處理未完成操作與保留副本 {#recovery}

在「任務中心」開啟需要處理的任務，點擊「處理異常」，先看目前遷移記錄。面板會分開列出「目前資料」與「保留的舊副本」路徑，幫助判斷哪一份正在使用。結束關聯應用，接好並解鎖原磁碟；權限不足時使用「檢查權限」，再重試。重試範圍以面板列出的項目為準，「重試所有待處理項」可能涉及多筆記錄。

| 資料異常面板中的選擇 | 實際作用 |
| --- | --- |
| 重試／重新嘗試清理 | 重新檢查並繼續相應操作；不會強制刪除有差異的舊檔案。 |
| 授權清理舊副本 | 資料已切換但保留的舊副本歸屬管理員（root）時顯示；按系統密碼框授權清理，取消則保留副本，背景不會反覆彈窗。 |
| 稍後處理 | 暫停自動處理，保留檔案，之後可以主動重試。 |
| 打開舊副本 | 在資料已切換、位置核對通過時查看保留內容。 |
| 保留副本並結束清理 | 僅在資料已切換後提供；停止自動清理和異常提醒，舊副本仍佔空間，可再開啟或單獨重試清理。 |

主體遷移完成但舊副本尚未清理時，任務仍可能顯示「需要處理」。背景完成了舊現場清理，也不能據此把原遷移判為成功；請結合目錄實際狀態核對。移除任務歷史不會解決這些記錄。

應用異常面板另有「重試處理」「忽略錯誤結束任務」和「忽略錯誤強制回遷」。優先重試正常處理。「忽略錯誤結束任務」只把原記錄歸檔為未完成並保留檔案；**「忽略錯誤強制回遷」不進行內容驗證**，會在複製成功後替換本機入口，保留外接磁碟原件及已有本機副本，原記錄仍歸檔為未完成。只有理解確認框含義並願意自行檢查結果時才使用，不能視為正常還原成功。

若任務中心裡需要處理的是背景「應用程式更新守護」同步來的 ShipIt 更新記錄，詳細資料會提供「復原更新」：核對存在完整且簽名有效的更新前舊版時，將其恢復回外接磁碟原路徑、重新整理本機入口，並直接清理本次更新的下載快取與暫存副本，不建立額外歸檔目錄；若無法確認完整舊版，則保留現場並說明原因。
