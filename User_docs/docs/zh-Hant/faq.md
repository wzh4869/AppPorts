# 常見問題與排查

先儲存工作，記下 AppPorts 顯示的狀態和錯誤提示。涉及資料不可見或遷移中斷時，保留原磁碟與現有副本，再按下面的現象檢查。

## 升級後開關已開啟，為什麼仍提示缺少權限 {#permissions-after-upgrade}

如果升級後「App 管理」或「完整磁碟取用權限」的開關已開啟，但 AppPorts 仍提示缺少權限，請依[準備狀況與系統權限](/docs/settings#permissions)重新授權。舊項目仍未生效時，可在「準備狀況」清理舊版授權記錄。

*系統權限清單中找不到 AppPorts 時，將引導視窗中的 App 圖示拖到「完整磁碟存取權」清單。*

## 應用打不開或開啟後立即退出 {#launch}

先確認原外接磁碟（或應用庫映像）線上、本地入口沒有變成「孤立連結」。如果出現「簽名已替換」，或升級 macOS 27 後才發生問題，按[升級與修復](/docs/macos-27)處理。沒有這類提示時，檢查原應用是否支援目前系統，並保留錯誤資訊；不能把所有啟動失敗都歸因於簽名。

## 應用能開啟，但原來的資料不見了 {#missing-data}

先結束應用，避免繼續向新建的空目錄寫入。開啟 AppPorts，確認對應資料為「已掛載」或連結正常，再檢查原應用是否獲准存取可移動宗卷。外接磁碟上的檔案還在，並不等於原應用已接到這些檔案。若本地和外部都出現新內容，保留兩份，反饋具體路徑型別與狀態，勿直接互相覆蓋。

## 顯示「外接磁碟未連線」或「孤立連結」 {#offline}

重新連線原磁碟，在 Finder 或磁碟工具程式中檢查裝置是否出現，必要時解鎖，再重新整理 AppPorts。若卷宗線上但顯示「待掛載」，使用「掛載」（先前手動卸載過單個資料卷宗時，自動掛載會持續暫停，必須手動點選「掛載」或「恢復自動掛載」）。外接磁碟離線期間，受管本機目錄會呈現為唯讀可瀏覽的空目錄以防止誤寫入，看到空目錄並不代表資料已被刪除或已還原回本機。確認原磁碟和目標位置後仍異常，再[匯出診斷資訊](/docs/faq#feedback)。

## 應用庫映像沒有自動接回或提示核驗失敗 {#image-library}

先確認承載映像的 SMB 共享或外接磁碟已在 Finder 中正常掛載（SMB 未儲存憑據時需先在 Finder 連線，加密卷宗需先解鎖），並確認 AppPorts 位於「應用程式」資料夾且「設定 → 背景代理」中的「磁碟維護代理」已開啟。

若先前在側欄點過「卸載映像」，自動恢復會持續保持暫停，重連 NAS 或重開 AppPorts 不會自動解除，需在「目的地儲存」選單選擇「再次安裝映像」。若在 Finder 中修改過映像卷宗的名稱，掛載路徑變化會導致身份核驗失敗；將卷名改回原名稱後再重新掛載即可恢復。詳見[使用 APFS 應用庫映像](/docs/storage-guide#app-library-image)。

## 掛載遷移的檢查沒有通過 {#mount}

先在設定頁「準備狀況」檢查權限、連線、格式和加密狀態；安裝位置與本次所需空間，以點選遷移後的檢查提示為準。目前容器掛載遷移要求 APFS 儲存；其他內容不應一概套用這一要求。可以更換目標或保留本地資料，詳見[外接磁碟準備](/docs/storage-guide#apfs)。

## 遷移後某個應用說資料目錄不屬於我 {#owners}

這類提示來自應用自己的背景服務，例如 clash-verge 的系統服務拒絕啟動核心（錯誤碼 1012）。原因通常不是權限丟了，而是目標磁碟不保存檔案擁有者：exFAT、FAT32 沒有歸屬欄位，HFS+ 在以忽略擁有權的方式掛載時會把新檔案記成預留使用者。你的帳號看到的是自己，管理員服務看到的是那個預留值，於是判斷不一致。

提示裡常建議執行 `sudo chown`，但在這類卷上系統會靜默丟棄修改，指令看似成功、實際無效。可行的做法是：把這份資料還原到本機；或遷到 APFS 磁碟（APFS 保存真實歸屬）；HFS+ 可在 Finder 的「顯示簡介」中取消「忽略此磁碟區上的擁有權」後重新遷移。exFAT 沒有該開關。詳見[外接磁碟是否記得檔案屬於誰](/docs/storage-guide#owners)。

## 提示目標已存在、保留副本或清理未完成 {#conflict}

先在異常面板核對「目前資料」與「保留的舊副本」各自的位置。「目標衝突」需要確認歸屬；「保留副本」或清理失敗則可能表示主體操作已完成，但收尾尚未結束（舊副本歸屬 root 時可使用「授權清理舊副本」）。按介面提供的重試或保留選項處理，不要重複遷移、手工刪除備份或覆蓋同名目錄。恢復入口、強制解除連結與搬回本地的區別見[還原與接回](/docs/restore)。

## 遷移中斷後應該重來嗎 {#interrupted}

保持原儲存連線，先檢視 AppPorts 的恢復提示。中斷可能發生在複製、切換或清理階段，各階段留下的有效副本不同。保留程式提示的臨時目錄和備份；無法判斷時記錄最後一步和錯誤，不要自行選一份刪除。

## 哪些內容不適合遷移 {#compatibility}

系統應用、受保護的容器結構、整個使用者目錄，以及相互包含的受管目錄都有額外限制。虛擬機器、資料庫和正在下載的遊戲庫還可能有背景寫入，操作前必須完全停止使用它們。AppPorts 能識別一個目錄，不代表該應用支援把它搬到任意儲存。應用已有自己的儲存位置設定時，也可優先使用官方方式。

## 為什麼不允許移動某些容器目錄 {#protected}

有些目錄承擔系統結構作用，例如容器根目錄和特定臨時目錄。即使檔案複製和掛載都成功，應用也可能拒絕啟動。目錄列表中的保護提示需要保留，具體原因見[容器結構實驗](/docs/blog/data-migration-boundaries#starting-point)。

## 如何更新遷移後的應用 {#updates}

先檢視是否有「鎖定遷移」或「非鎖定遷移」提示。「非鎖定遷移」可嘗試繼續使用應用內更新，開啟「設定 → 背景代理」中的「應用程式更新守護」後，AppPorts 可在已適配的 ShipIt 更新失敗時協助完成安裝，並在失敗記錄中提供「復原更新」；「鎖定遷移」的應用若更新受阻，可先遷回本機更新後再遷出。系統管理的 App Store 外接安裝有自己的更新流程。按[應用更新說明](/docs/core#updates)處理，勿為了更新直接刪除外部副本。

## 為什麼磁碟工具裡多了 AppPorts 資料卷 {#volumes}

這些可能是掛載遷移建立的專用卷宗。它們通常不會一直顯示在 Finder 邊欄，但仍存放實際資料。需要撤銷遷移時使用 AppPorts 的「還原」，不要在磁碟工具程式中直接抹掉或刪除這些卷宗。

## 外接磁碟上的 AppPorts Backups 能刪除嗎 {#signature-backups}

這是手動重簽前儲存官方應用原包的資料夾，不是聊天記錄或文件備份。確認不再需要恢復材料、也沒有操作待完成時，可以在 Finder 中刪除對應原包；目前安裝和個人資料不受影響，但之後恢復官方狀態可能需要重新取得官方安裝包。AppPorts 也會自動清理已證明冗餘的原包，詳見[儲存與清理規則](/docs/settings#signature-backup-cleanup)。

恢復提示找不到原包時，先連線儲存它的那塊磁碟，確認資料夾仍在原位置。即使應用沒有遷出內建磁碟，新原包仍儲存在外接磁碟；沒有合適外接磁碟時，新的官方應用重簽會在修改正式應用前停止。

## 刪除 AppPorts 前要做什麼 {#uninstall}

先還原仍由它管理的容器資料，並確認完成清理；若不再需要背景服務，也可先在設定中關閉「磁碟維護代理」與「應用程式更新守護」。單獨刪除程式不會把資料搬回本機，還可能使自動接回失去所需程式。遷移過的應用和普通資料也建議先按[還原說明](/docs/restore)檢查，明確它們目前存在哪裡。

## AppPorts 會自動上傳我的檔案嗎 {#privacy}

遷移操作在本機進行，日誌與診斷包也先儲存在本地。檢查版本、執行應用內下載更新、載入貢獻者與贊助者名單會存取網路，因此不應把應用描述為完全離線。具體資訊和接收方見[隱私政策](/docs/privacy)。

## 怎樣反饋問題 {#feedback}

在 [GitHub Issues](https://github.com/wzh4869/AppPorts/issues) 描述 AppPorts 與 macOS 版本、外接磁碟格式、發生的操作、完整錯誤提示，以及問題是否可重複。透過設定頁「日誌設定 → 匯出診斷包」或選單欄「日誌 → 匯出診斷包」獲取記錄，提交前檢查是否含私人路徑或內容。診斷包不會自動上傳；不要公開聊天記錄、帳戶資料或無關檔案。

## 退出或卸載後不再自動掛載 {#eject}

從 AppPorts 主動「退出外接磁碟」會暫停整塊實體磁碟的自動掛載；即使 Finder 退出被取消，也需要**拔下並重新插入裝置**才能恢復。而主動「卸載映像」或資料目錄中單個卷宗的「卸載」則會持續保留暫停狀態，重新插拔裝置不會自動恢復，需手動選擇「再次安裝映像」或「掛載 / 恢復自動掛載」。仍有卷宗掛載時先結束佔用應用，再「重試退出」，不要強行拔除。步驟見[退出外接磁碟](/docs/storage-guide#eject)。

## 任務顯示暫停、正在取消或需要處理 {#tasks}

暫停須等到可暫停的位置；正在取消須等安全收尾，均不應直接拔除磁碟。「加入背景」只是收起詳細資料，可以從側欄「任務中心」返回。需要處理時查看詳細資料的「處理異常」（背景更新接手失敗時為「復原更新」），保留提示中的副本，按[異常恢復](/docs/restore#recovery)繼續。重新啟動後歷史任務不會自動重做遷移；背景清理結束也不等於原遷移成功。

## 啟動時提示正在遷移應用資料 {#launch-protection}

關聯資料正在遷移、遷回或暫停複製時，更新後的原生啟動入口會提示等待。回到 AppPorts 查看任務並等待結束。此保護不能阻止直接開啟真實應用等其他方式，不要繞過提示強行啟動；範圍見[啟動保護](/docs/datamigrae/operation#launch-protection)。
