# 設定與權限

點選左側邊欄底部的設定齒輪（或按 `Command + ,`）在主視窗開啟設定；權限尚未就緒時，設定齒輪和「準備狀況」的「檢查」按鈕會顯示紅色（已拒絕）或橙色（無法確認）提示點。遷移前先檢視「準備狀況」，按提示完成所需權限與外接儲存檢查；不同 macOS 版本顯示的項目可能不同。

## 應用資訊與應用內更新 {#updates}

設定頁右上方卡片展示目前執行的 AppPorts 版本、實際執行路徑（可選取複製），以及「檢查更新」「官網」「文件」「關於」入口。

點選「檢查更新」發現新版本後，可在更新面板中選擇：

- **國內更新**：從國內來源下載更新包，不依賴 GitHub 連線。
- **GitHub 更新**：下載對應版本的 GitHub Release 附件。

下載期間顯示進度並可取消；驗證完大小、SHA-256、簽名身份、版本、架構與系統要求後，點選「安裝並重新啟動」即可替換並重啟 AppPorts。仍有遷移等任務未結束時會提示先完成任務；自更新期間會暫時掛起「應用程式更新守護」並在更新完成或取消後恢復。應用內安裝需要 AppPorts 位於可寫的本機目錄（例如「應用程式」資料夾），失敗時也可點選「國內下載」透過瀏覽器手動更新。

如果使用 DMG 或 ZIP 手動替換安裝，請開啟一次新版 AppPorts，讓它同步背景代理並處理仍在執行的舊版應用程式更新守護。如果代理狀態仍有異常，請到「背景代理」查看提示並重試。

## 準備狀況與系統權限 {#permissions}

「準備狀況」直接內嵌在右上方卡片中，點選標題右側的「檢查」可重新整理系統權限、外部儲存與 App Store 外接安裝狀態。已就緒的項目以精簡狀態列展示（懸停可查看詳細說明）並收起多餘按鈕；需要處理的項目保留原因與「開啟系統設定」入口。

| 項目 | 用途 | 怎樣處理 |
| --- | --- | --- |
| 完全磁碟訪問 | 讓 AppPorts 讀取和管理受保護的資料位置。 | 點選「開啟系統設定」，授權後按提示重新開啟 AppPorts；找不到圖示時可直接將畫面上的引導浮窗圖示拖入系統設定清單。 |
| App 管理 | 系統要求時，允許修改或管理其他應用套件。 | 系統預檢顯示「已就緒」「需要授權」或「無法確認」；未就緒時點選「開啟系統設定」可直達「App 管理」子頁，並同樣支援拖曳圖示加入。 |
| 可移動宗卷 | 讓遷移後的應用存取外接磁碟資料。 | 原應用首次存取時可能單獨詢問；這與 AppPorts 的權限不同。 |
| 外部儲存 | 檢查連線、格式和加密狀態。 | 按[外接磁碟準備](/docs/storage-guide)選擇合適目標。 |

發起新遷移、建立/開啟/重新掛載應用庫映像以及開啟權限引導前，AppPorts 會檢查自身是否位於「應用程式」資料夾；僅瀏覽清單、掃描應用和把已有資料遷回本機不受這條限制。給 AppPorts 授權不代表其他應用也獲得授權；遇到讀不到資料的問題，先檢查[掛載狀態與原應用權限](/docs/faq#missing-data)。

如果升級後系統設定中的「App 管理」或「完整磁碟取用權限」開關已開啟，但 AppPorts 仍提示缺少權限，系統可能仍在使用舊簽署憑證的授權記錄。出現「需要重新授予系統權限」提示時，請依指示開啟對應設定，將新版 AppPorts 加入清單並開啟開關。如果舊項目仍未生效，請在「準備狀況」按一下「清理舊版授權記錄」，再回到系統設定重新加入並開啟。清理「完整磁碟取用權限」時可能需要確認管理員授權；如果清理失敗，也可以在系統設定中選取舊項目，按 `-` 移除後重新加入。完成後依提示重新開啟 AppPorts，並回到「準備狀況」查看狀態。

## App Store 與非原生應用 {#app-store}

macOS 15.1 及以上顯示「App Store 應用程式外部安裝」卡片，AppPorts 會唯讀核對系統 App Store 的外接安裝設定是否與目前所選外接磁碟一致：

- 一致時顯示「已設定」及實際 `Applications` 目錄；不一致或尚未開啟時，提供「開啟 App Store 設定」入口。
- App Store 自身只對新下載大於 1 GB 的大型應用使用該設定並管理後續更新；**AppPorts 遷移不受 1 GB 限制，任意大小（包括小於 1 GB）的 App Store 應用都可由 AppPorts 遷入該目錄**。
- 選擇或恢復外部儲存時若尚未完成該配置，主介面會彈出提示；點選「不再提醒」（或按 Esc）會持久記住選擇，之後仍可隨時在本頁查看狀態並開啟 App Store 設定。「我已設定」只會重新讀取真實系統狀態，不會靠建立空目錄偽造完成。

較早系統會顯示「允許遷移 Mac App Store 應用」和「允許遷移非原生應用」。開啟前閱讀提示：系統支援、應用更新與裝置要求仍然適用。詳見[遷移應用](/docs/core#updates)。

## 經典資料遷移模式 {#classic-data-migration-mode}

「經典資料遷移模式（不推薦）」預設關閉，為仍需處理舊容器連結方式的使用者保留。開啟需要確認風險，關閉不會還原已有資料，也不會恢復被修改的簽名。

目前遷移與重簽名分開進行。這個開關不會恢復舊版自動重簽流程。適用範圍與轉回方法見[經典模式](/docs/classic-mode)，舊版行為儲存在[歷史功能歸檔](/docs/archive/data-signing)。

## 手動簽名與修復 {#manual-signing}

簽名操作處理的是應用身份，不是把檔案搬到另一個位置。只有明確知道用途時才使用手動重簽；沙盒應用預設受限，經典模式下仍需要針對目前操作確認風險。

應用列表確認某個應用已重簽後，右鍵選單保留「恢復原始簽名」，隱藏重複的「重簽名此應用」。恢復官方狀態後，符合條件的應用才重新顯示重簽入口。檢查結果不明時，先使用「檢查簽名」，不能只看選單判斷應用是否正常。

「恢復原始簽名」需要適用且經核對的原始應用備份，不能拿另一個版本強行替換。有「簽名已替換」提示時，從修復面板開始；沒有可用備份時，按指引使用官方原版。完整步驟見[升級與修復](/docs/macos-27#repair)。

### 原包儲存在哪裡 {#signature-backups}

從 1.9.1 build 31 起，手動重簽官方應用時，AppPorts 將經核對的完整原包儲存在**外接磁碟根目錄可見的 `AppPorts Backups` 資料夾**，並放入中英文 `README.txt`。無需額外選擇備份位置，也沒有單獨的備份管理頁面；可以直接在 Finder 中檢視。

AppPorts 會依次嘗試應用所在的外接磁碟、目前外部應用庫所在的磁碟，再從其他合適的外接磁碟中優先選擇剩餘空間較多的卷宗。目標必須是已連線、可寫且空間足夠的本地實體外接磁碟；內建磁碟、網路盤和磁碟映像不參與選擇。沒有合適外接磁碟時，在修改正式應用前停止。

**應用仍在內建磁碟，也需要連線外接磁碟儲存原包。** 內建磁碟只長期保留小型索引和操作記錄；重簽期間仍需臨時工作空間。原包在同一卷宗內可以直接移入備份目錄；需要跨卷時，先複製並確認外接磁碟原包完整儲存，再清理內部臨時原件。

這些原包用於恢復應用內容和官方簽名，**不包含聊天記錄、文件等應用資料**。它們也不替代獨立備份：同一塊外接磁碟故障時，磁碟上的應用和原包可能同時不可用。

### 恢復與清理原包 {#signature-backup-cleanup}

恢復時連線儲存原包的那塊外接磁碟，在 AppPorts 中對目前應用選擇「恢復原始簽名」。程式會核對版本、內容、開發者身份及相關資料依賴；同一版本即使重複重簽，也仍保留最初的官方原包，不會用重簽後的副本覆蓋它。

AppPorts 會保留仍有恢復價值的原包。在確認應用已經恢復官方狀態，或已安裝經驗證的同開發者官方新版，並排除未完成操作和資料依賴後，才自動清理冗餘原包。舊版留在內建磁碟的有效完整原包會在條件滿足時自動遷到外接磁碟，確認成功後再移除內部副本。

如果確定不再需要這份恢復材料，可以在 Finder 中刪除對應原包。刪除不會移除目前安裝的應用或個人資料，但會失去這份原包提供的離線恢復能力；之後可能需要從官方渠道重灌。移入廢紙簍仍佔空間，APFS 共享資料區塊也使顯示大小不等於最終釋放量。

請保持備份資料夾的位置，不要修改原包內容，也不要把它當作日常應用啟動。外接磁碟暫時離線不等於原包失效；尚有操作未完成時，先按 AppPorts 的提示處理。只有身份名稱的舊記錄如何保留或清理，見[歷史簽名備份](/docs/archive/data-signing#backups)。

### 舊登入任務 {#login-signing}

目前版本在所有 macOS 上停用「開機自動重簽名」，build 31 也已移除對應設定卡。更新後開啟一次 AppPorts，讓它處理舊登入任務；僅清理失敗時，設定才顯示「舊的登入重簽任務尚未完全關閉，請重試。」，此時使用「重試」並保留錯誤資訊。

## 背景代理 {#mount-agent}

「背景代理」卡片包含兩項預設開啟、可分別關閉的登入背景配置：

- **磁碟維護代理**：在登入、外接磁碟重新連線或選取映像的定時檢查時，將線上的受管容器資料卷宗與目前選取的 [APFS 應用庫映像](/docs/storage-guide#app-library-image)接回原位置，並保持 AppPorts 管理的專用 APFS 資料卷宗隱藏。關閉開關會卸載其自動執行配置，保留現有掛載、資料和恢復記錄；前台手動掛載與恢復不受影響。
- **應用程式更新守護**：在 AppPorts 結束後繼續監聽已遷移應用，遇到已適配的 ShipIt 更新明確失敗時自動驗證快取新版並嘗試完成安裝，把結果同步到「任務中心」（失敗項提供「復原更新」）。關閉開關會安全停止自動接手，保留已有收據與副本。它目前僅涵蓋已適配的 ShipIt 更新，不替應用重簽名，也不涵蓋所有其他更新框架。

兩項代理均使用「應用程式」資料夾內已安裝的 AppPorts 無視窗模式執行，不會阻礙主介面正常重新開啟，但也不保證在所有登入應用啟動前完成接回。移動或更新 AppPorts 後開啟一次即可核對並同步配置；若系統背景項目被停用或配置同步報錯，可使用卡片內的「重試」。刪除 AppPorts 前先[還原受管容器資料](/docs/restore#data)。

## 日誌設定 {#logs}

可以在設定卡片中開關日誌記錄、調整最大日誌大小（1 MB 至 100 MB），直接點選「在 Finder 中檢視」「匯出診斷包」或「清空日誌」（選單欄「日誌 → 匯出診斷包」同樣可用）；匯出不會自動傳送。

提交前檢查內容，說明系統版本、AppPorts 版本、發生的操作和介面提示。見[反饋問題](/docs/faq#feedback)與[隱私政策](/docs/privacy)。

## 任務歷史 {#task-history}

「任務中心」卡片中的「結束後清理已完成的任務列表」預設開啟，可關閉以保留成功任務（含背景更新守護已完成記錄）的顯示歷史。「任務中心」頁面的「清空已完成」與列末移除按鈕同樣只影響顯示，不刪除應用或資料，也不刪除用於恢復的遷移或更新收據。

加入背景的遷移任務仍依賴 AppPorts 主程式執行。重新開啟時，上次未結束的遷移任務需要檢查記錄，不會自動從歷史重做遷移。暫停、取消和異常處理見[任務中心](/docs/datamigrae/operation#task-center)及[異常恢復](/docs/restore#recovery)。
