# 关于 AppPorts 的边界与共识

AppPorts 做的，是改变 macOS 与许多应用在设计上的默认前提——在尽量不破坏原有签名与沙盒机制的前提下，将原本默认驻留在内置盘的应用本体与数据，通过启动壳、符号链接或 APFS 卷挂载等方式迁移到你指定的外部存储。

::: warning 核心共识

但请记住：**AppPorts 不是神，它只是一把精密的手术刀。**

:::

## 无法穷举的生态 {#ecosystem}

macOS 生态下有成千上万款应用，每款软件对路径硬编码、沙盒与权限校验（Sandbox / TCC）、文件所有权、签名与自更新机制及后台守护进程的实现各不相同。我们无法穷举测试所有应用，也无法保证 AppPorts 对你电脑里的每一个软件都 100% 兼容。

## 风险与自由并存 {#risk-and-freedom}

脱离系统和应用默认的本地盘假设，意味着你需要承担相应的不确定性。轻则应用闪退、配置重置、更新异常或权限失效；重则因外盘意外断开、离线写入分叉或操作失误，引发数据不可见、损坏甚至丢失。

## 对数据保持敬畏 {#respect-data}

在点击任何迁移、还原、解绑、重签名或清理旧副本等操作前，请务必仔细核对状态与提示。操作前建议先查阅本站文档（如[快速开始](/docs/faststart)、[迁移应用](/docs/core)、[迁移数据](/docs/datamigrae/operation)与[外置盘与日常使用](/docs/storage-guide)）；你也可以点击页面右上角复制对应文档页的 Markdown 内容发给 AI，让它帮你快速解读原理并评估目标应用的迁移风险。同时，请务必确认目标磁盘的连接稳定性，**操作前先做好备份；另外注意，Time Machine 默认只备份 Mac 内置硬盘，迁到外置盘里的重要数据请自己另外留一份备份**。

## 反馈与共建 {#feedback}

AppPorts 的各项保护机制，正是在一次次真实实验与踩坑中逐步打磨出来的。如果你在使用过程中遇到了异常、兼容性问题，或者有更好的改进建议，欢迎通过 [GitHub Issues](https://github.com/wzh4869/AppPorts/issues)（提交 Bug 时建议通过「日志 → 导出诊断包」附带诊断信息）或其他社区渠道反馈给我。

**AppPorts 赋予你掌控存储空间的自由，但数据的最终安全，永远掌握在你自己手中。**
