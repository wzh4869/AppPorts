# 设置与权限

点击左侧边栏底部的设置齿轮（或按 `Command + ,`）在主窗口打开设置；权限尚未就绪时，设置齿轮和“准备情况”的“检查”按钮会显示红色（已拒绝）或橙色（无法确认）提示点。迁移前先查看“准备情况”，按提示完成所需权限与外置存储检查；不同 macOS 版本显示的项目可能不同。

## 应用信息与应用内更新 {#updates}

设置页右上方卡片展示当前运行的 AppPorts 版本、实际运行路径（可选中复制），以及“检查更新”“边界与共识”“官网”“文档”“关于”入口；点击“边界与共识”可随时重看只读的“关于 AppPorts 的边界与共识”面板。

点击“检查更新”发现新版本后，可在更新面板中选择：

- **国内更新**：从国内来源下载更新包，不依赖 GitHub 连接。
- **GitHub 更新**：下载对应版本的 GitHub Release 附件。

下载期间显示进度并可取消；校验完大小、SHA-256、签名身份、版本、架构与系统要求后，点击“安装并重新启动”即可替换并重启 AppPorts。仍有迁移等任务未结束时会提示先完成任务；自更新期间会暂时挂起“应用更新守护”并在更新完成或取消后恢复。应用内安装需要 AppPorts 位于可写的本地目录（例如“应用程序”文件夹），失败时也可点击“国内下载”通过浏览器手动更新。

如果用 DMG 或 ZIP 手动替换安装，请打开一次新版 AppPorts，让它同步后台代理并处理仍在运行的旧版应用更新守护。代理状态仍有异常时，到「后台代理」查看提示并重试。

## 准备情况与系统权限 {#permissions}

“准备情况”直接内嵌在右上方卡片中，点击标题右侧的“检查”可刷新系统权限、外部存储与 App Store 外置安装状态。已就绪的项目以紧凑状态行展示（悬停可查看详细说明）并收起多余按钮；需要处理的项目保留原因与“打开系统设置”入口。

| 项目 | 用途 | 怎样处理 |
| --- | --- | --- |
| 完全磁盘访问 | 让 AppPorts 读取和管理受保护的数据位置。 | 点击“打开系统设置”，授权后按提示重新打开 AppPorts；找不到图标时可直接将屏幕上的引导浮窗图标拖入系统设置列表。 |
| App 管理 | 系统要求时，允许修改或管理其他应用包。 | 系统预检显示“已就绪”“需要授权”或“无法确认”；未就绪时点击“打开系统设置”可直达“App 管理”子页，并同样支持拖拽图标添加。 |
| 可移动宗卷 | 让迁移后的应用访问外盘数据。 | 原应用首次访问时可能单独询问；这与 AppPorts 的权限不同。 |
| 外部存储 | 检查连接、格式和加密状态。 | 按[外置盘准备](/docs/storage-guide)选择合适目标。 |

发起新迁移、创建/打开/重新挂载应用库映像以及打开权限引导前，AppPorts 会检查自身是否位于“应用程序”文件夹；仅浏览列表、扫描应用和把已有数据迁回本机不受这条限制。给 AppPorts 授权不代表其他应用也获得授权；遇到读不到数据的问题，先检查[挂载状态与原应用权限](/docs/faq#missing-data)。

如果升级后系统设置里的「App 管理」或「完全磁盘访问权限」开关已打开，AppPorts 仍提示缺权限，可能是系统还在使用旧签名证书的授权记录。看到「需要重新授予系统权限」时，先按提示打开对应设置，把新版 AppPorts 添加到列表并开启开关。若旧条目仍无法生效，在「准备情况」点击「清理旧版授权记录」，再返回系统设置重新添加并开启。清理「完全磁盘访问权限」时可能需要确认管理员授权；如果清理未成功，也可以在系统设置中选中旧条目，点 `-` 移除后重新添加。完成后按提示重新打开 AppPorts，并回「准备情况」检查状态。

## App Store 与非原生应用 {#app-store}

macOS 15.1 及以上显示“App Store 应用外部安装”卡片，AppPorts 会只读核对系统 App Store 的外置安装设置是否与当前所选外盘一致：

- 一致时显示“已设置”及实际 `Applications` 目录；不一致或尚未开启时，提供“打开 App Store 设置”入口。
- App Store 自身只对新下载大于 1 GB 的大型应用使用该设置并管理后续更新；**AppPorts 迁移不受 1 GB 限制，任意大小（包括小于 1 GB）的 App Store 应用都可由 AppPorts 迁入该目录**。
- 选择或恢复外部存储时若尚未完成该配置，主界面会弹出提示；点击“不再提醒”（或按 Esc）会持久记住选择，之后仍可随时在本页查看状态并打开 App Store 设置。“我已设置”只会重新读取真实系统状态，不会靠创建空目录伪造完成。

较早系统会显示“允许迁移 Mac App Store 应用”和“允许迁移非原生应用”。开启前阅读提示：系统支持、应用更新与设备要求仍然适用。详见[迁移应用](/docs/core#updates)。

## 经典数据迁移模式 {#classic-data-migration-mode}

“经典数据迁移模式（不推荐）”默认关闭，为仍需处理旧容器链接方式的用户保留。开启需要确认风险，关闭不会还原已有数据，也不会恢复被修改的签名。

当前迁移与重签名分开进行。这个开关不会恢复旧版自动重签流程。适用范围与转回方法见[经典模式](/docs/classic-mode)，旧版行为保存在[历史功能归档](/docs/archive/data-signing)。

## 手动签名与修复 {#manual-signing}

签名操作处理的是应用身份，不是把文件搬到另一个位置。只有明确知道用途时才使用手动重签；沙盒应用默认受限，经典模式下仍需要针对当前操作确认风险。

应用列表确认某个应用已重签后，右键菜单保留“恢复原始签名”，隐藏重复的“重签名此应用”。恢复官方状态后，符合条件的应用才重新显示重签入口。检查结果不明时，先使用“检查签名”，不能只看菜单判断应用是否正常。

“恢复原始签名”需要适用且经核对的原始应用备份，不能拿另一个版本强行替换。有“签名已替换”提示时，从修复面板开始；没有可用备份时，按指引使用官方原版。完整步骤见[升级与修复](/docs/macos-27#repair)。

### 原包保存在哪里 {#signature-backups}

从 1.9.1 build 31 起，手动重签官方应用时，AppPorts 将经核对的完整原包保存在**外盘根目录可见的 `AppPorts Backups` 文件夹**，并放入中英文 `README.txt`。无需额外选择备份位置，也没有单独的备份管理页面；可以直接在 Finder 中查看。

AppPorts 会依次尝试应用所在的外盘、当前外部应用库所在的盘，再从其他合适的外盘中优先选择剩余空间较多的卷。目标必须是已连接、可写且空间足够的本地物理外盘；内盘、网络盘和磁盘映像不参与选择。没有合适外盘时，在修改正式应用前停止。

**应用仍在内盘，也需要连接外盘保存原包。** 内盘只长期保留小型索引和操作记录；重签期间仍需临时工作空间。原包在同一卷内可以直接移入备份目录；需要跨卷时，先复制并确认外盘原包完整保存，再清理内部临时原件。

这些原包用于恢复应用内容和官方签名，**不包含聊天记录、文档等应用数据**。它们也不替代独立备份：同一块外盘故障时，盘上的应用和原包可能同时不可用。

### 恢复与清理原包 {#signature-backup-cleanup}

恢复时连接保存原包的那块外盘，在 AppPorts 中对当前应用选择“恢复原始签名”。程序会核对版本、内容、开发者身份及相关数据依赖；同一版本即使重复重签，也仍保留最初的官方原包，不会用重签后的副本覆盖它。

AppPorts 会保留仍有恢复价值的原包。在确认应用已经恢复官方状态，或已安装经验证的同开发者官方新版，并排除未完成操作和数据依赖后，才自动清理冗余原包。旧版留在内盘的有效完整原包会在条件满足时自动迁到外盘，确认成功后再移除内部副本。

如果确定不再需要这份恢复材料，可以在 Finder 中删除对应原包。删除不会移除当前安装的应用或个人数据，但会失去这份原包提供的离线恢复能力；之后可能需要从官方渠道重装。移入废纸篓仍占空间，APFS 共享数据块也使显示大小不等于最终释放量。

请保持备份文件夹的位置，不要修改原包内容，也不要把它当作日常应用启动。外盘暂时离线不等于原包失效；尚有操作未完成时，先按 AppPorts 的提示处理。只有身份名称的旧记录如何保留或清理，见[历史签名备份](/docs/archive/data-signing#backups)。

### 旧登录任务 {#login-signing}

当前版本在所有 macOS 上停用“开机自动重签名”，build 31 也已移除对应设置卡。更新后打开一次 AppPorts，让它处理旧登录任务；仅清理失败时，设置才显示“旧的登录重签任务尚未完全关闭，请重试。”，此时使用“重试”并保留错误信息。

## 后台代理 {#mount-agent}

“后台代理”卡片包含两项默认开启、可分别关闭的登录后台配置：

- **磁盘维护代理**：在登录、外置盘重新连接或选中映像的定时检查时，将在线的受管容器数据卷与当前选中的 [APFS 应用库映像](/docs/storage-guide#app-library-image)接回原位置，并保持 AppPorts 管理的专用 APFS 数据卷隐藏。关闭开关会卸载其自动运行配置，保留现有挂载、数据和恢复记录；前台手动挂载与恢复不受影响。
- **应用更新守护**：在 AppPorts 退出后继续监听已迁移应用，遇到已适配的 ShipIt 更新明确失败时自动校验缓存新版并尝试完成安装，把结果同步到“任务中心”（失败项提供“回退更新”）。关闭开关会安全停止自动接手，保留已有收据与副本。它目前仅覆盖已适配的 ShipIt 更新，不替应用重签名，也不覆盖所有其他更新框架。

两项代理均使用“应用程序”文件夹内已安装的 AppPorts 无窗口模式运行，不会阻碍主界面正常重新打开，但也不保证在所有登录应用启动前完成接回。移动或更新 AppPorts 后打开一次即可核对并同步配置；若系统后台项目被禁用或配置同步报错，可使用卡片内的“重试”。删除 AppPorts 前先[还原受管容器数据](/docs/restore#data)。

## 日志设置 {#logs}

可以在“日志设置”卡片中开关日志记录、调整最大日志大小（可选 `1 / 2 / 5 / 10 / 20 / 50 / 100 MB` 与“不限”，默认 `10 MB`；原配置低于 `10 MB` 的用户在升级后会自动一次性提升至 `10 MB`，高于 `10 MB` 或“不限”的设置保持不变）。

主日志（`AppPorts_Log.txt`）与高频追踪日志（`AppPorts_Trace.txt`）按 `6:4` 比例各自独立滚动（每路各含 `.1.txt` 上一卷备份），总大小不超过所选上限；选为“不限”时不再轮转或截断本地日志。设置页同时显示当前日志总大小和日志存放路径，可通过“更换位置”或“恢复默认”修改存放目录（菜单栏日志菜单也提供“恢复默认”与“不限”档位）。

点击“在 Finder 中查看”可打开当前日志目录；点击“清空日志”会弹出二次确认框，确认后将日志文件移入废纸篓（不支持废纸篓的路径才会直接删除），避免误删历史记录；点击“导出诊断包”（菜单栏“日志 → 导出诊断包”同样可用）会默认预填桌面保存路径，合并导出脱敏后的 `AppPorts_Log.share-safe.txt` 与 `AppPorts_Trace.share-safe.txt`，并跨重启保留最近 100 条操作摘要，同时对用户名、外置盘名称及 `smb://` / `afp://` 等网络共享地址脱敏。导出不会自动发送。

## 任务历史 {#task-history}

“任务中心”卡片中的“退出后清理已完成的任务列表”默认开启，可关闭以保留成功任务（含后台更新守护已完成记录）的展示历史。“任务中心”页面的“清空已完成”与行末移除按钮同样只影响展示，不删除应用或数据，也不删除用于恢复的迁移或更新收据。

加入后台的迁移任务仍依赖 AppPorts 主程序运行。重新打开时，上次未结束的迁移任务需要检查记录，不会自动从历史重做迁移。暂停、取消和异常处理见[任务中心](/docs/datamigrae/operation#task-center)及[异常恢复](/docs/restore#recovery)。
